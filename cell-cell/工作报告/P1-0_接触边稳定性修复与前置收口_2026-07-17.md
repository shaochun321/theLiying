## 二、②接触边稳定性缺口：验证与修复

### 2.1 问题验证

构造对照场景：世界扩散极稳（`kappa=0.001`），但接触边参数激进（`h=1000`，皮肤热容
`0.01`）：

```
is_stable(world) = True   （只检查世界扩散，看不到接触边）
χ_contact = H·dt·(1/C_w+1/C_s) = 101000   （接触边自身严重不稳定）
```

实际运行 5 步后，`T_w`/`T_s` 从初始 5.0 发散到 `~10^25` 量级——**证实这是一个真实、
此前完全未被测试覆盖的严重数值稳定性漏洞**，不是理论假设。

### 2.2 修复设计

新增 `contact_stability_numbers(contact, world_graph, skin, dt) -> (η_w, η_s)`：

```
η_w = Δt·(Σ_j κ_wj + H) / C_w    # 世界接触节点：把接触边H并入该节点已有的扩散求和
η_s = Δt·H / C_s                  # 皮肤侧
```

关键点：`η_w` 把接触边的 `H` **并入**世界节点自身已有的扩散 `κ` 求和里一起核算，而不是
分别检查扩散稳定性和接触稳定性后假设组合仍稳定——同一节点同一步内两个通道共享同一个
能量预算，必须联合核算（批判的关键洞察）。`is_contact_stable(...)` 用 `η_w<=eta and
η_s<=eta` 判定（`eta` 默认 1.0，与既有 `is_stable()` 同一约定）。

`couple_world_skin_step()` 在原有 `is_stable(world_graph,dt,eta)` 检查之外，新增
`is_contact_stable(...)` 检查，两者都在 `source.release()` 之前——不通过则拒绝执行，
state 未被触碰。

### 2.3 修复验证

重新运行 2.1 的对照场景：`is_contact_stable()` 正确返回 `False`（`η_w=1000`，
`η_s=1e5`），`couple_world_skin_step()` 在执行前抛出 `ValueError`，source/world/skin
三方状态均未变化——之前会发散到 `10^25` 的场景现在被正确、安全地拒绝。

## 三、①③④其余收口项

**①调度描述订正**：模块 docstring 与 `couple_world_skin_step()` 函数 docstring 改为
精确的五步描述（快照 t_n 所有状态 → 计算所有源项/扩散/接触通量 → 验证稳定性及可用能量
→ 一次性提交到 t_{n+1} → 更新联合账本），不再用"释放→传播→交换"这种暗示顺序过程的
表述。

**③补测试**：
- T-STC-9（逆向交换）：皮肤初始温度高于世界，验证 `Δ E_world>0`、`ΔE_skin<0`、账本仍
  闭合；
- T-STC-10（长程收敛）：隔离场景（单节点世界，无扩散无泄漏），驱动 10 个接触时间常数
  `τ_ws`，验证 `|ΔT|` 单调不增、不变号、最终收敛到 `<0.01`；
- T-STC-11~14（四种接触失稳场景，`pytest.mark.parametrize`）：大 `h`/大 `area`/小
  `C_s`/大 `dt` 分别验证 `is_contact_stable()` 返回 `False`，`couple_world_skin_step()`
  在 `source.release()` 前拒绝，三方状态未被触碰。

**④量纲契约正式化**：模块 docstring 新增"Dimensional contract"一节，明确声明
`external_injections` 的所有值恒为功率/电流（never pre-multiplied by dt），并固定命名
规范（`*_flux`/`*_current`/`power` = 电流量纲；`delta_e_*`/`e_*_drawn`/`e_loss_*` = 已
乘dt的能量量纲），防止 P1 引入搬运通量后同类 dt² 错误复发。
