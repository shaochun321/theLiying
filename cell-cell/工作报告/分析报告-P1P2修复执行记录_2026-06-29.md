## 二、P2 修复：L3_Aff 次阈值发放（修复路径封闭）

### 问题描述

全链路结构审计（2026-06-28）发现：在 World 物理仿真中，前庭链路中的 L3_Aff 神经元发放率约 **2 Hz**，远低于设计目标 12.5 Hz。后果：

```
L3_Aff 2 Hz 发放 → Aff→Enc 有效电流 0.010 A × 5 Ω = 0.050 V < v_peak=0.300 V
                 → L4_Enc 从不激活
                 → L5_Col（前庭轴）= 0.000000
                 → 5/6 前庭轴在 Column 层静默
```

### 已穷举的修复路径

#### 路径 1：降低 v_peak（0.23 → 0.10）

**原理**：降低脉冲阈值，允许更少的注入电流触发脉冲。

**结果**：回归测试 T5.1 FAIL — Xin 峰频 0.98 Hz（期望 0.5 Hz ±0.2 Hz）

**失败机制**：
- v_peak=0.10 时，仅依靠偏置电流（bc_current=0.05）即可维持约 4 Hz 发放
- 零输入基线 4 Hz 意味着：Aff 在正弦波的**正半周和负半周都会发放**
- 两个半周均有发放 → Xin 残差在正负周期均非零 → FFT 峰出现在 1 Hz（输入频率 0.5 Hz 的二次谐波）
- T5.1 检测 Xin 峰频，得到 0.98 Hz，判定 FAIL

#### 路径 2：降低 fatigue_k（0.5 → 0.1）

**原理**：减少每次脉冲累积的疲劳超极化电流，让 Aff 能维持更高的持续发放率。

**理论分析**：
```
零输入基线最大发放率 = I_bias / (q_spike × τ_fat × fatigue_k)
                    = 0.099 / (0.05 × 3.0 × 0.5) = 1.32 Hz  ← 当前
                    = 0.099 / (0.05 × 3.0 × 0.1) = 6.6 Hz   ← 修改后
```

**执行情况**：已在 `vestibular/chain.py` 两个函数中添加 `fatigue_k=0.1`，运行测试。

**结果**：两项 FAIL

| 测试 | 期望 | 实测 | 状态 |
|------|------|------|------|
| T5.1 Xin 峰频 | 0.5 Hz ±0.2 Hz | 0.98 Hz | FAIL |
| T2.3 编码选择性 | > 1.5× | 1.39× | FAIL |

**失败机制（与路径 1 相同）**：
- fatigue_k=0.1 将零输入基线提升到 ~8 Hz
- 8 Hz 基线 >> HC 负半周的抑制能力（HC 换能单向，负加速度下 HC 接近零而非变负）
- Aff 在负半周仍维持 ~8 Hz 发放 → 二次谐波 → T5.1 FAIL
- T2.3 失败：所有前庭轴 Aff 基线上升，跨轴信号污染"安静"编码层

**已恢复**：`vestibular/chain.py` 已恢复到修改前状态（两个函数均不含显式 `fatigue_k`）。

### T5.1 失败的结构性约束

这是一个**不可规避的权衡**，由测试设计与 World 物理的差异共同决定：

```
T5.1 约束：Aff 零输入基线必须足够低，使负半周 HC 信号能将 Aff 抑制至静默
           → 基线发放率必须 < HC_negative_inhibition / (q_spike × τ_fat × fatigue_k)
           → 约 < 1-2 Hz（在当前 HC→Aff 参数下）

World 物理约束：前庭 HC 在轨道运动中激活极弱（HC_act ≈ 0.001-0.01）
               → 对 Aff 的驱动电流 ≈ 0.023-0.23 A
               → 只能支撑 Aff 在 2-3 Hz 范围内

Aff→Enc 设计约束：按 12.5 Hz 标定（hebbian.py 第 325-328 行注释）
                 → 2 Hz Aff → V_ss_enc = 0.050 V < v_peak_enc = 0.300 V
                 → Enc 从不激活
```

**核心矛盾**：T5.1 要求低基线（< 2 Hz），而 P2 修复需要高基线（> 12.5 Hz），两者在当前 synapse 标定下不可兼得。

### 唯一可行的修复路径

**修改 `hebbian.py` 中 Aff→Enc 束的 `synapse_gain`，从按 12.5 Hz 标定改为按 2 Hz 标定。**

```python
# 当前（hebbian.py 第 ~330 行）
# 标定注释：at Aff rate ~12.5 Hz:
# I_mean = 12.5×2.5×2.0×0.001 = 0.0625; V_ss = 0.0625×5 = 0.31 > V_th=0.3 ✓
initial_weight=2.5,
synapse_gain=2.0,

# 目标（按 2 Hz 重新标定）
# I_mean = 2.0×2.5×30.0×0.001 = 0.150; V_ss = 0.150×5 = 0.75 > V_th=0.3 ✓
initial_weight=2.5,
synapse_gain=30.0,    # 需要约 15× 增益
```

**风险评估**：
- synapse_gain 从 2.0 → 30.0 会使回归测试中 Aff→Enc 电流大幅增加
- 回归测试的 oto_x 输入幅度=200（远强于 World），Aff 发放率约 12.5 Hz
- 新 V_ss_enc = 12.5 × 2.5 × 30 × 0.001 × 5 = **4.69 V >> v_peak_enc=0.3 V**
- Enc 将在回归测试中完全饱和（持续发放）→ T2.2/T2.3 可能 FAIL

**结论**：synapse_gain 重标定需要同步调整回归测试的 Enc 阈值或输入幅度，属于多参数联动修改，不是单一参数 bugfix。
