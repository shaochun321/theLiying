## 增量补充：S0-a加固——稀缺资源顺序偏置实证（2026-08-02）

commit：d0e883d

**发现**：
旧T-SEL-6只覆盖资源充足条件（0.2×3=0.6 < capacity=1.0），从未真正触发资源竞争，
所以"顺序无关"这个结论是空洞的——谁申请都会成功，跟公平与否无关。

评判211341精准指出这个资格边界问题：

```
资源池无显式索引偏置 ≠ 稀缺资源分配无顺序偏置
```

**修正**：
- `try_allocate()`明确冻结为记账接口，不是选择器——docstring加了禁止用法说明
- S0-c真正实现竞争时必须采用同一物理步的batch请求处理，不能逐次调用后立即决定
- 批量分配规则必须满足对候选置换等变：`A(π·r) = π·A(r)`

**测试**（新增T-SEL-6b，用capacity=0.3、每候选申请0.2的稀缺场景）：
- T-SEL-6a：资源充足时记账无顺序偏置 PASS
- T-SEL-6b：稀缺资源顺序偏置真实复现 PASS——
  顺序[0,1,2] ⇒ candidate_0先获资源；顺序[2,1,0] ⇒ candidate_2先获资源
- 全量回归 21/21 PASS

**冻结边界**：
S0-a只取得契约级反硬编码资格；运行时置换等变、资源竞争和内生选择尚未证明。
