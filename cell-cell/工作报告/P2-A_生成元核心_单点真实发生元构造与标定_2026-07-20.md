# P2-A：生成元核心——抽取 + 地址 + D_i^sim 输入合同 + 闭合状态机（差分格式）

## 1. 目标

P2-A0（轨迹身份核对 + 皮肤地址接通）已完成，本轮启动 P2-A 主体：单点真实
发生元构造与标定。范围来自四轮交叉比对（`交叉比对/document -
2026-07-20T203329.284.md` 方案本体 → `...T203750.258.md` 评判 → 我方评判#1
→ `...T211325.369.md` 反评判 → 我方评判#2 → `反馈_动态皮肤P2-A与自然单位
概念修正_2026-07-20.md`）收敛出的执行顺序第 1-3 步：

1. 抽取现有十神经元结构（不从零重建）；
2. 建立正式 `D_i^sim → 𝒢_i` 输入合同；
3. 实现触发—退出—重新武装（trigger/exit/rearm）闭合状态机。

核心裁定（贯穿四轮交叉比对，最终由反馈文档定案）：**生成元完成一次闭合
χ ≠ 自然单位本身 𝔫**——本轮只交付"一次可辨识、可计数、带谱系、受地址
系统约束的真实发生"，不冻结任何无量纲测度/相位/占比字段，那是 P2-B 才
需要验证的问题。

## 3. 发现的真实问题

**REFRACTORY 阶段判断存在同步 fall-through 缺失**：首版 `OccurrenceClosure.
update()` 里 ACTIVE→REFRACTORY 的阶段迁移发生在函数中段后直接 `return
None`，导致即使 `rearm_min_steps=0`，也要等**下一次**调用才会真正检查
REFRACTORY→ARMED 的重整条件并 emit——多等了一步，且这一步在
`t_down==t_rearm`（rearm_min_steps=0 时的既定语义）下是错误的。跑
T-P2AG-5（长饱和不重复计数）与 T-P2AG-6（阈值抖动去抖）两个单元测试时
立即暴露（`assert ev is not None` 失败）。修复：让 ACTIVE 分支在完成阶段
迁移后**同步落入** REFRACTORY 分支判断，而不是提前 return（
`occurrence.py` 对应位置已加注释说明这一設計意图）。

## 5. 冻结契约

- **χ ≠ 𝔫**：`Occurrence` 只携带三边界 + 恒为 1 的计数 + 生成地址，不携带
  任何无量纲测度/相位/内部占比字段。任何后续代码都不得往 `Occurrence`
  加测度字段，除非走 P2-B 的正式测度映射 `𝒩: χ ↦ 𝔫`。
- **`feed()`/`tick()` 与 `circuit.step()` 互斥**：`VariantCircuit._step_
  quantum_thermal_pathways` 每次 `circuit.step()` 都会用 world/body 真实
  采样自动驱动同一批 l1/hc/ensemble/collector 对象；`BaseGenerator.feed()`
  是"绕开 world/body、手动喂合成 dT"的标定/测试专用路径，两者同时使用
  会造成同一 pathway 每步被驱动两次。`base_generator.py` docstring 已
  显式警告。
- **闭合迟滞参数是待标定占位，不是调参结论**：`theta_up=0.01` 复用
  `test_basegen_thermal_t1_real_occurrence.py:64` 已验证的经验值；
  `theta_down=0.1*theta_up`、`rearm_min_steps=0` 均标注
  `EXP-P2A-001/002-PROVISIONAL`，**必须由 P2-A1 输入工作区间扫描替换**，
  不得被后续代码当作已标定的正式值直接引用。
- **`wrap_base_generator` 不限制 `site_index` 来源**：它是比
  `relations/site_selection.py` 低一层的通用抽取工具，本身不强制"只读
  冻结集合"；生产/测试代码若要遵守项目"不动态搜索"纪律，应从
  `FROZEN_THERMAL_SITES`/`get_frozen_site` 取得索引后再传入。
