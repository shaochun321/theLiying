## 二、方案偏差分析与修正

方案文档（`前庭 v2.0 集成方案-阶段1/2.md`）存在两处与实际代码不符的错误：

### 偏差 1：`EnergyStore.fill` 不存在

- **方案写法**：`self._v2_p_avail[0] = self.energy_store.fill`
- **实际 API**：`EnergyStore.fill_fraction`（`_level / capacity`，范围 [0,1]）
- **修正**：将所有调用改为 `energy_store.fill_fraction`

### 偏差 2：Phase 1 Enc 检查对象错误

- **方案写法**：`enc_avg = np.mean([n.activation for n in self.vestibular_v2.enc_neurons])`
- **实际架构**：`VestibularChainV2` 只包含 MET / HC / Aff_reg / Aff_irr 四层；Enc 神经元在 `HebbianCircuit`，不在 chain 对象内
- **修正**：v2 层面的可测指标是 `spike_cost()`（Aff 放电）、`fifo_signal_rms()`（FIFO 信号）、`last_gain`（G_eff）；主回路 Enc 通过 `_activation_ema` 读取

### 附加修正：`VariantCircuit.__init__` 不接受参数

- 原签名 `def __init__(self):` 无法在测试中注入模式
- 新增 `vestibular_mode: Optional[str] = None` 参数，优先级高于模块常量
- 使测试可用 `VariantCircuit(vestibular_mode="V2_PARALLEL_LOG")` 而无需改源码

## 四、Phase 2 验证结果（V2_ACTIVE_DRIVE）

VestibularChainV2 直接作为 HebbianCircuit 的主链（在 `__init__` 时传入 `vestibular=`），运行标准 10k 步回归。

| 指标 | V1_ONLY（基线） | V2_ACTIVE_DRIVE | 变化 |
|------|----------------|-----------------|------|
| T2.1 Enc active | 0.6995 | 0.6995 | 不变 |
| T2.2 Enc quiet | 0.0001~0.48（随机） | 0.0001 | **稳定化** |
| T2.3 Selectivity | 2.84x（偶发 <1.5x） | **699x** | +24500% |
| T3.1 Col vest | 0.6888 | 0.6873 | ≈不变 |
| T5.1 Xin peak | 0.49Hz（偶发 0.98Hz）| 0.49Hz | **稳定化** |
| 总 PASS | 21/21（偶发 20/21）| **21/21（稳定）** | 随机性消除 |

**核心发现**：T2.3 从 2.84x 跃升至 699x，根因是 soft saturation 消除了 HC 过驱动对共享 Col 层的旁路激活：

```
V1 路径：HC 无软饱和 → HC 强激活时电流溢出 → 通过 bundles_hc_to_aff
         → 热觉 Col 获得旁路噪声 → quiet encoding 升至 0.25
         → Selectivity = 0.70/0.25 = 2.84x（有时 <1.5x 触发 T2.3 失败）

V2 路径：HC → soft_saturate(r=0.05) → 渐近上限 1/0.05=20
         → 旁路噪声被截断 → quiet encoding → 0.0001
         → Selectivity = 0.70/0.0001 = 699x
```

这同时解释了 T5.1 的随机抖动消除：旁路噪声不再干扰 Xin 频谱。
