## C. Aff 激活的正确理解

Aff 是**脉冲编码**神经元（spiking=True，无通道）。从 `neuron.py` 第 515-516 行：

```python
# For spiking neurons, activation = instantaneous spike (0 or 1)
self.activation = 1.0 if self._spiked_this_step else 0.0
```

激活值含义：
- `activation = 1.0`：本步发放了一个动作电位
- `activation = 0.0`：本步静默（占绝大多数时间）

`L3_Aff: act=0.0022` 意味着：**每 1000 步中约 2 步有脉冲 = 2 Hz 发放率**。

---

## D. 发放率受限的四重机制

### D-1. PowerRail 内阻压降

```python
v_avail = self._power.draw(abs(scaled_current))  # PowerRail.draw()
v_ratio = v_avail / max(self._power.vdd, 0.01)
injected = scaled_current * v_ratio
```

PowerRail 参数：`vdd=1.0, r_internal=0.1`

计算（HC_act=0.17 时）：
```
scaled_current = 0.8 × 0.17 × 20.0 / 0.5 = 5.44 A
v_drop = 5.44 × 0.1 = 0.544 V
v_avail = max(0, 1.0 - 0.544) = 0.456 V
v_ratio = 0.456
injected = 5.44 × 0.456 = 2.48 A
```

**PowerRail 将有效注入电流削减 54%（5.44 → 2.48 A）。**

### D-2. 适应电流（Adaptation）

```python
self._membrane.inject(-self._w_adapt, dt)
# 每次脉冲后：self._w_adapt += b_adapt = 0.01
```

每次脉冲后，w_adapt 增加，注入超极化电流，需要指数衰减（tau_w）才能恢复。

### D-3. 疲劳（Fatigue）

```python
self._fatigue_cap.charge += fatigue_q_spike × C_fat  # 每次脉冲
self._membrane.inject(-fatigue_k × v_fat, dt)         # 持续超极化
```

每次脉冲后 v_fat 增加，提供持续超极化电流，降低后续脉冲的发放概率。

### D-4. 脉冲能量门控

```python
SPIKE_ENERGY_COST = 0.005
if self.energy >= SPIKE_ENERGY_COST:
    # 脉冲发放，重置 V_m
else:
    # 去极化阻断：V_m *= 0.5（无脉冲，半衰期衰减）
```

在隔离 VestibularChain 中（无 VascularCooling 补给），经 5000 步激烈发放后：
- Aff_reg yaw: energy = **0.056** (初始 1.0，消耗 188 × 0.005 = 0.94)
- 进入去极化阻断循环（V_m 充至 0.23 → ×0.5 → 充至 0.23 → ×0.5...）

在 VariantCircuit（有 VascularCooling 补给）：
- 从账本数据：`L3_Aff: E=0.8423`（能量充足）
- 但四重抑制机制仍将发放率压低至 ~2 Hz

## E. 理论发放率计算

充电阶段（V_m 从 v_reset 到 v_peak）：

```
注入电流    = 2.48 A（after PowerRail）
有效净 ΔV   ≈ 2.48 × dt / C - 适应/疲劳电流
              ≈ 2.48 × 0.001 / 0.5 - 补偿项
              = 0.00496 V/step（理论最大）
```

充电时间（忽略疲劳）：
```
Δ = v_peak - v_reset = 0.23 - 0.077 = 0.153 V
t_charge = 0.153 / 0.00496 = 31 steps → 31 Hz 理论最大
```

实测（VariantCircuit 30k步）：act=0.002 = 2 Hz

**减速因子 = 31/2 = 15×**，由适应 + 疲劳 + 适应电流衰减时间共同贡献。

## F. 级联影响

1. **L3_Aff → L4_Enc**：脉冲束（2 Hz 稀疏码）传递到 Enc 神经元  
   - 束权重 frozen 初始=0.5，synapse_gain=5.0（参见 HebbianCircuit._aff_enc_config）  
   - 有效电流 = 1.0 × 5.0 × dt / C_enc → 极小  
   - L4_Enc（前庭轴）激活 < 0.002

2. **L4_Enc → L5_Col**：信号 < 0.002 → Column 的前庭激活 ≈ 0  
   - L5_Col 的账本均值 0.0004 主要来自**热觉通道**（ThermalMembrane → Encoding，绕过 L3）  
   - Column 层展示 5/6 静默：yaw/pitch/roll/oto_x/oto_y/oto_z 全零

3. **L5_Col → L6_Motor**：Column 无前庭信号 → Motor 没有方向性输入  
   - Motor 的运动控制退化为纯 DEVIATION_MOTOR_GAIN 驱动  
   - 学习仅在 DA 门控的热觉束上有效（w_brake/w_front）

4. **Variant Contracts G3 FAIL**：信号深度测量到 4（Enc 层），而非 6（Motor 层）

## G. 为什么 5/6 而非 6/6 静默

热觉通道（therm）有独立信号路径：
```
ThermalMembrane → bundles_therm_to_encoding → L4_Enc_therm → L5_Col_therm → L6_Motor
```

此路径**绕过 L3_Aff**，直接从体感膜注入 L4_Enc。因此热觉轴（pitch 中的 therm 部分）显示较高激活，拉高了 L4_Enc 平均值（0.03-0.10），但这并不反映前庭信号的传导。

前庭通道（yaw/pitch_vest/roll/oto_x/y/z）全经过 L3_Aff，均以 ~2 Hz 发放 → 均静默。

## H. 最小修复路径分析

**问题本质**：v_peak=0.23 相对于有效注入电流过高，加上适应/疲劳机制，导致稳态发放率仅 ~2 Hz。

| 修复方向 | 涉及文件 | 是否可不改主代码 |
|---------|---------|----------------|
| 降低 v_peak（0.23 → 0.10） | `vestibular/chain.py` 的 `_afferent_config()` | **否**（主项目代码） |
| 降低 fatigue_k（0.5 → 0.1） | 同上 | **否** |
| 增大 VascularCooling 对 L3 的供能 | `circuit/variant_adapter.py` | **否** |
| 增大 HC→Aff synapse_gain（20→40） | `vestibular/chain.py` | **否** |
| 增大 Aff→Enc synapse_gain | `circuit/hebbian.py` | **否** |

**所有修复都涉及主项目代码，需要用户授权。**

推荐优先级：降低 v_peak（0.23 → 0.10）。理由：

```
v_peak_new = 0.10
t_charge = (0.10 - 0.077) / 0.00496 = 4.6 steps → 217 Hz 理论最大
实际（含适应/疲劳）估计：~15-30 Hz，从 2 Hz 提升 7-15×
```

这会让前庭信号在 L3_Aff 以正常神经发放率（15-30 Hz）传递，解锁 L4→L5→L6 的信号传导。

## I. P2 根因总结

| 项目 | 值 | 含义 |
|-----|---|------|
| HC→Aff 有效注入（HC=0.17） | 2.48 A | PowerRail 削减 54% |
| Aff 理论发放率 | 31 Hz | 无适应/疲劳 |
| Aff 实测发放率（VariantCircuit） | 2 Hz | 四重抑制 |
| 频率损失因子 | 15× | 适应+疲劳+能量门控 |
| v_peak 与 V_m_ss 的关系 | V_m_ss < v_peak（约 0.01V 差） | 理论上发放率更低 |
| 修复最小方案 | v_peak: 0.23 → 0.10 | 需用户授权 |

**P2 不是信号路径断裂，而是参数校准问题：v_peak 过高，加上适应/疲劳机制，将 Aff 发放率压缩至 ~2 Hz，无法有效驱动下游层。**
