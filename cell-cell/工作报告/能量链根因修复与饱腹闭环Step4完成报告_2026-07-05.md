## 一、根因诊断：R1-Pre 持续失败的真正原因

### 问题现象
R1-Pre（50k步能量链验证）持续 FAIL：fill_fraction 全程 0.0000，即使 T-029（eta=0.06）使 ThermalMouth deposit ≈ 0.09/step。

### 诊断路径
通过 `traced_withdraw` monkey-patch 追踪每步 withdraw 来源：

```
step=101: requested=18.38942  got=0.09264  from=variant_adapter.py:1435
```

**每步请求 18.38 单位但只拿到 0.09（全部当前存量）。**

来源：`variant_adapter.py:1435` = `energy_store.withdraw(repair_cost)`  
公式：`repair_cost = _total_damage * self.repair_energy_rate * dt`  
实测：`_total_damage = 3676` @ step 101，`repair_cost = 3676 × 0.005 = 18.38/step`

### 根因：数学发散设计缺陷

`damage_integral` 是**累积积分**（单调递增）：
```python
# SkinPatch.sample()
if T_skin > damage_threshold:
    damage_integral += (T_skin - threshold) * dt  # 无限增长
```

body 在热场中（世界温度 T_max ≈ 6.4，threshold=3.0），12个patch每步积累 excess ≈ 3.4：
- 每步 `_total_damage` 增长 ≈ 39.6
- step N 时：`_total_damage ≈ 39.6 × N`
- `repair_cost ≈ 39.6 × N × 0.005 = 0.198 × N/step` — 线性发散

食物入量固定 ≈ 0.09/step（ThermalMouth），故 **step 1 以后 repair_cost 永远超过食物入量**。

## 二、修复方案

### 原理：瞬时损伤率替代累积积分

```python
# 旧（发散）：
repair_cost = _total_damage * self.repair_energy_rate * dt

# 新（稳定）：
_dmg_threshold = 3.0
_instant_excess = sum(max(0.0, patch_temps[pid][0] - _dmg_threshold) for pid in patch_temps)
repair_cost = _instant_excess * self.repair_energy_rate * dt
```

**生物学依据**：创伤修复的 ATP 成本 ∝ 当前受损速率（修复工作量），而非累积历史（Arnold & Barbul 2006 Nutrition and Wound Healing）。创伤未愈合时无法"修复"，修复成本不应随时间线性增大。

### 参数校准：repair_energy_rate 0.005 → 0.001

在 T_max≈6.4（12个patch，平均excess≈3.4）的正常工作温度下：
- `_instant_excess ≈ 40.8`
- `repair_cost = 40.8 × 0.001 × 1.0 = 0.041/step`
- 食物入量 ≈ 0.09/step
- **修复占食物的 45%**（Arnold 2006 生物学范围 20-50%，✓）
- 净存入 ≈ 0.049/step → 稳定正收益
