## 二、实际改动

### 2.1 nexus_v1/relations/r1_structure.py（新建，396行）

五个类型 + 一个函数：

**KappaTen**（κ^10基元）：κ^10 = (B_in, C^10, S_dyn, B_out)，即
- C^10（不可约核心）= ensemble中的10个神经元——最低功能规模（"十"指核心，不是总元件数）
- B_in（输入边界）= l1
- S_dyn（支持动力学）= hc
- B_out（输出边界）= collector

collector属于生成元整体但不属于核心，trace和relation_collector属于ℓ_gen不属于κ^10。

**RelationGenLink**（ℓ_gen）：A和B怎样形成关系
- 新增`relation_type`字段（语义关系类型，如"a_prec_b_fast"）
- 区别于`link_type`（链路机制类型，如"fast_trace_and_gate"）
- 两者不能混用：同一relation_type可用不同link_type检测，反之亦然

**R1OutputLink**（ℓ_out）：已形成的关系怎样向下游产生作用
- measure_local_current()读取bundle.propagate()的局部电流（Y的读取位置）

**R1StructureBlock**（R1本体）：只含κ_A/κ_B/ℓ_gen/区间，**不含ℓ_out**
- 评判030645阻塞修正：ℓ_out从本体移出——"关系是否存在"不依赖"能否施力"
- RPrecCircuitT1基类没有bundle_rprec_to_da，R1本体依然合法成立

**R1OutputBinding**：R1本体 + ℓ_out，回答"已形成的关系能否向下游施力"
- __post_init__强制校验output_link.source_collector必须与r1.relation_collector同一对象（桥梁）

**project_to_relation_occurrence_fields(r1, t_detect, t_closed, ...)** →
把投影关系Π_τ(R1_AB[I])=RelationOccurrence显式化为可测代码路径：
- relation_type ← r1.link_gen.relation_type（语义层，非机制层）
- collector_address ← r1.link_gen.link_address
- trace_scale ← r1.link_gen.trace_scale
- parent_a/b_instance_id ← r1.parent_a/b_instance_id

### 2.2 nexus_v1/relations/relation_occurrence.py（修改）

RelationOccurrence docstring重新定型：
- 不再是"完整关系本体"，而是"R1StructureBlock在时间尺度的投影与谱系审计"
- 现有字段结构不变（字段本身已是Π_τ所需的全部信息）
- 新增`from .r1_structure import R1StructureBlock`关联引用（不改变生产执行路径）

## 三、发现的真实问题

### 3.1 link_type与relation_type的真实区分（P2-B1X2b时发现）

在实现`project_to_relation_occurrence_fields()`时，初版直接把
`r1.link_gen.link_type`填入RelationOccurrence.relation_type——这是一个
隐性混淆：link_type描述"用什么方法检测"（fast trace + AND门），
relation_type描述"检测到什么关系"（A先于B）。两个方向的collector（a_prec_b
和b_prec_a）使用**同一个**link_type检测机制，却代表**不同的**relation_type——
如果混用，则切换检测方向时relation_type字段不会正确变化。

发现后立即在RelationGenLink里加了独立的`relation_type`字段，
project_to_relation_occurrence_fields()取relation_type而非link_type。
T-R1S-5专门验证了两者不能混用。

### 3.2 ℓ_out在R1本体里引发的逻辑问题（评判030645阻塞）

X2a首版把ℓ_out作为Optional字段放在R1StructureBlock里——看起来"只是可选"，
但会制造"RPrecCircuitT1基类的R1不完整"的错误语义。彻底移出独立成
R1OutputBinding后，T-R1S-3用RPrecCircuitT1基类（没有bundle_rprec_to_da）
构造R1本体，验证了合法成立；T-R1S-3还验证了R1StructureBlock确实不再有
link_out/has_output_link/measure_output_current这些字段。
