## 一、这份报告要讲什么

表面上，这是一次"给感温链路加一层耦合生成元"的常规功能开发。但过程中暴露、并最终解决的问题，不是这一层特有的——它是**任何"新聚合层读取已有 spiking 神经元输出"场景都会踩的坑**：结构完全正确、参数在数值上"看起来"远超阈值，神经元却始终不发放。根因不是逻辑错误，而是**膜电容 RC 积分器的时间尺度，与上游信号源的实际动态特征（阵发性 vs 持续性）不匹配**。

这份报告的核心价值不在"Ω 层做完了"，而在于把**诊断这类问题的方法论**沉淀下来——如何从"看起来该工作却不工作"一步步 bisect 到"电容太大、积分跟不上爆发时长"这个物理级根因，以及背后一个可推广的经验法则：**任何时候复用另一层的电容/权重常量之前，先问一句"上游信号源的实际动态特征和原设计假设的动态特征是否一致"**。这条经验法则未来适用于 Γ(组织生成元)层、以及任何后续感觉通路的类似构建。

## 二、背景与理论定位

《感温链路局部—耦合生成元》交叉方案文档提出了一个四级生成元分类链条：

```
世界温度场
    ↓
局部耗散事件
    ↓
局部生成元 ξ (Local Generator)
    ↓
耦合生成元 Ω (Coupling Generator)
    ↓
组织生成元 Γ (Organization Generator)
    ↓
Shadow Layer / Motor
```

在本次工作开始前，代码状态是：

- **ξ 层已完整实现**（`_init_quantum_thermal_pathways`，`variant_adapter.py`）：32 个 Fibonacci 球面采样点 × warm/cool 双通道 = 64 个独立的三级链路（L1 ThermalDeltaNeuron → L2 热觉毛细胞 → L3 ensemble+collector），已接入 `step()` 并纳入 `get_all_bundles()` census。这部分对应另一份方案文档（`claudecode方案/感温链路量子元重构V2`），**不是**本次读到的两份交叉方案文档。
- **Ω 层完全未实现**：`skin_network.py` 只有球面坐标生成函数 `fibonacci_sphere_points`，没有任何耦合权重计算或 rf/div collector。ξ 层实现的 docstring 明确写着"本轮不做跨点/跨方向耦合（Ω 层）"。

本次任务范围（用户确认）：只做 Ω 层，止于 collector 的脉冲输出，**不接 Motor**。Γ 层和 Motor 对接是下一阶段，待 Ω 层验证稳定后再设计。

## 三、对原方案文档的两处物理修正

在实现前对照代码库做了核实，发现原交叉方案文档在两处与实际物理机制不符，属于文档撰写时的推断错误，非代码问题：

### 修正 1：Ω 读取的是 pre_trace，不是 membrane voltage

原方案文档写"Ω 和 ξ 的输出都是 Collector 的模拟膜电位（Vm），而非离散 spike 计数"，主张 Ω 层应直接读取 `collector._membrane.voltage`。

实测代码后发现：xi collector 的 `NeuronConfig` 里 `spiking=True`。`SynapticBundle.propagate()`（`bundle.py:243-256`）对信号源的选择逻辑是：
```python
if src.config.spiking and hasattr(src, '_calcium_integrator') and src._calcium_integrator is not None:
    a_src = src.calcium_rate      # spiking + CRI：钙积分速率
elif src.config.spiking:
    a_src = src.pre_trace         # spiking（无CRI）：脉冲迹
else:
    a_src = src.activation        # 非spiking：瞬时激活
```
xi collector 属于第二种情况（spiking，无钙积分），bundle 读的是 `pre_trace`（指数衰减的脉冲历史，模拟 EPSP 时程），不是原始膜电位。这实际上更符合项目"禁止直接注入、必须经 Bundle"的结构优先原则——Bundle 的信号选择规则本身就是既有代码的一部分，Ω 只是照章调用，不需要自己决定读什么信号。

### 修正 2：抑制路径不能用负 Memristor 权重

原方案文档给出 `DIV_SURROUND_W = -0.015`（负权重表示抑制路径）。

`Memristor.conductance` 属性（`semiconductor.py:222`）：
```python
w_safe = max(0.0, min(1.0, self.w))  # 防御性钳制
return self.r_min + (self.r_max - self.r_min) * (1.0 - w_safe)
```
`w` 被无条件钳到 `[0, 1]`，负权重在物理上直接失效（钳成 0，等效于断路，不会产生"负电流"）。正确的抑制机制是 `BundleConfig.synapse_gain = -1.0`——`propagate()` 里 `current = memristor.conduct(a_src) * synapse_gain`，抑制通过束级增益的符号实现，权重本身必须是正的（代表这条通路本身的耦合强度）。这是这个代码库里"电导恒正、抑制靠增益符号"的既定约定，Ω_div 沿用了同一约定。

## 四、核心范式：RC 时间尺度失配的完整诊断过程

这是整个工作里耗时最长、也最有沉淀价值的部分。按实际发生顺序还原。

### 4.1 起点：结构对，数字对，就是不响应

Ω 层的 Bundle→Ensemble→Collector 三级结构写完后，第一次跑 T-Ω1~T-Ω5 探针：T-Ω1（census）、T-Ω3（cos²权重连续性）、T-Ω5（frozen 权重不变）全部通过，说明**结构层面完全正确**。但 T-Ω2（方向选择性）和 T-Ω4（散度响应）失败——RF/Div collector 的 `pre_trace` 全程为 0，无论用几个点驱动、权重调多高。

这是最容易被误诊的阶段：直觉会认为"响应为零 = 电流不够 = 加大权重"。于是第一轮尝试是不断调大 `_RF_BASE_WEIGHT`（从 0.5 加到 1.0，即 Memristor 权重上限），调大 `_DIV_CENTER_W/_DIV_SURROUND_W`，但**响应依然是零**。这个"调参数没用"的信号本身就说明问题不在"电流量级不够"这个假设上，需要换个角度重新定位。

### 4.2 排除的假说链条

在真正找到根因之前，依次假设并排除了以下几种解释（每一种都写了独立诊断脚本验证，逐一被证伪）：

1. **World 热源距离太远**：最初用真实 `World` + `HeatSource` 驱动，标定脚本量出 xi collector 全部 `pre_trace=0`。排查后发现是标定脚本自己把热源和 body 摆在了热源作用半径之外（`d≈38-42 > radius=30`），热完全没传到皮肤——这是标定脚本的构造错误，修正距离后确认不是根因。
2. **Python 字符串哈希随机化**：`Memristor` 的 ±25% 对称性打破扰动基于 `hash((bundle_id, i_s, i_t))`，而 Python 字符串 `hash()` 默认逐进程随机化（`PYTHONHASHSEED` 未固定）。怀疑这导致跨进程结果不可复现。用 `PYTHONHASHSEED=0` 固定后重跑，问题依旧——排除。
3. **点身份的几何特殊性**：怀疑某些具体的球面采样点存在结构性差异。做了 A/B 对照（point0 单独驱动 vs 和其他 6 个点一起驱动），行为完全一致——排除点身份因素。
4. **"内联 main() vs 包在函数里"的诡异现象**：这是诊断过程中一个真正的岔路。一次性诊断脚本里，把完全相同的驱动逻辑写在 `main()` 函数体内 vs 包一层 `peak_scan()` 函数再调用，结果截然不同（前者读数为零、后者读数正常）。花了几轮 bisection（v3~v6 版本脚本）才确认：这是**诊断脚本本身的读数时机问题**——早期脚本只在少数几个采样步打印瞬时状态，而不是在整个跑步窗口里追踪峰值，恰好在采样到的那几步处于信号的"衰减相"。换成峰值追踪（`if v > peak: peak = v`）后，两种写法结果一致。这一步教训是：**诊断阵发性信号时，绝对不能只看某个采样点的瞬时值，必须追踪整个窗口的峰值**，否则会得出"完全没有响应"的错误结论。

### 4.3 真正的根因：xi 层输出是阵发性的，不是持续饱和的

排除以上假说后，用追踪峰值的方法重新测量：单点独立驱动 2000 步，xi collector 的 `pre_trace` 确实能达到峰值 ~1.0（稳定的量子化"发放"上限）。但进一步追踪"16 个点同时驱动时，任意瞬间同时处于高发放态的源有多少个"，发现了关键现象：

- 在跑步过程中的**某些特定时刻**（如第 1887 步），16 个点里有 14 个同时处于 `pre_trace > 0.5` 的高发放态，瞬时电流总和高达 11.6（远超阶梯阈值 0.3）。
- 但在**大多数其他时刻**（包括脚本随手采样的最终步），这个总和只有 ~0.01-0.05，几乎为零。

也就是说，xi collector 的输出本质上是**阵发性的（burst-decay）**：会周期性地集体"爆发"到高值，然后迅速衰减回接近零，单次爆发只持续约 10-15 步。这不是设计缺陷，是 xi 层三级链路（spiking 神经元 + 适应电流）本身固有的动力学特征。

### 4.4 定位到膜电容——为什么"电流够了却不发放"

有了"爆发窗口约 10-15 步"这个关键数据后，直接在爆发窗口内打印 Ω ensemble 神经元的逐步状态，抓到了决定性证据：

```
step 1887: currents_in[0]=2.7571（远超k=0阶梯阈值0.3）
           ens_activation=[0.0, ...]（完全不发放）
           ens_pretrace=[0.0014, ...]（几乎不涨）
```

电流持续多步保持在 2.7 左右（阶梯阈值的近 10 倍），但神经元的 `activation` 全程为 0。回到 `Neuron.step()` 的实现（`neuron.py:412-426`）：

```python
scaled_current = total_input / max(self.config.inertia, 0.1)
v_avail = self._power.draw(abs(scaled_current))          # PowerRail IR-drop
v_ratio = v_avail / max(self._power.vdd, 0.01)
injected = scaled_current * v_ratio
self._membrane.inject(injected, dt)                       # dV = I*dt / C
```

膜电位是一个标准 RC 积分器：`dV = I·dt/C`。Ω ensemble 当时复用的是 xi 层自己的 `_thermal_quantum_ensemble_config`，其中 `capacitance=0.5`。在 `dt=0.001` 的仿真步长下，即使电流高达 2.76，单步电压涨幅也只有：

```
dV = 2.76 × 0.001 / 0.5 ≈ 0.0074 / step
```

要充到 `v_peak=0.23` 需要约 31 步的**持续**电流，而实测的爆发窗口只有 10-15 步——累计涨幅顶多 0.11，不到阈值一半，神经元永远等不到发放的那一刻，爆发就已经衰减过去了。

**这就是根因：不是电流不够大，是"电流够大但持续时间不够长，而膜电容的时间常数没有跟着调整"。** 这是一个纯粹的时间尺度失配问题，任何静态的"调大权重/调大阈值"式调参都无法解决——因为无论权重调多大，只要膜电容不变，31 步的充电需求就不会变，而爆发窗口是上游信号的固有属性，不受 Ω 自己的参数控制。

### 4.5 为什么会犯这个错

Ω ensemble 最初直接复用了 xi 层的 `_thermal_quantum_ensemble_config` 工厂函数，图省事、避免代码重复。但 xi 层这个工厂函数的电容值，是为"Level2 热觉毛细胞的连续、非 spiking 输出（`hc.activation`，持续存在于每一步）"标定的——那种信号源没有"爆发窗口"的概念，只要电流够大，充多少步都行。Ω 层面对的输入源完全不同：**多个 spiking 神经元的 pre_trace 阵发性总和**，其"可用充电时间"被上游的爆发周期严格限定。

这正是 xi 层作者自己在代码注释里反复强调的原则——"独立复制一份而非直接调用前庭版本，因为峰值量级不同，参数需独立校准，不应共享同一组模块常量导致牵连"——只不过这次我自己在实现 Ω 层时图省事违反了这条项目既有的原则，付出了大量诊断时间的代价才绕回来。

### 4.6 修复与最终标定

新建 Ω 专属的工厂函数 `_omega_ensemble_config`/`_omega_collector_config`（不再复用 xi 层工厂函数），独立标定电容：

| 参数 | xi 层原值 | Ω 层最终值 | 比例 | 推导依据 |
|---|---|---|---|---|
| `capacitance`(ensemble) | 0.5 | **0.05** | 1/10 | 使同样电流在同样爆发窗口内的累计充电量提高 10 倍，实测足以在单次爆发内充过 v_peak |
| `capacitance`(collector) | 1.0 | **0.002** | 1/500 | collector 面对的是"ensemble 10 档中通常只有 1 档间歇发放"的更稀疏输入，需要比 ensemble 更小的电容才能积累到位 |
| ensemble→collector 权重 `_OMEGA_COLLECT_W0` | 0.1 | **0.5** | 5x | xi 层的 0.1 是按"AND 门，10 档全激活求和=1.0"设计的；Ω 的爆发窗口通常只够越过最低档 k=0，需要更高权重补偿单路贡献不足 |
| `_RF_BASE_WEIGHT`（方向权重上限） | — | **1.0** | — | 已是 Memristor 权重上限（cos²=1 时电导达到最大值 10） |

修复过程本身也是分两步定位的：先把 ensemble 电容降到 1/10，验证 ensemble 确实能发放了（k=0 档 pre_trace 冲到 1.0-2.5），但发现 collector 那一级**仍然是零响应**——因为此时只有 10 档中的 1 档（k=0）被触发，用 xi 层原本"假设 10 档全激活"设计的权重去接收"只有 1 档"的输入，信号强度天然打了 10 折。于是第二步同时调整 collector 电容和 ensemble→collector 权重，才让 collector 也开始正确响应。

### 4.7 可复用的诊断方法论

把这次的诊断过程提炼成一个通用步骤，供以后任何"新聚合层读取已有 spiking 源"的场景复用：

1. **先验证结构**：census 是否正确、几何/连接权重是否符合设计（单调性、半波整流等）、frozen 权重是否真的不变。这些和"信号有没有传过去"无关，是独立的正确性维度，可以先确认排除。
2. **再验证时序，而非只看瞬时值/终态**：如果响应是零，第一反应不要是"调大参数"，而是**在整个观测窗口里追踪峰值**（`if v > peak: peak = v`），而不是抽样几个固定步数打印。如果峰值也是零，才轮到怀疑幅度不够；如果峰值非零但瞬时值经常是零，说明信号本身是阵发性的，问题在时间维度而非幅度维度。
3. **定位到具体是哪一级"跟不上"**：逐级打印中间量（本次是 `bundle.propagate()` 的返回电流 → `ensemble.activation`/`pre_trace` → `collector.pre_trace`），找到电流已经"看起来足够大"但下一级仍然不响应的那个断点。
4. **换算成 RC 时间常数做人工验算**：`dV = I·dt/C`，用实测的电流量级和观测到的信号持续步数，反推需要多大的电容才能在这个窗口内充过阈值，而不是继续凭直觉试数字。
5. **复用别的层的工厂函数前，先确认输入信号的动态特征是否一致**：持续 vs 阵发、单源 vs 多源求和、连续量 vs 离散 spike。任何一项不一致，都不能直接共享电容/权重常量，需要独立标定。

## 五、已知局限与 Phase 2 展望

### 已知局限（记入代码注释，暂不处理）

- **Ω ensemble 退化为粗粒度 1-bit 检测**：实测中 10 档阶梯里通常只有 k=0（最低阈值那档）能被短促爆发可靠触发，k>=1 的更高阶梯在爆发时长内达不到。xi 层设计的"10 级精细温度计"编码，在 Ω 层实际上只剩"有/无"两态。Phase 1 范围内（只需方向性/散度的有无信号，不接 Motor）这是可接受的折衷；如果 Phase 2（Γ 层）需要更精细的分级信息，需要重新考虑编码方式。
- **Ω_div 并非真正的空间中心-周围拓扑**：兴奋/抑制两条路径均匀覆盖全部 64 个 xi 源，本质是"总强度/散度代理"，不是真正的 Mach-band（中心权重集中于邻近点、周围权重覆盖远点）。这是原方案文档自己承认的已知局限，本次按原方案的均匀实现落地。
- **参数标定基于合成 dT 直接注入，非真实 World 长程接近场景**：本次所有标定和验证都用"直接给 L1 喂合成 dT，绕开 world/body 物理"的方法论（与 `test_quantum_thermal_pathways.py` 一致），排除了 World 热扩散本身缓慢（SkinPatch 热惯性 τ=5s）带来的额外时间尺度问题。真实的长程热源接近场景下，同一瞬间会有多少个 xi 源同时越过发放阈值，仍然是未知数，需要专门的长程实验测定——这与 xi 层自己标注的 `TODO-CALIBRATE` 性质相同。

### Phase 2 接口设计（本次不实现）

Γ(组织生成元)层的职责：接收 7 个 Ω collector 的脉冲输出，经过 WTA/侧抑制竞争后形成稳定流形，再经新的 Bundle 输出到 Motor。届时需要重新过 CLAUDE.md 的强制三问：

- 接哪个已有的 Motor 神经元、经哪条新 Bundle、方向权重从哪来。
- 严禁把 Ω→Motor 束的权重变成变相的 `sign(∇T·v)` 硬编码——方向性必须从 Ω 层的差异化激活中物理涌现，不能在 Python 逻辑里显式判断方向。
- 可参考已有的 relay/yaw 运动弧（`bundles_*_to_yaw`）和 D1 phasic arc 的接线范式。
