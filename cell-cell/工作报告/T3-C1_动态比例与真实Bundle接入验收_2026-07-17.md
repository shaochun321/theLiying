# T3-C1：动态比例、真实 Bundle 接入与独立账本验收

## 订正（针对 T3-C1R 报告的表述修正）

`T3-C1R_分级电位线性中继与读出机制判别_2026-07-17.md` 中"任意时刻比例保真"的表述
过强，已被第十一份交叉比对批判指出并用代码实测复现证伪：`GradedPotentialRelay`
实际输出是卷积 `V_i(t)=∫h(t-s)y_i(s)ds`，只有当驱动历史全程满足 `y_a(s)=c·y_b(s)`
（同一常数）时才有 `V_a(t)=c·V_b(t)`。T3-C1R 的 24 组测试全部是固定比例场景，
`eps_ratio=0` 是"固定历史比例"这一特例下的正确结果。同一份报告"中继公开输出可被
下游 Bundle 实际读取而不失真"的结论也略微超前——当时从未接入真实下游 Bundle 验证。
本报告（T3-C1）补齐这两处遗留验证。

第十一份交叉比对批判（`交叉比对/document - 2026-07-17T001314.696.md`）审查 T3-C1R

## 二、①动态比例与实现正确性交叉验证

分段驱动 `1:1→2:1→1:3→1:1`（各 150 步，`dt=0.001`），并行运行一份**独立重新实现**
的 RC 核卷积基准 `ẑ_i(t)=(h_τ*y_i)(t)`（脚本内单独实现，不调用 `GradedPotentialRelay`
本体，验证的是"中继是否正确实现了自己声明的动力学方程"，不是重新论证已知不成立的
"瞬时无记忆"假设）。

**结果**：`z_i(t)` 与独立卷积基准 `ẑ_i(t)` 误差精确为 `0.000e+00`——证实
`GradedPotentialRelay` 的实现忠实复现了其声明的 RC 核动力学，无离散化/顺序 bug。
同时复现批判①指出的滞后现象：切换到 2:1 后 150 步，中继输出比仅达 1.519（未达
2.0）；比例交叉测试（300 步 3:1 占优 → 切换为 1:3）显示新占优通道需要 260/300
步才能反超，且有 ~6.45% 过冲。

**结论**：`GradedPotentialRelay` 的比例保真是"固定历史比例"下的精确特例；动态输入
下正确的描述是 `r_ρ^τ` 窗口化射影关系（见下节）。测试：`test_t3_c1_dynamic_ratio.py`
（T-C1D-1~3，3/3 PASS）。

## 三、②r_ρ^τ 窗口化射影关系定义（采纳）

```
z_i^τ(t) = (h_τ * y_i)(t)                          # 中继已有的 RC 核卷积
r_ρ^τ(t) = [z_1^τ(t) : z_2^τ(t) : ... : z_n^τ(t)]   # 射影等价类
```

不是新增计算逻辑，是给中继已经存在的卷积行为一个正式数学名称，与项目"关系是有
自身时间尺度的过程状态，不是外部瞬时计算出的数"的一贯哲学一致。固定历史比例输入
下精确退化为 `[y_1:y_2]`（已证）；动态输入下表示"最近一个由中继动力学决定的历史
窗口内，各通道以什么相对份额参与了共同过程"。已写入 `graded_potential_relay.py`
模块 docstring。

## 四、③真实下游 Bundle 接入

**设计决策**：`SynapticBundle.propagate()` 要求 source 满足 `is_alive()`/
`config.spiking`/`.activation` 三个契约点，`GradedPotentialRelay` 此前不满足。
若接一个标准 `Neuron` 做"输出适配器"会重新触发 `gm×V²` 二次门控——正是 T3-C1R
刚解决的问题会被重新引入。**采纳方案**：直接给 `GradedPotentialRelay` 本身新增
三个 duck-typing 契约点（不继承 `Neuron`，不改 `bundle.py`/`neuron.py`）：
`is_alive()`（本轮恒真）、`.config`（新增极简 `RelayConfig(spiking=False)`，不
复用完整 `NeuronConfig`）、`.activation`（只读，返回最近一次 `step()` 的返回值
本身，不重新计算）。

**电路**：`GradedPotentialRelay_a/b ─ Bundle_a/b(frozen) ─ observer_a/b(Neuron)`。

**实测**（多个固定 `PYTHONHASHSEED` 对照：0/1/7/42）：`ρ_transport`（Bundle 输出
电流比）相对 `ρ_relay`（中继自身输出比）的偏置为 0.00%~4.52%，与 T3-B 已记录的
Memristor hash 扰动量级（~5~8%）同一数量级。`seed=0` 下两条 Bundle 的 hash 扰动
恰好都落在"正向偏移→被 `weight_max` 硬 clamp 抹平"区间，产生 0% 偏置——这是
`initial_weight==weight_max`（项目约束2要求）下的合法边缘情况，不是 bug；
`seed=1/7/42` 稳定复现 3.5%~4.5% 偏置。**不做自动补偿**（按批判建议，避免重新
引入 Python 比例校正），测试容差容忍观测到的全部偏置范围。

**结论**：批判③的准确表述是"中继公开输出可被 Bundle 接口读取，但通过 Bundle
后的比例协变尚待验证"——现已验证：**可读取，且偏置量级落在已知、可解释的
Memristor hash 扰动范围内，不是新缺陷**。测试：`test_t3_c1_bundle_readout.py`
（T-C1B-1~3，3/3 PASS，多 seed 复核稳定）。

## 五、④幅度可消费性

`z_min` 不是生物阈值——本系统 channel 全程 `v_threshold=0.0`（无阈值），数学上
不存在"低于某值则输出恒零"的硬底线，`z_min` 取"与浮点/数值噪声可区分"的实用
下界 `1e-6`。覆盖 T3-C0 已实测的真实 `y_i` 操作范围（0.03~2.61）：

| y | z(300步后) | 判定 |
|---|---|---|
| 0.03（最保守） | 0.008355 | ≥z_min，Bundle输出电流0.00119 > z_min，可驱动下游 |
| 0.14 | 0.038992 | 工作区间内 |
| 0.40 | 0.111406 | 工作区间内 |
| 2.61（最大实测） | 0.726923 | 远低于 β·a_max=5.0，无clip |

全部落在 `[z_min, β·a_max]`（`β≤0.5`）工作区间内，`n_clip=0`。测试：
`test_t3_c1_magnitude.py`（T-C1M-1~2，2/2 PASS）。

## 六、⑤独立账本

`GradedPotentialRelay` 新增 `relay_ledger_stats() -> Dict`，返回
`{n_step, n_clip, v_max, q_max, e_leak}`：
- `n_step`/`n_clip`：内部计数器，`step()` 每次调用自增；
- `v_max`/`q_max`：中继膜电位/电荷绝对值历史峰值；
- `e_leak`：leak 阶段累计耗散能量，仿照 `TemporalCoupler.stored_energy` 的
  `E=½CV²` 差分模式（`Capacitor` 本身只追踪累积电荷不追踪能量，本组件自行
  在每步 inject/leak 前后计算差值累加）。

**`n_clip=0` 作为 r_ρ 资格硬门槛**：T-C1M-1 显式断言 T3-C0 实测范围内
`n_clip==0`，否则该场景下 `r_ρ^τ` 视为失格。`N_relay`（实例数）不在此方法
返回值里，由持有中继的电路自行统计（同 `rpart_relation_pool_stats()` 的
`pool_instance_count` 模式）。
