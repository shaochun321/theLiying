## 一、任务背景

T2 设计报告（`基础生成元温感轨T2_方向关系电路定义报告_2026-07-16.md`）的核心机制是：用 `BundleConfig.delay_steps` 承载"信号从球面感温点 A 传播到相邻点 B 所需的物理传输时间"，公式为：

```
delay_ab_steps = round(d_ab / v_edge)
```

其中 `d_ab` 是 T0 冻结的两点球面距离（如 28↔31 的 1.0916 模型单位），`v_edge` 原本类比"轴突传导速度"（第一版甚至直接引用真实生物值 100 m/s，经批判三修正为模型单位速度，避免量纲错误）。

无论 `v_edge` 取什么值，**这个公式背后的物理假设都是"热量确实沿着感温点之间的球面路径以某个有限速度传播"**。在正式编码（R3）之前，本报告核查这个假设在当前世界模型里是否成立。

## 二、核查过程

### 2.1 世界模型热场——传统点热源

`nexus_v1/components/world.py`：

```python
class HeatSource:  # L40-95
    def effective_temperature(self) -> float:
        """Temperature scales with remaining energy."""
        ...  # T_eff = T_base × min(1, E/E_half)，纯粹是能量的函数
    def step(self, dt):
        # 热源本身可以缓慢漂移（模拟海底热泉迁移）
        self.position[i] += self._drift[i] * dt   # speed=0.001/step，极慢
```

`World.temperature_at(pos)`（L553-571）：

```python
def temperature_at(self, pos):
    T = self.ambient_temp
    for src in self.cylindrical_sources:      # World 2.0 主力
        if src.alive:
            T += src.temperature_at(pos) - src.T_ambient
    for src in self.heat_sources:              # legacy 点源
        d = _distance(pos, src.position)
        if d < src.radius:
            T += src.effective_temperature() * (1.0 - d / src.radius)
    return T
```

**关键观察**：整个函数是对给定 `pos`（世界坐标）的**瞬时空间叠加**——只有距离项 `d`，**没有任何 `dt`/波速/传播项**。给定坐标，温度当场确定。

### 2.2 世界模型热场——World 2.0 主力热源（更重要，之前遗漏未查）

`nexus_v1/components/heat_source.py` 的 `CylindricalHeatSource`（水热喷口类比，`REF: Kelley et al. 2002, Science 301`）：

```python
def temperature_at(self, pos: List[float]) -> float:
    """Gaussian temperature field from cylinder surface."""
    d = _dist_to_cylinder_surface(pos, self.center, self.radius, self.height/2.0)
    return self.T_ambient + (self.effective_T_surface - self.T_ambient) * math.exp(
        -d * d / (2.0 * self.sigma * self.sigma)
    )
```

这是一个**空间高斯衰减场**：`T(pos) = T_ambient + ΔT × exp(-d²/2σ²)`，`d` 是到圆柱表面的最短距离。**该公式不含任何时间项**——`dt` 只出现在 `CylindricalHeatSource.step(dt)` 里，且只用于缓慢的能量再生（`regeneration_rate=0.002/step`，改变的是 `effective_T_surface` 这个缓变的"总体强度"参数，不是"温度值传播到某处需要多久"）。**这是稳态高斯扩散剖面的空间快照，不是瞬态传播波前**。

### 2.3 采样点如何获得世界坐标

`SkinPatch.world_position(body)`（`world.py:177-194`）：把采样点的 `local_offset`（**身体局部坐标系固定偏移**）先绕 `body.yaw` 旋转、再加 `body.position` 平移，得到世界坐标：

```python
def world_position(self, body):
    # local_offset 是身体坐标系下的固定点（如 T0 冻结的 28/31 号球面采样点）
    rotated = rotate_z(self.local_offset, body.yaw)
    return [body.position[i] + rotated[i] for i in range(3)]
```

`VariantCircuit._init_quantum_thermal_pathways`（`variant_adapter.py:1702-1729`）用 `fibonacci_sphere_points(32, 2.0)` 生成的 32 个点，**全部作为 `local_offset` 传入 `SkinPatch` 构造函数**（`variant_adapter.py:1728`）——这些点固定在身体局部坐标系，身体转向/平移时随身体刚体运动。

## 三、核查结论

三段证据链拼起来：

1. 温度场 `temperature_at(pos)` 对任意给定世界坐标是**瞬时确定的**（无论是 legacy 线性衰减源还是 World 2.0 的高斯扩散源），不存在"这个温度传到这里花了多久"的时间过程；
2. 感温采样点固定在**身体局部坐标系**，随身体刚体运动进入/离开世界坐标系里的温度梯度区；
3. 因此，感温点 28 号与 31 号先后"感受到"温度变化的时间差，**由身体整体转向/平移速度决定**（两点被身体运动依次带入温度梯度区的先后），**与两点间的局部球面距离（~1.09 模型单位）/ 所谓"热传导速度"几乎无关**。

> **T2 报告 §四.2 依赖的物理假设——"`delay_ab = d_ab/v_edge`，几何距离除以传导速度等于传播延迟"——在当前世界模型里没有对应的真实物理过程。**

无论把 `v_edge` 标定成什么数值，这个公式描述的都是一个不存在的物理机制。这不是"参数还没标定好"的问题，是"要标定的物理量本身不存在"的问题。

---

## 四、这个问题与已识别问题的关系

批判五（第五份交叉比对批判）12.2 第3点指出的是"升格判据不可操作"——`r_edge-lag` 能否被证明"不能被 r≺ 参数化模拟"这个问题在数学上难以回答。**本报告指出的是更早一步、更根本的问题**：即使升格判据可以设计得很好，`delay_steps` 机制本身要建模的"沿球面局部边传播"这件事，在当前世界物理里**根本没有对应物**。

如果直接按 T2 报告原 §四.2 的设计实施，会构造出一个**结构合法但物理叙事虚构**的组件：

- Bundle/`delay_steps` 的接线方式本身没有问题（frozen bundle、源→中继→collector 的三段式，符合"结构优先"、不绕过 Bundle）；
- 但支撑其参数取值的"# BIO: 轴突传导延迟"式注释会是**编造的**——真正驱动观测到的时差的是身体运动学，不是沿球面局部边的热传导。

这正是项目 RULES.md"每个组件映射到真实生物/物理对象"要严格把关的那类问题，只是这次的破绽不在 Python 硬编码语义（那种一眼能看出的"if/sign()"），而在**参数标定所依赖的物理叙事本身站不住脚**——这是一种更隐蔽的"语义硬编码"：把"这个数字应该是什么"的问题用一个听起来合理但实际不成立的生物学类比蒙混过去。"强制三问"的 Q1（生物对应物是什么）在这里必须被认真回答，而不能满足于"听起来像轴突传导"就算过关。

## 五、重新定向方向

### 5.1 方向 A（推荐）：把"传播延迟"重新锚定为"身体运动学扫掠顺序"

现象本身是真实的、结构化涌现的：身体绕 yaw 轴旋转时，body-frame 上固定的两个球面点，会以一个**由角速度和两点角距离决定的、确定的先后顺序**依次扫过温度梯度——这不是编造的，是真实运动学（转动刚体上两个固定点，必然按角位置顺序扫过任何固定的空间场）。

**重新定义** `r_edge-lag`：不再检测"热沿边传播"，改为检测"运动扫掠是否以与两点几何布局一致的顺序、在合理时间窗内先后激活"——本质上是一种**运动诱发的空间梯度扫掠一致性关系**。物理对应物明确写为"前庭-皮肤耦合的空间扫掠信号"（运动觉与体表温度觉共享同一具身运动学时钟），而非"轴突传导延迟"。这个类比本身有生物学基础：动物转头时，皮肤上不同点依次扫过环境温度梯度，这与前庭系统同时检测到的角速度是同一个物理事件的两种感官投影——这正是"结构涌现关系"而非"编造语义"的例子。

**具体标定路径**：`v_edge` 不再是虚构的"传导速度"，改用项目**已有、已标定的真实角速度常量**——`nexus_v1/vestibular/DIMENSIONAL_CONTRACT.md`（P0 冻结数据，`vest-P3-complete` tag，2026-06-30）记录的权威锚定：

| 轴 | P0 slope (Hz/unit) | 1 unit (deg/s) |
|---|---|---|
| yaw | 1.213 | **1.21** |
| pitch | 2.252 | 2.25 |
| roll | 1.930 | 1.93 |
| 六轴均值 | 1.798 | 1.80 |

T2 关注的是身体绕 yaw 轴转向时的扫掠顺序，应取 **yaw 专轴值 1.21 deg/s/unit**，而非六轴均值。用两点间的**角距离**（不是原来的欧氏弦距离，需要从 T0 冻结的球面坐标反算两点相对身体中心的角度差）除以 yaw 角速度，得到"以该角速度扫过这两点"所需的真实步数——这是可推导、有生物物理依据的标定，不是拍脑袋凑数量级。

**已核实**：`DIMENSIONAL_CONTRACT.md` 的 yaw=1.213 Hz/unit（≈1.21 deg/s/unit）数值本次已重新读取源文件确认，未过期，可直接引用。

### 5.2 方向 B（保守）：暂缓 T2，仅保留温感轨 T1/T3

若认为方向 A 的重新定向还需要更多论证/实验（如先验证 yaw 转向时感温点是否确有可测的先后模式，这需要在真实 `World`+`Body`+yaw 转动机制下跑一次探索性实验），可以暂缓 T2 的正式实施，先完成 R2（T3）+ T4 集成（用 T1+T3 两类关系），把 T2 列为独立后续任务。这不违反已批准的"R2 优先于 R3"执行顺序，只是把 R3 的门槛从"设计报告完成即可编码"提高到"物理前提重审通过（或方向A的探索性实验验证）后才能编码"。

### 5.3 我方推荐结论

**倾向方向 A**，理由：
1. 现象是真实的、有生物学对应，且这个对应本身相当合理——运动觉与体表感觉共享同一具身运动学时钟，是比"皮肤内部热传导"更贴近"生成元检测结构涌现关系"的项目哲学的类比；
2. 复用了项目已完成、已验证的前庭角速度标定（`DIMENSIONAL_CONTRACT.md`），不需要凭空造一个"传导速度"；
3. **不改变已批准的执行顺序**：R2（T3 正式实施）仍是下一个编码任务，本次重新定向只影响 R3（T2）的物理基础，不影响 R2 的优先级。
