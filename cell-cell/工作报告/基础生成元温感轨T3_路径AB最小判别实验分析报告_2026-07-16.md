## 一、任务背景

T3（r_part 参与竞争关系）要求编码前先做路径 A（减法抑制）/ 路径 B（分流抑制，复用 `DivisiveNormalizationReceptor`）的最小判别实验，用方案定义的两级验收标准评分，择定一条路径后才进入正式实施（Gate D）。

---

## 二、实验设计

用项目既有物理组件（非 Python 除法）分别搭建两条路径的最小标量模型：

- **路径A（减法抑制）**：`ξ_a, ξ_b → 独立兴奋通道 → 共同总量池(RC积分 I_a+I_b) → 共享减法抑制(synapse_gain=-1.0) → y_a=φ(I_a−w·pool), y_b=φ(I_b−w·pool)`。
- **路径B（分流抑制）**：复用既有 `DivisiveNormalizationReceptor`（`compensation.py:295`，Carandini-Heeger 分流抑制物理电路），**用同一实例依次对 I_a、I_b 调用 `.normalize()`**，使其内部 `_pool_voltage` 同时追踪两路输入，构成共享横向池版本。

8 个测试场景覆盖：静默、单通道A、单通道B（交换对称性）、等强、A占优2:1（含共同放大 1x/2x/4x）、极端3:1。

## 四、两级验收评分

### 一级验收（必须达到）

| 标准 | 路径A | 路径B |
|---|---|---|
| 静默无虚假占比 | ✅ PASS | ✅ PASS |
| 单通道占优 | ✅ PASS | ✅ PASS |
| 交换对称 | ✅ PASS（精确对称） | ✅ PASS（精确对称） |
| 等强输出近似相等 | ✅ PASS（精确相等） | ⚠️ 近似通过（差异 1e-4 量级，见 §五） |
| 较大输入→较大输出 | ✅ PASS | ✅ PASS |

两条路径在一级验收上**均可通过**（路径B 的等强情形有极小的实现artifact，非本质缺陷，见 §五）。

### 二级验收（实验性目标，真正的分水岭）

| 标准 | 路径A | 路径B |
|---|---|---|
| 共同放大时排序保持 | ✅ 保持（y_a 始终>y_b=0） | ✅ 保持 |
| **输出比值对共同尺度稳定**（核心指标） | ❌ **完全失效**：2:1 输入在 1x/2x/4x 共同放大下，比值从 987728676 飙升到 3950914706（弱通道被减法抑制**直接压到 0**，比值发散、失去意义） | ✅ **精确稳定**：2:1 输入在 1x/2x/4x 共同放大下，比值恒为 **2.000**（方差仅 0.0001，浮点误差量级） |
| 输出总量变动在有限范围 | ❌ 总量随放大线性增长不封顶（0.99→1.98→3.95，正比于输入） | ✅ 总量随放大**亚线性增长且趋于饱和**（1.42→1.86→2.21，典型除法归一化的饱和特征） |
| 多通道竞争后近似归一化 | ❌ 退化为"赢者通吃"（弱通道被完全清零，不是"归一化占比"而是"淘汰"） | ✅ 输出比值 = 输入比值，是真正意义上的占比关系 |

**路径B 在二级验收的核心指标（共同尺度稳定性）上以压倒性优势胜出**——2:1 输入比在三个不同放大倍数下，路径B 的输出比值锁定在 2.000（与理论 `I_a/(I_a+I_b)` 型除法归一化完全一致），而路径A 一旦一个通道的兴奋度不足以对抗共享抑制池，就会被直接压到 0，比值发散到无意义的天文数字——这正是方案原文警告的"`y_a≈φ(I_a−λI_Σ)`…不保证共同尺度不变"在实测中的具体体现，而且比理论警告的"整体增大/饱和/归零"更糟：它直接**归零**，不是"漂移"。

---

## 五、路径B 等强场景微小不对称的原因（不影响结论）

`DivisiveNormalizationReceptor.normalize()` 设计为**单实例、单路输入**调用（`compensation.py:340-360`），本实验为构造"共享池"，用同一实例依次调用两次（先 `.normalize(I_a)` 再 `.normalize(I_b)`），导致：调用 I_a 时，池状态尚未包含 I_b 本步的贡献；调用 I_b 时，池状态已包含 I_a 本步的贡献——这是**调用顺序**造成的极小先后不对称（1e-4 量级），不是分流抑制机制本身的缺陷。真正实施 T3 时，需要把"池更新"改为**先汇总 I_a+I_b 再一次性更新池，然后分别计算两路的归一化输出**（即在 `DivisiveNormalizationReceptor` 的基础上新增一个"先合并再分别读出"的调用模式，或用两个独立的 `DivisiveNormalizationReceptor` 实例但共享同一个外部 pool 状态变量）——这是留给正式实施阶段的一个具体、已定位的实现修正点，不是新发现的开放问题。

---

## 六、结论：择定路径B（分流抑制/共享池），可望直接进入 r_ρ 而非停留 r_part

基于实测结果，**推荐路径B 作为 T3 正式实施的路径**，理由：

1. 一级验收两条路径都能过，不构成区分点；
2. 二级验收的核心指标"共同放大时输出比值稳定"上，路径B 精确保持（方差量级仅为浮点误差），路径A 完全失效（发散到天文数字，本质是弱通道被清零）；
3. 路径B 复用**已有物理组件**（`DivisiveNormalizationReceptor`，非 Python 除法，符合项目"不新造类"的约束），只需修正 §五 指出的池更新顺序问题即可用于正式实施；
4. 由于二级验收（共同尺度近似不变）已经在这个最小标量模型上**清晰通过**，正式实施 T3 时**有较大机会直接满足升格 r_ρ 的条件**（而不必长期停留在"r_part 参与竞争关系原型"），但仍需在真实 ξ^occ 驱动、真实 Neuron/Bundle 接线（而非本报告的简化标量 RC 模型）下重新验证一遍二级验收，不能仅凭这次简化模型的结果就直接宣称 r_ρ 达成——**升格判定权在正式实施后的实测，本报告只负责路径择定**。

**路径A（减法抑制）不再作为 T3 的主选路径**——它在最基本的"占比关系"语义上就会失败（赢者通吃而非按比例分配），只在"纯粹的二元 WTA 竞争"这种不需要保留输入比例信息的场景下才有意义，与 r_part/r_ρ 的设计目标（保留占比信息）不符。

## 七、遗留给正式实施阶段的具体待办

1. 修正 `DivisiveNormalizationReceptor` 的共享池调用方式：先汇总所有通道电流再统一更新池状态，避免 §五 的调用顺序不对称。
2. 用真实 ξ^occ 源（T0 冻结的 28、31 号点）替代本报告的标量合成输入，重新验证二级验收——需注意 T1 已发现的"真实 ξ^occ 源有 ~400 步启动延迟 + 半自主振荡"特性，可能同样需要 T1 式的合成脉冲优先验证策略。
3. 用真实 Neuron/Bundle 接线（`SynapticBundle` + `NeuronConfig`）复现本报告的标量 RC 模型，标定容值/权重/`sigma`（比照 T1 的"先定增益、反解容值"标定方法论）。
4. 通过升格验收后，把生成元正式重命名为 `r_ρ`（而非停留 `r_part`），并在正式工程报告中记录升格判定依据。
5. 二元验收通过后再扩展到 T2 冻结链的三元占比关系（ξ_31, ξ_28, ξ_23 三通道竞争）。
