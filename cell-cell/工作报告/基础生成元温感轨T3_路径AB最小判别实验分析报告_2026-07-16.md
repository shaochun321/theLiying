## 一、任务背景

T3（r_part 参与竞争关系）要求编码前先做路径 A（减法抑制）/ 路径 B（分流抑制，复用 `DivisiveNormalizationReceptor`）的最小判别实验，用方案定义的两级验收标准评分，择定一条路径后才进入正式实施（Gate D）。

---

## 二、实验设计

用项目既有物理组件（非 Python 除法）分别搭建两条路径的最小标量模型：

- **路径A（减法抑制）**：`ξ_a, ξ_b → 独立兴奋通道 → 共同总量池(RC积分 I_a+I_b) → 共享减法抑制(synapse_gain=-1.0) → y_a=φ(I_a−w·pool), y_b=φ(I_b−w·pool)`。
- **路径B（分流抑制）**：复用既有 `DivisiveNormalizationReceptor`（`compensation.py:295`，Carandini-Heeger 分流抑制物理电路），**用同一实例依次对 I_a、I_b 调用 `.normalize()`**，使其内部 `_pool_voltage` 同时追踪两路输入，构成共享横向池版本。

8 个测试场景覆盖：静默、单通道A、单通道B（交换对称性）、等强、A占优2:1（含共同放大 1x/2x/4x）、极端3:1。

## 四、两级验收评分

### 一级验收（必须达到）

| 标准 | 路径A | 路径B |
|---|---|---|
| 静默无虚假占比 | ✅ PASS | ✅ PASS |
| 单通道占优 | ✅ PASS | ✅ PASS |
| 交换对称 | ✅ PASS（精确对称） | ✅ PASS（精确对称） |
| 等强输出近似相等 | ✅ PASS（精确相等） | ⚠️ 近似通过（差异 1e-4 量级，见 §五） |
| 较大输入→较大输出 | ✅ PASS | ✅ PASS |

两条路径在一级验收上**均可通过**（路径B 的等强情形有极小的实现artifact，非本质缺陷，见 §五）。

### 二级验收（实验性目标，真正的分水岭）

| 标准 | 路径A | 路径B |
|---|---|---|
| 共同放大时排序保持 | ✅ 保持（y_a 始终>y_b=0） | ✅ 保持 |
| **输出比值对共同尺度稳定**（核心指标） | ❌ **完全失效**：2:1 输入在 1x/2x/4x 共同放大下，比值从 987728676 飙升到 3950914706（弱通道被减法抑制**直接压到 0**，比值发散、失去意义） | ✅ **精确稳定**：2:1 输入在 1x/2x/4x 共同放大下，比值恒为 **2.000**（方差仅 0.0001，浮点误差量级） |
| 输出总量变动在有限范围 | ❌ 总量随放大线性增长不封顶（0.99→1.98→3.95，正比于输入） | ✅ 总量随放大**亚线性增长且趋于饱和**（1.42→1.86→2.21，典型除法归一化的饱和特征） |
| 多通道竞争后近似归一化 | ❌ 退化为"赢者通吃"（弱通道被完全清零，不是"归一化占比"而是"淘汰"） | ✅ 输出比值 = 输入比值，是真正意义上的占比关系 |

**路径B 在二级验收的核心指标（共同尺度稳定性）上以压倒性优势胜出**——2:1 输入比在三个不同放大倍数下，路径B 的输出比值锁定在 2.000（与理论 `I_a/(I_a+I_b)` 型除法归一化完全一致），而路径A 一旦一个通道的兴奋度不足以对抗共享抑制池，就会被直接压到 0，比值发散到无意义的天文数字——这正是方案原文警告的"`y_a≈φ(I_a−λI_Σ)`…不保证共同尺度不变"在实测中的具体体现，而且比理论警告的"整体增大/饱和/归零"更糟：它直接**归零**，不是"漂移"。

## 五、路径B 同步共享池的正确实现（2026-07-16 修订，取代原"顺序调用"分析）

### 5.1 原顺序调用版的不对称原因

`DivisiveNormalizationReceptor.normalize()` 设计为**单实例、单路输入**调用（`compensation.py:340-360`）。最初实验为构造"共享池"，用同一实例依次调用两次（先 `.normalize(I_a)` 再 `.normalize(I_b)`），导致：调用 I_a 时，池状态尚未包含 I_b 本步的贡献；调用 I_b 时，池状态已包含 I_a 本步的贡献——这是**调用顺序**造成的极小先后不对称（1e-4 量级）。交叉比对批判指出这"不是单纯数值误差，而是接口语义不匹配"，评判为正确。

### 5.2 同步共享池的合法实现（只用现有公开接口，实测验证）

`DivisiveNormalizationReceptor` 已公开 `pool_activity` 属性（`compensation.py:337-338`，只读，非本次新增）。合法实现方式：

```python
dn.normalize(i_a + i_b, dt)              # ① 只调用一次，池按总电流更新，返回值丢弃
denom = max(sigma + dn.pool_activity, sigma * 0.01)
norm_factor = sigma / denom              # ② 手算与 normalize() 内部相同的公式
y_a = i_a * norm_factor                  # ③ 同一个 norm_factor 分别乘到两路
y_b = i_b * norm_factor
```

全程只用两个已有公开成员（一个方法 `.normalize()`、一个属性 `.pool_activity`），**未新增方法、未修改/直接读写内部 `_pool_voltage`**，是合法的"只用现有组件"实现——回应交叉比对批判"建议的修复超出了只使用现有组件"的判断（不成立）。这个实现同时天然满足批判第9点提出的更严格要求："所有通道使用同一次 pool 更新后的 G"——因为 `norm_factor` 是从同一次 `dn.normalize(i_a+i_b,dt)` 调用后读出的，`y_a`、`y_b` 保证共享同一个增益。

### 5.3 实测对比（`_calib_t3_path_ab.py` 重跑结果）

| 指标 | 顺序调用版（原） | 同步共享池版（修订，仅用现有接口） |
|---|---|---|
| 等强场景 y_a vs y_b 差值 | ~1e-4（顺序不对称） | **精确为 0**（0.00e+00） |
| 2:1 比例在 1x/2x/4x 共同放大下的比值方差 | 0.0001 | **0.000000**（更优） |
| 实现是否新增/修改接口 | 未新增，但批判认为"建议修复"超范围 | **确认只用两个已有公开成员，未新增/未修改** |

同步版**结果不仅没有变差，反而更干净**（等强场景从近似相等变为精确相等）。

### 5.4 排除"常数乘性增益"替代假设（回应批判第9点）

交叉比对批判指出："比值保持不变"本身不能证明这是真正的共享池分流——任何常数乘性增益 `y=g·I` 都会同样满足 `y_a/y_b=I_a/I_b`。这个抽象论点成立，但本报告的原始数据已经包含反驳这个替代假设的证据：若为常数增益，输出总量应严格正比于放大倍数（1x→2x→4x 应呈 1:2:4）。实测同步版总量：

```
1x: 总量=1.3933
2x: 总量=1.8146   （2x/1x = 1.3024，远小于常数增益预期的 2.0000）
4x: 总量=2.1379   （4x/1x = 1.5345，远小于常数增益预期的 4.0000）
```

总量增长明显亚线性/饱和，**排除了"纯常数增益"这个替代解释**，确认观测到的是真正的分流归一化饱和特征（`I_eff=I_raw×σ/(σ+V_pool)`，`V_pool` 随总输入增大而增大，压低归一化因子）。

## 六、结论：择定路径B（分流抑制/共享池），可望直接进入 r_ρ 而非停留 r_part

基于实测结果，**推荐路径B 作为 T3 正式实施的路径**，理由：

1. 一级验收两条路径都能过，不构成区分点；
2. 二级验收的核心指标"共同放大时输出比值稳定"上，路径B 精确保持（方差量级仅为浮点误差），路径A 完全失效（发散到天文数字，本质是弱通道被清零）；
3. 路径B 复用**已有物理组件**（`DivisiveNormalizationReceptor`，非 Python 除法，符合项目"不新造类"的约束）；§五 修订后的同步共享池实现已验证只用现有公开接口（`.normalize()`+`.pool_activity`）即可正确工作，**工程实现路径已闭合**，无需新增或修改任何组件接口；
4. 由于二级验收（共同尺度近似不变）已经在这个最小标量模型上**清晰通过**，正式实施 T3 时**有较大机会直接满足升格 r_ρ 的条件**（而不必长期停留在"r_part 参与竞争关系原型"），但仍需在真实 ξ^occ 驱动、真实 Neuron/Bundle 接线（而非本报告的简化标量 RC 模型）下重新验证一遍二级验收，不能仅凭这次简化模型的结果就直接宣称 r_ρ 达成——**升格判定权在正式实施后的实测，本报告只负责路径择定**。

**路径A（减法抑制）不再作为 T3 的主选路径**——它在最基本的"占比关系"语义上就会失败（赢者通吃而非按比例分配），只在"纯粹的二元 WTA 竞争"这种不需要保留输入比例信息的场景下才有意义，与 r_part/r_ρ 的设计目标（保留占比信息）不符。
