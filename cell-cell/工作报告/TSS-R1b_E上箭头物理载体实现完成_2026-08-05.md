## 1. 目标

把 TSS-R1a 建立的 `EntryBoundaryDetector`（Python 三态状态机，判定规则）
替换成真正的物理载体——用 `Capacitor` + `MOSFET` 实现 E^↑ 的过程变换：

```
E^↑ : p_α(t) ──[物理门]──> b_α^↑(t)
```

资格边界由评判 `170642.972` 明确列出 9 条，本轮只交付这 9 条，完成后立即

## 2. 背景：为什么会有 v1 → v2 两版方案

审计阶段（前置报告）已判定：E^↑ 的"首次通过 + 重复抑制"有现成物理先例
（FatigueCapacitor / D2Autoreceptor / CalciumRateIntegrator 三个同构范式），
"静默退出"可用 RC 泄漏替代整数计步，"重新武装"（τ_rearm）是纯计步、
无物理载体，且是 `occurrence.py` 的继承债务（此前多轮审计未单独挑出）。

评判裁定路线为**单时钟**（E^↑ 新支路合并 τ_gap/τ_rearm 为一个 RC 时间常数），
路线乙（保留双时钟需查文献）被明确禁止。

我据此写了第一版实现方案（v1），随后被评判 `170306.100` **否决**——不是
风格问题，是推导错误，详见第 3 节。

## 3. v1 被否决的原因（核心教训，不可回退）

v1 的执行步骤规定：

> 首枚脉冲通过并给电容充电；门关闭期间的重复脉冲被抑制，而且不再给电容充电。

这个规定的本意是防止"持续驱动下门永久锁死"（若每个被抑制的脉冲都无限
充电，电容电压会单调爬升永不跌破阈值）。但它引入了一个更严重的错误：

门电压变成只记录**距首次脉冲过去了多久**，而不是**距最近一次脉冲过去了
多久**。用具体数字推演：假设持续发生中每 200 步来一枚脉冲，门恢复约
1204 步：

```
t=0     首枚通过，V_g 充电到 V_H
t=200~  重复脉冲被抑制，但不刷新 → V_g 继续单调衰减（不管有没有新脉冲）
t=1204  V_g 跌破阈值，门自行打开 —— 但簇还在继续！
t=1400  下一枚脉冲再次输出 b^↑     ← 错误：同一次持续发生输出了 2 次
```

这直接违反"同一持续发生只输出一次"的核心资格。评判进一步指出 v1 的参数
不等式也有缺口：只约束了「单次充电后经过一个 ISI_max 仍关门」，没约束
「经过整个簇长仍关门」——实测簇长可达数千步，远大于 ISI_max=316 步，
所以 v1 的参数即使取在自己推出的区间内也必然在长簇测试里失败。

**教训**：防止永久锁死的正确解法是**钳位**（Zener clamp，限制电压上限），
不是拒绝充电。这是 v1→v2 的唯一实质性改动。

## 4. v2 方案设计（已执行）

### 4.1 物理结构（Q2）

```
Sources                      载体                              Targets
───────────────────────────  ───────────────────────────────  ──────────────
collector（既有 Neuron，      _gate_cap : Capacitor            b_α^↑(t)
spiking=True，产生 p_α(t)）   _gate_fet : MOSFET（阈值判定）
经 CollectorBoundaryPort      _clamp_fet: MOSFET（Zener 钳位）
读 spike_output）                    ↑
        │                            │
        └──── 每枚 spike 都充电 ──────┘（可重触发；钳位限幅在 V_H）
```

不新建 Neuron（门是对既有 collector 输出的门控，不是新细胞），不新建
SynapticBundle（spike-frequency adaptation 是同一细胞内的通道动力学，
不经过突触，硬接一条 bundle 是错的建模）。

`step()` 严格按 6 步顺序（顺序不可换）：

```
1. _gate_cap.leak(r_leak, dt)                  # 先泄漏（恢复）
2. V_g = _gate_cap.voltage                     # 读脉冲到来前的门电压
3. gate_open = (_gate_fet.conduct(V_g) == 0)   # MOSFET 阈值判定
4. b^↑ = 1.0 if (spike and gate_open) else 0.0
5. if spike: 充电 + Zener 钳位到 V_H            # 每枚脉冲都刷新
6. 无脉冲时只泄漏，不做任何软件复位
```

步骤 2 必须在 5 之前——若先充电再判定，同一枚 spike 会自己关自己的门。

### 4.2 参数（Q3，零自由参数）

评判纠正了报告初稿的错误写法：决定重新开门的不是 τ 单独，而是三者联合：

```
t_open = τ · ln(V_H / θ_g)
```

三个值全部取项目既有默认，不是本轮新填的数字：

| 参数 | 值 | 来源 |
|---|---|---|
| V_H（钳位电压） | 1.0 | `compensation.py:247` `CalciumRateIntegrator.v_clamp` |
| θ_g（门阈值） | 0.3 | `semiconductor.py:130` `MOSFET.v_threshold` |
| τ = R·C | 1.0 s | collector 既有 AdEx 适应时间常数 `tau_w=1.0`（`variant_adapter.py:386`） |
| Q_spike | 1.0 | 由 `Q_spike/C ≥ V_H` 反推，取等号（见下） |

代入：`t_open = 1.0 × ln(1/0.3) = 1.204s = 1204 步`（dt=0.001），落在
EXP-R1A-01 实测分离带 (316, 4257) 内，与几何中位 1160 步差 3.8%。

**为什么 Q_spike/C 必须 ≥ V_H**：若刷新量不足以单枚脉冲直接饱和，孤立
单枚 spike 后的恢复时间会短于长簇后的恢复时间——即恢复时间变成簇历史的
函数，破坏"同一持续发生判定与前史无关"的位置不变性，也无法跨站点共用
一份参数。取等号 1.0 是满足这个约束的最简选择。

### 4.3 Q1 生物对应物

spike-frequency adaptation / 阈值调适，其中"每枚脉冲都刷新 + 抑制量有
饱和上限"对应 Ca²⁺ 依赖 K⁺ 通道的**池饱和**特性：每枚 spike 都引起 Ca²⁺
内流给池充电，池容量有上限（缓冲蛋白饱和 / 泵-漏平衡），Ca²⁺ 被泵出后
抑制按 τ=C·R 衰减。REF（项目内既有引用，不引入新生物声明）：
`neuron.py:129` FatigueCapacitor 注释、`compensation.py:211-247`
CalciumRateIntegrator 的"Circuit: Capacitor (Ca²⁺ pool) + MOSFET Zener clamp"。

**关键**：FatigueCapacitor 单独不足以作先例——它没有钳位，持续发放下靠
充电率/泄漏率的动态平衡达到率依赖稳态，恢复时间随发放率变化。E^↑ 要求
恢复时间与簇长/发放率无关，所以拓扑必须取自带 Zener 钳位的
CalciumRateIntegrator，这是 v1→v2 的实质性区别所在。

## 7. 实现过程中独立发现并纠正的一处错误

写 T-R1B-8（分歧区间测试）时，报告和方案初稿里手推的 oracle 开门步数是
用 `gap_steps+1` / `gap_steps+rearm+1` 算出的 501 / 1001。改成**探测式
实测**（构造"spike → 静默 n 步 → spike"序列，逐步扫描找到第一个使第二枚
spike 令 `update()` 返回 True 的 n）后，测出的真实值是 **500 / 999**，
差 1 步。

原因：`EntryBoundaryDetector` 的 `REFRACTORY→ARMED` 判断
（`entry_boundary.py:177` `t_step - self._t_exit >= rearm_min_steps`）
在探测 spike **到达前**已经完成计步比较，手推时误把"探测 spike 本身也
需要先经过一步"算进了开门条件里，多算了一步。

这处偏差不影响任何判定结论（因为最终测试代码用的是实测值，不是手推值），
但暴露一个方法论问题：连"看起来能直接推出来"的 oracle 阈值，也应该用
代码实测验证，不能相信自己的手算。两份文档中的数字已同步更正。

## 8. 发现的真实问题（技术债务登记）

审计阶段已发现两处脆弱点，本轮实现完成后正式登记进
`cell-cell/docs/degradation_registry.md`：

**DEG-018：`occurrence.py` 双时钟继承债务**
`_ClosurePhase.REFRACTORY` 的重新武装判定是纯整数计步，与退出判定
（`theta_down` 阈值迟滞）是两个独立的软件时钟。TSS-R1b 已用单时钟物理门
证明这个功能可以只用一个 RC 时间常数实现，且实测两个 oracle 变体
（rearm=0 / rearm=500）在真实数据流上事件计数完全相同——即现有实测数据
分辨不出第二个时钟做了什么。**本轮明确不修改** `occurrence.py`——它被
`occurrence_tap.py` / `r2_fork.py` / `test_occurrence_identity.py` /
`test_p2a_generator_core.py`（显式依赖 `rearm_min_steps=0` 分支）等多个
消费方依赖，混在审计+单支路物理化任务里改会扩大回归面。

**DEG-019：`MOSFET.conduct()` 阈下分支注释与实现不一致**
`semiconductor.py:151-159` 注释承诺阈下有指数尾流电流（"physical drain
current = |I_sub|"），但实现 `max(0.0, gm·nVT·(exp(x)-1))` 在
`x = (v_gate-v_threshold)/nVT < 0` 时恒返回 0.0（`exp(x)-1<0` 被
`max(0.0,·)` 截断）。`PhysicalEntryGate` 当前依赖这个"截零"行为作硬阈值
判定（`gate_open = conduct(V_g)==0.0`）。T-R1B-3 内有锁定断言
`conduct(θ_g-1e-6)==0.0`——若将来有人按注释语义"修复"这个不一致（让
阈下返回微小正值），该断言会立刻失败报警，而不是让门静默退化为永久
微导通、E^↑ 失效。
