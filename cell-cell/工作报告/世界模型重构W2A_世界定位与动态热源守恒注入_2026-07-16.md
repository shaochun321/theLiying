## 三、物理定义（强制三问）

**`ThermalFieldLocator`**

- Q1：定位查询工具，同 `skin_network.py`"坐标生成器不应知道电路"定位——不是 Bundle，是几何/插值工具，TYPE:MATH。
- Q2：`Sources(world position x) → Locator.locate(x, graph) → Targets({node_id: weight})`，只读 `graph.cells[*].position`，不修改任何状态。
- Q3：反距离加权插值（REF: Shepard 1968, "A two-dimensional interpolation function for irregularly-spaced data"），非拍脑袋公式；`k=4` 默认值与 `build_fibonacci_shell_graph` 的 `k_neighbors` 默认值一致，保持 W1/W2A 测试夹具口径统一。

**`DynamicHeatSource`**

- Q1 BIO：海底热泉功率输出，同 `heat_source.py` 场景（REF: Kelley et al. 2002, Science 301），但换成功率语义（dQ/dt）而非温度语义——旧热源的"温度"不能直接当新世界的"功率"用，这是第七/八份批判都指出的语义错配，`DynamicHeatSource` 从设计上就规避这个错配，不是复用 `HeatSource.effective_temperature()`。
- Q2：`state=(energy_remaining, power, position, efficiency)`，`release(dt)` 满足 `power·dt <= energy_remaining`，耗尽后返回 0。
- Q3：`energy_remaining`/`power`/`efficiency` 首轮为 EXP 标注的测试尺度常量，不宣称精确物理标定，与 `THERMAL_FIELD_MODE="normalized"`（W1.5 已建立）一致。

**`couple()`（组合函数，非新增有状态类）**

- Q2：`Sources(DynamicHeatSource.release()) + Targets(Locator.locate())` → 注入字典，供 `ThermalFieldGraph.step(dt, external_injections=...)` 直接使用。`Σweight=1` 保证 `Σ注入=power`，不需要额外归一化步骤——守恒是由权重定义天然保证的，不是事后校正出来的。

**`guarded_step()`（fail-fast 包装，非修改 `step()` 本体）**

- Q2：`is_stable(graph, dt, eta)` 检查在前，`graph.step()` 调用在后，检查失败时直接 `raise ValueError`，`step()` 从未被调用，graph 状态完全不受影响。`ThermalFieldGraph.step()` 源码本身零改动，保持 W1/W1.5 已验证过的诊断-only 行为。

## 四、电路/组合结构

```
ThermalFieldLocator.locate(x, graph) -> {node_id: weight}   # weight>=0, Σweight=1，只读

DynamicHeatSource.release(dt) -> power                       # power*dt <= energy_remaining，耗尽后返回0

couple(source, locator, graph, dt) -> {node_id: power*weight}
    # Σ注入 = power，由 Σweight=1 天然保证

guarded_step(graph, dt, external_injections, eta=1.0):
    if not is_stable(graph, dt, eta):
        raise ValueError(...)      # graph 完全未被触碰
    graph.step(dt, external_injections)   # 复用 W1 已测试的 step() 本体，零改动
```

新文件 `nexus_v1/components/thermal_source_coupling.py`，与 `dynamic_thermal_field.py` 分开（关注点不同：后者是图/扩散，前者是定位/注入语义）。

## 八、能量守恒（本轮验证方式）

`couple()` 的守恒不是靠"注入后再检查总量"这种事后校正，而是**由权重定义结构性保证**（`Σweight=1` ⟹ `Σ(power×weight)=power`）——T-TSC-2/5 验证的正是这条结构性保证在多组不同坐标/热源位置下始终成立，不是偶然凑对的。`DynamicHeatSource.release()` 自身的能量守恒（T-TSC-3/4）复用了 `HeatSource` 在 `world.py` 里已经验证过的"有限储备、耗尽即停"模式，不是新发明的账本逻辑。

## 十、已知局限

1. `ThermalFieldLocator`/`DynamicHeatSource` 目前只在独立测试中实例化，未与真实 `Body`/`World`/`VariantCircuit` 产生任何连接——这是 W2A 范围内的有意设计（不接皮肤），不是遗漏；

3. `DynamicHeatSource` 参数（`power`/`efficiency`）仍是测试尺度的 EXP 占位值，尚未对照真实海底热泉功率量级做校准——留给后续需要精确物理标定时处理，与 `THERMAL_FIELD_MODE="normalized"` 的既定立场一致；
