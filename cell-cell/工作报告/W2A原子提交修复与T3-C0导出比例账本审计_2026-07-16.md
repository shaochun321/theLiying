## 二、W2A 原子提交 bug 修复

### 2.1 根因

`thermal_source_coupling.py` 的 `couple()` 调用顺序是：`source.release(dt)`（立即扣热源能量）→ `locator.locate()` → 返回注入字典；`guarded_step()`（稳定性检查）是独立的第二次调用。若生产代码按"先 `couple()` 再 `guarded_step()`"的模式使用，`guarded_step()` 因不稳定拒绝时，热源能量已经被 `couple()` 内部的 `release()` 扣了，但世界图从未收到注入——能量在跨组件提交窗口中丢失。已有的 T-TSC-6 只验证了 graph 状态未被修改，从未验证 source 状态，这个真实缺口没被覆盖。

### 2.2 修复：调整调用顺序，不建事务对象

核实 `diffusion_number(graph, dt)` 的函数签名只依赖图自身的 `kappa`/`capacitance`，与注入量无关；`locator.locate()` 也只在图为空时报错，同样与功率无关。这意味着**稳定性检查和定位查询都可以在 `release()`（整条链路里唯一有副作用的调用）之前完成**——新增组合函数 `couple_and_step()`：

```python
def couple_and_step(source, locator, graph, dt, eta=1.0):
    if not is_stable(graph, dt, eta):
        raise ValueError(...)          # 尚未触碰 source/graph
    weights = locator.locate(source.position, graph)   # 只读，尚未触碰
    power = source.release(dt)         # 唯一副作用点，到这里才提交
    injections = {nid: power * w for nid, w in weights.items()}
    graph.step(dt, injections)
```

`couple()`/`guarded_step()` 保留（作为底层可组合工具，docstring 补充"不保证原子性，生产路径用 `couple_and_step()`"）。这是**调整调用顺序**，不是批判提议的"两阶段提交/`ThermalInjectionTransaction` 事务对象"——按项目"不加不必要抽象"的一贯做法，重排序已经能完全消除这个缺口。

### 2.3 验证：T-TSC-7

新增测试，构造不稳定 graph，断言 `couple_and_step()` 抛出 `ValueError` 且 `source.energy_remaining` 未被修改（同 T-TSC-6 的"状态未被触碰"验证方法论，扩展到 source 侧）；对照稳定配置下正常执行且能量确实被正确扣除（不是永远不扣）。

```

  稳定配置下 couple_and_step() 正常执行，energy_remaining=98.0
7 passed, 0 failed（T-TSC-1~7 全部）
```

## 三、T3-C0：导出比例与共享池账本审计

### 3.1 四层信号同时记录（诊断脚本 `_diag_t3_c0_ratio_audit.py`）

批判理论推导：`activation_a/activation_b ≈ (y_a/y_b)²`（DN 池输出精确线性，但 channel Neuron 的 `activation=gm×vm²` 二次门控会把比例平方）。实测结果：

| 场景 | x_a/x_b | i_a/i_b | y_a/y_b | o_a/o_b | (y比)² | o比/(y比)² |
|---|---|---|---|---|---|---|
| 2:1 | 2.0000 | 2.1614 | 2.1614 | 4.6005 | 4.6716 | **0.9848** |
| 3:1 | 3.0000 | 3.2421 | 3.2421 | 9.7332 | 10.5111 | **0.9260** |
| 4:1 | 4.0000 | 4.3228 | 4.3228 | 9.7818 | 18.6863 | **0.5235** |

**结论**：2:1、3:1 场景下"o比≈(y比)²"的平方假说基本成立（比值接近1.0），**但 4:1 场景严重偏离（0.52）**——这不是假说本身失效，而是发现了**批判理论没有预测到的第二重效应：Neuron 的 `activation` 有硬钳位**（`neuron.py:438`：`self.activation = max(-10.0, min(10.0, gate.gated_conduct(vm)))`）。4:1 场景下 `o_a` 已接近或达到 10.0 的钳位上限，o_a 无法继续按平方关系增长，导致 `o比/(y比)²` 骤降。**这是比批判预测更严重的发现**：不只是比例被平方扭曲，在较大输入幅度下比例信息会被钳位直接抹掉。

### 3.2 共同尺度扫描

固定比 1:1/2:1/3:1，扫描共同放大系数 α∈{0.25,0.5,1,2,4,8}：

- **y 层（DN 输出）**：所有固定比、所有 α 下比值相对散布 **精确为 0.0000**——DN 池数学在共同放大下完全稳定，这部分批判的判断（"DN 层理论上应稳定"）被精确证实。
- **o 层（Neuron activation）**：相对散布 **0.14~0.90**，α≥2 时几乎所有场景的 `o_a/o_b` 都收敛到精确 **1.0**——两个通道的 activation 都被钳位压到同一个上限值（10.0/10.0=1.0），**比例信息完全丢失**，不是"变成平方关系"这么温和，是"归零判别力"。

### 3.3 多 PYTHONHASHSEED 对照

用 3 个固定 seed（0/1/42）各跑一遍 T-RPT 核心场景（子进程隔离，因为 hash 扰动只在进程启动时固定一次）：

```
seed       eps_equal  eps_swap_a  eps_swap_b   eps_ratio
0             0.0499      0.0497      0.0501      0.0525
1             0.0000      0.0000      0.0000      0.0000
42            0.0000      0.0000      0.0000      0.0000
```

范围 [0.0000, 0.0525]。但不设 `PYTHONHASHSEED` 的常规测试运行（本机环境随机种子）实测偏差常在 0.07~0.09 量级，说明 3 个采样点未覆盖全部扰动范围——因此容差没有直接取"1.5x 余量=0.08"，而是取约 2x 余量 **0.10**，留更多安全边际（5 次独立重复运行验证 0.10 容差下稳定通过，不是理论假设）。

### 3.4 共享池关系层账本

`RPartCircuitT3` 新增 `rpart_relation_pool_stats()`，返回 `{pool_instance_count, pool_step_count, pool_activity}`。`pool_step_count` 由 `step_rpart()` 内部自增（`DivisiveNormalizationReceptor` 本身不记录调用次数）。T-RPT-7 验证：① 驱动 N 步后 `pool_step_count==N`（`dt=0` 只读读出不会被误计入，因为计数只在真实 dt 的 `normalize()` 调用处自增）；② 静默/新实例 `pool_activity` 为 0；③ 不同电路实例的共享池是不同对象（`is not` 断言），互不干扰。

### 3.5 容差收紧与真值定义

T-RPT-2/T-RPT-4 的 `_HASH_JITTER_REL_TOL` 从原来的经验值 0.25 收紧为基于 3.3 节实测数据推算的 **0.10**——真值口径本就是"Bundle 传播后的有效电流比"（`i_a_raw`/`i_b_raw`），不是名义输入幅度（这两个测试比较的是 `y_a`/`y_b`，本就下游于 Bundle 有效电流，符合批判 §六 建议的口径，不需要额外改动）。

## 四、结论与后续影响

**核心发现（比批判理论预测更严重）**：T3-B 电路当前设计下，**"关系信号"若被读作 channel Neuron 的公开 `activation`，不但会被二次门控平方扭曲（中等输入幅度下近似成立），在较大输入幅度下还会被 `activation` 的 ±10.0 硬钳位彻底抹平比例信息**（多个场景在 α≥2 时 o 比值精确收敛到 1.0）。这不是 T3-B 一级验收（Gate D）失败——一级验收测的是 DN 层输出 `y_a/y_b`，那一层的数学是精确、稳定、经过验证的——而是**如果未来把 channel Neuron 的 `.activation` 当作"下游可读取的关系生成元输出"，这个假设目前不成立**，需要在 T3-C1 之前解决。

**按项目强制三问纪律，本轮不擅自新增"线性读出组件"**——这需要先答 Q1（生物对应物）/Q2（物理结构）/Q3（参数依据），且可能需要用户确认新组件的必要性，超出 T3-C0"审计"范围。留给 T3-C1 及以后的前置输入，候选方向包括：① 重新标定 `_CHANNEL_GM`/`_CHANNEL_CAPACITANCE`/`_CHANNEL_R_LEAK` 使典型 y 值映射到远离钳位的膜电压区间（若可行则不需要新组件）；② 若线性映射范围不够宽，才考虑新的线性读出机制（需走强制三问）。
