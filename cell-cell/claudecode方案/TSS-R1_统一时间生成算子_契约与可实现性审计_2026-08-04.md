## 1. 可行性预检（实测，探针已删除不留代码）

TSS-R0的核心假设是：用`spike_output`（=`collector.activation`，实时二值
0/1）取代`pre_trace`（连续leaky积分）作为下游输入，能否真正消除T3失败的
"跨站点幅值不匹配"问题？在写任何Θ_τ实现之前，先用同一场景实测验证，
不能只靠推理。

**场景**：单次HeatSource驱动（site28, radius=5.0, T=300.0），5000步，
测站点28/31/21/24的`CollectorBoundaryPort.spike_output`。

| 站点 | onset | 发火次数 | 发火密度 | mean ISI |
|---|---|---|---|---|
| 28 | 384 | 6 | 0.12% | 173.4 |
| 31 | 396 | 4 | 0.08% | 138.7 |
| 21 | 504 | 8 | 0.16% | 241.1 |
| 24 | 510 | 5 | 0.10% | 157.5 |

**结论**：
1. 发火密度跨站点差异约2倍（0.08%~0.16%），远小于T3诊断中`pre_trace`
   峰值的3.4倍差异（trace通道0.024 vs raw通道0.082）。说明二值化本身
   已经压缩了跨站点幅值差异——这是预期中的效果，因为二值脉冲不再携带
   "多强"的信息，只携带"有没有"。
2. onset时序清晰分层：28/31几乎同步（Δt=12步），21/24明显滞后
   （Δt=120/126步）——与TSS-3a此前测得的距离-延迟关系方向一致
   （近距站点先发火），说明二值化保留了足够的时序信息供Θ_τ判断先后。
3. 仍然存在的风险：密度差异不为零，说明`H_τ`若用简单累加（不衰减），
   长时间窗口下不同站点的积分值仍会分化。`H_τ`必须用**leaky积分**
   （随时间衰减），把"衰减时间常数内是否发生过"这件事和"发生了多少次"
   分开——只关心前者，二值化才真正生效。

**可行性判定：可行，但H_τ的设计必须是leaky（有衰减），不能是无衰减累加。**

## 2. 类型契约（命名：`TemporalRelationOperator`，不用RPrecCircuitT4）

### 2.1 结构分解

评判裁定的结构：
```
p_i(t) --H_τ--> h_i^(τ)(t)
(h_i^(τ)(t), p_j(t)) --C_Θ--> r_{i≺j}^(τ)(t)
```

对应到项目已有物理原语：

**H_τ（统一历史保持结构）**：复用`Capacitor`语义原语（`semiconductor.py:39`），
不是`Neuron`（避免引入spiking/MOSFET的额外自由度）：
```python
h_i = Capacitor(capacitance=C_h)
# 每步：
h_i.inject(p_i.spike_output * GAIN, dt)   # spike时充电
h_i.leak(R_h, dt)                          # 持续衰减
# h_i.voltage 即 h_i^(τ)(t)
```
`τ = R_h * C_h`，与T1的`_TAU_FAST_STEPS`/`_TAU_SLOW_STEPS`同一物理意义
（RC时间常数），但输入换成二值`spike_output`而非连续`pre_trace`。

**C_Θ（统一双输入关系结构）**：不是AND门神经元（避免MOSFET非线性/饱和
——这正是T3失败的直接原因），改用显式数值判断：
```python
r_ij = 1 if (h_i.voltage > θ_h and p_j.spike_output > 0.5) else 0
```
这是`step()`内的数值比较，属于RULES.md允许的"构造期接线/边界防护"，
不是"用if替代物理电路"——因为参与判断的两个量（`h_i.voltage`、
`p_j.spike_output`）本身都是真实物理状态，`if`只是读出关系，不产生
新的物理效应。

### 2.2 为什么不用现有Neuron+SynapticBundle路线

`SynapticBundle.propagate()`（bundle.py:283-288）对spiking源固定读
`pre_trace`，没有读`activation`的路径（非spiking源才读activation，但
`CollectorBoundaryPort`包装的是spiking collector）。若要通过Bundle
喂入`spike_output`，需要新增一种"spiking源读instantaneous activation"
的propagate分支——这会修改母本`bundle.py`的核心传播逻辑，违反
"不修改母本代码"的工程规范。

因此Θ_τ的输入不通过`SynapticBundle`，直接用`CollectorBoundaryPort.spike_output`
的返回值手工`inject()`进`Capacitor`。这是纯Python数值操作，不新建
Memristor/突触矩阵，因为H_τ对单个源i只有一条通路，不存在"多对多连接矩阵"
的场景，不需要Bundle抽象。

### 2.3 参数来源（Q3，实现前必须回答）

- `C_h`/`R_h`（H_τ时间常数）：候选复用T1的`_TRACE_CAPACITANCE_SLOW=0.12`/
  `_R_LEAK_TRACE=5.0`（τ=600步）——但T1这组值是标定给`pre_trace`输入的
  幅值量级，改成二值输入后充电量级不同（每次spike固定注入`GAIN`，
  不是`pre_trace`的连续值），**不能直接复用，需要重新推导**：
  - `GAIN`应使单次spike后`h_i.voltage`达到某个可判断的量级（如0.5~1.0）
  - 需要实测单次`inject(GAIN, dt) `后的`voltage`响应，反推`GAIN`
- `θ_h`（H_τ判断阈值）：需要保证"窗口内发生过"与"窗口外未发生"能被
  阈值区分，取决于`τ`和站点间的实测Δt分布（TSS-3a已有28→21/24/31的
  Δt数据，可直接复用作为τ的下界参考，不重新标定）
- 这些参数**必须跨三组站点对（28,31)/(28,21)/(28,24)统一**，
  这是TSS-R1的核心资格要求（评判"任意一组需要站点专属增益即不通过"）

## 3. 测试计划（对应评判9项要求）

```
T-R1-1  同一类、同一组参数，三组(28,31)/(28,21)/(28,24)全部构造成功
T-R1-2  输入只能来自 port.spike_output，代码里grep确认不出现pre_trace
T-R1-3  只驱动p_i（切断j的HeatSource路径）→ r_ij始终为0
T-R1-4  只驱动p_j → r_ij始终为0
T-R1-5  有效时间窗口内p_i先、p_j后 → r_ij产生
T-R1-6  交换i/j驱动顺序 → 不产生同一结果（不对称验证）
T-R1-7  r_ij输出携带两个父发生的谱系（parent_i, parent_j地址）
T-R1-8  三组测试用完全相同的C_h/R_h/GAIN/θ_h取值（同一份常量，非各自标定）
T-R1-9  STDP=0/DA=0（本结构本身不含学习，天然满足）
```

**最重要的失败条件（评判原话）**：任意一组需要站点专属增益或专属collector，
TSS-R1即不通过——即T-R1-1若需要为21或24单独调`GAIN`/`θ_h`才能通过，
则判定不可行，退回结论C（基础生成元没有统一输出边界，需要更底层修复）。

## 4. 本轮审计结论

1. 可行性预检通过：二值化后跨站点密度差异从3.4倍压缩到~2倍，onset
   时序分层清晰，理论上支持统一参数。
2. 类型契约已给出（H_τ=Capacitor leaky integrator，C_Θ=数值比较），
   不新建Neuron/Bundle，不修改母本bundle.py。
3. **未解决**：`GAIN`/`C_h`/`R_h`/`θ_h`四个参数目前没有推导值，T1的
   旧参数是标定给`pre_trace`的，不能直接复用，需要在实现阶段先用单站点
   响应曲线反推（不是网格搜索——用实测单次spike的充电响应反解）。
4. 命名采纳：`TemporalRelationOperator`，不用`RPrecCircuitT4`。
