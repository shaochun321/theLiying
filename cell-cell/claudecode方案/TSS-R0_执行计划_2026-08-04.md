## R0-1 审计结论（代码静态分析，G_28/G_31/G_21）

### 1. collector 物理类型（结论：三者同型）

所有32个温感量子元站点均由同一工厂函数构造
`_thermal_quantum_collector_config`（variant_adapter.py:371）：
```
spiking=True, v_peak=0.23, capacitance=1.0, r_leak=10.0,
theta_collect=_THERM_Q_COLLECT_THR, 同一 gm/tau_gate
```
G_28/G_31/G_21 使用完全相同的物理类型，无站点专属变体。
→ 物理载体类型一致，满足 T-R0-5。

### 2. pre_trace 是否归一化（结论：**不归一化**）

neuron.py:587-589：
```python
pre_trace = pre_trace * decay + abs(activation)
# activation = 1.0 if spiked else 0.0
```
pre_trace 是 spike 事件的 leaky 积分，**绝对值随站点增益/距离变化**。
bundle.py:286：`a_src = src.pre_trace`（spiking 源用 pre_trace 传播）。

→ RPrec 读取的 raw pre_trace 混合了"是否发生"与"发生强度/延迟"，
  这正是 T3 AND 门失败的根本原因。

### 3. OccurrenceClosure 产生的 Occurrence（结论：已是边界记录）

occurrence.py:127-156：
```python
@dataclass(frozen=True)
class Occurrence:
    t_up: int      # 进入有效发生的 step_index
    t_down: int    # 活动退出时刻
    t_rearm: int   # 重新具备触发资格
    address: GeneratedAddress  # 物理谱系（parent = skin patch）
    epoch_id: int  # 父物理支撑 epoch 序号
```

OccurrenceClosure 的检测阈值**跨全部站点统一**（occurrence.py:223-225）：
```python
theta_up = 0.01, theta_down = 0.001, rearm_min_steps = 500
```

CollectorOccurrenceTap.observe()（occurrence_tap.py:83）：
```python
closure.update(collector.pre_trace, t_step, phys_support=(l1.activation > 0))
```

→ `Occurrence` 已经是 p_α[W] 的**审计记录**（证明边界存在），不是边界过程本体：
  - 明确起始（t_up）——但 t_down 只有在活动结束后才知道（事后量）
  - STDP=0 / DA=0 时仍成立
  - 与发生实例可追踪（address + epoch_id）
  - 检测参数与站点名称/语义标签解耦

### 4. RPrec 为何绕过 Occurrence（结论：短路了边界接口）

temporal_r_prec.py 的 step_rprec 通过 bundle.propagate() 直接读取
`xi_collector.pre_trace`（连续模拟量），完全绕过 OccurrenceClosure/Tap。

Occurrence 只在独立调用 `tap.observe()` + `finalizer.step()` 时才被消费，
而这些调用在测试脚本里是可选的，不在主传播循环内。

→ 现有结构的问题不是"缺少边界过程"，而是
  **关系算子读取了上游的 raw pre_trace，而不是读取 collector 的实时脉冲输出**。

## R0-1 最终判定：结论 B（接近但缺少明确边界接口）

**评判修正（document - 2026-08-04T010613.482.md）**：

原方案错误地认为 `Occurrence → binary boundary pulse → Θ`。
这是因果方向错误：`Occurrence.t_down` 只有活动结束后才存在，
从已闭合 Occurrence 反向重建 binary 窗口是**事后重建**，不是实时物理过程。
另外 `physical_carrier: str = "collector.spiking"` 是字符串声明，
不是真实结构绑定，违反 RULES.md"禁止语义标签替代物理连接"。

**正确因果方向**：

```
collector.activation(t)   ← 实时二值脉冲（0 或 1）
    ↓          ↓
CollectorBoundaryPort     OccurrenceClosure
（实时物理接口）          （审计记录，p_α 的下游产物）
    ↓
Θ / Σ / Λ
```

即：`Occurrence = A[p_α]`，反方向 `p_α ≠ B[Occurrence]` 不成立。

## R0-2：最小发生边界端口（已修正）

**删除（不做）**：给 CollectorOccurrenceTap 加 `.last_boundary_process`，
不从已闭合 Occurrence 反向生成 binary 窗口。

**改为**：新增轻量实时端口 `CollectorBoundaryPort`：

```python
@dataclass
class CollectorBoundaryPort:
    """B^(1)：基础生成元发生边界端口——实时暴露collector真实脉冲输出。

    TYPE:INFRA
    不创造新信号，只对物理过程提供有类型的访问。
    不负责：判断发生是否完成、保存t_down、生成关系、归一化幅值、
            从审计记录反推过程。
    """
    generator_address: GeneratedAddress    # 谱系，不决定算子是否成立
    carrier_ref: Neuron                    # 指向真实collector对象（非字符串）
    epoch_id: int                          # 当前父物理支撑epoch序号

    @property
    def spike_output(self) -> float:
        """本步实时脉冲：= collector.activation（spiking神经元的0/1输出）。"""
        return self.carrier_ref.activation

    @property
    def exists_without_learning(self) -> bool:
        return True   # STDP=0 DA=0 时 collector 仍发火
```

端口每步更新 `epoch_id`（从外部注入当前 epoch），其余字段在构造时冻结。
