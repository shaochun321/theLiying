## 脆弱点 1：HC-016 驱动力真空

### 根因分析

当前 HC-016 的实际驱动力：
```python
DEVIATION_MOTOR_GAIN = 1.0 / dt   # = 1000（dt=0.001）
motor_drive = (deviation - 0.1) × 1000
mot._membrane.inject(motor_drive, dt)
→ ΔQ = motor_drive × dt = deviation - 0.1
```

典型 deviation=0.19 → 每步注入 ΔQ=0.09 到 Motor 膜  
V_ss = ΔQ × R_leak / dt = 0.09 × 5 / 0.001 = 450V（远超 v_peak=0.2V）  
**结论：旧路径是暴力强制注入，不是调制，直接使 Motor 饱和 spike。**

VitalOscillator 的现有路径（`variant_adapter.py:1019-1022`）：
```python
vital_outputs = self.vital_oscillator.step(self.energy_store, dt)
vital_outputs = [v * vital_damage_factor for v in vital_outputs]
mot._membrane.inject(vital_outputs[i], dt)   # 亚阈值，"sub-threshold current"
```

### 修正策略：两步替换，保留过渡期

**不立即删除旧路径**，而是在 200k 基线中测量以下两个量：
- `vital_output_typical`：典型步骤下 `vital_outputs[i]` 的均值（预计 0.01-0.1A 量级）
- `deviation_typical`：`deviation - 0.1` 的均值（受 CPC 影响，约 0.05-0.15）

**补偿增益反推公式**：

目标：新路径对 Motor 的每步等效注入量 = 旧路径的等效注入量

旧路径等效注入：`ΔQ_old = deviation_typical - 0.1`

新路径：在 VitalOscillator 输出后乘以 `vital_boost_factor`：
```python
vital_boost_factor = 1.0 + (deviation - 0.1) × w_cpc2vital
vital_outputs = [v * vital_damage_factor * vital_boost_factor for v in vital_outputs]
```

等效条件：`vital_output_typical × (deviation_typical × w_cpc2vital) = ΔQ_old`

→ **w_cpc2vital = (deviation_typical - 0.1) / (vital_output_typical × deviation_typical)**

这是一个需要 200k 基线数据实测的物理常数，不是猜测参数。

### 实施步骤

1. **Phase B0（基线前）**：在 step() 末尾添加监控输出（不改逻辑）：
   ```python
   # 监控：每 1000 步打印一次
   ms.vital_output_x = vital_outputs[0]   # 新增 MotionState 字段
   ms.deviation_raw = deviation
   ```

2. **200k 基线**：记录 `vital_output_x` 和 `deviation_raw` 的均值和分布。

3. **Phase B1a**：代入反推公式计算 `w_cpc2vital`，实现 `vital_boost_factor` 调制，**保留旧注入，降低 DEVIATION_MOTOR_GAIN 为 0.1**（平滑过渡）。

4. **Phase B1a 验证通过后**：完全删除 `mot._membrane.inject(motor_drive, dt)` 调用。

## 脆弱点 2：ν-DA 双条件精确映射

### 映射澄清

| 条件 | 含义 | 对 DA 的作用 |
|------|------|-------------|
| ν < 0（单独） | 系统耗散 > 注入，张力在减小 | **不足以**触发 DA burst |
| ν < 0 **且** ΣΔ|ξ| < 0（Xin 总量同步下降） | 预测误差被成功消除（"顿悟"） | → DA burst（固化有效行为序列）|
| ν > 0 | 注入 > 耗散，系统困惑/发散 | → AGC gain↑（放大探索噪声）|

### 物理实现（纯半导体原语）

**两个换能电容**（在 `variant_adapter.__init__` 中初始化）：

```python
from ..components.semiconductor import Capacitor, MOSFET

# NuNegCapacitor：积分 ν 负向分量
self._nu_neg_cap = Capacitor(capacitance=1.0)
self._r_nu_neg = 2000.0   # τ = C×R/dt = 1×2000/0.001 = 2000k步（慢积分）
self._mosfet_nu_neg = MOSFET(v_threshold=0.05, gm=1.0)  # 阈值后验设定

# XinDecayCapacitor：积分 Xin 总量下降速率
self._xin_decay_cap = Capacitor(capacitance=1.0)
self._r_xin_decay = 500.0  # τ = 500k步（中速）
self._mosfet_xin_decay = MOSFET(v_threshold=0.01, gm=1.0)  # 阈值后验设定
self._prev_xin_total = 0.0
```

**在 step() 中，NuProbe 更新之后**：

```python
# --- ν 负向整流积分 ---
nu_now = self.nu_probe.system_nu_ema      # 只读，NuProbe 已在上游更新
nu_neg_in = max(0.0, -nu_now)            # 整流：只充负向分量
self._nu_neg_cap.inject(nu_neg_in, dt)
self._nu_neg_cap.leak(self._r_nu_neg, dt)
v_nu_neg = self._nu_neg_cap.voltage

# --- Xin 下降速率积分 ---
xin_total = sum(abs(b.config.xin_tension)
                for b in self.get_all_bundles())
xin_drop = max(0.0, self._prev_xin_total - xin_total)   # 整流：只充下降分量
xin_decay_in = xin_drop / max(dt, 1e-12)
self._xin_decay_cap.inject(xin_decay_in, dt)
self._xin_decay_cap.leak(self._r_xin_decay, dt)
v_xin_decay = self._xin_decay_cap.voltage
self._prev_xin_total = xin_total

# --- AND 门：串联 MOSFET ---
# 仅当两路信号均超阈，才产生 DA 固化信号
i_nu  = self._mosfet_nu_neg.conduct(v_nu_neg)
i_xin = self._mosfet_xin_decay.conduct(v_xin_decay)
da_consolidation_signal = i_nu * i_xin   # 串联乘积 = AND 门
```

**`da_consolidation_signal` 的接入点**：

作为额外电流注入 `da_input_currents`（与接口二 hunger_to_da 相同的位置）：
```python
for da_id in da_input_currents:
    da_input_currents[da_id] += da_consolidation_signal × w_consolidation
```

其中 `w_consolidation` 用 200k 基线中 `da_input_currents` 的均值反推，使固化信号 ≈ DA 注入均值的 50%（不过强，只是适度固化）。

### 参数阈值后验设定

两个 MOSFET 的阈值（`v_threshold`）无法预设，必须在 200k 基线后统计：
- `v_threshold_nu_neg`：设为 `V_nu_neg 分布的 75th 百分位`（只有强负向 ν 才触发）
- `v_threshold_xin_decay`：设为 `V_xin_decay 分布的 50th 百分位`（适中灵敏度）

**实施前不填具体数字**，先在 step() 中记录 `v_nu_neg` 和 `v_xin_decay` 的分布。

## 脆弱点 3：进食环流 V_feed 信号源替换

### 信号源澄清

| 候选 | 物理本质 | 问题 |
|------|---------|------|
| `max(thermo_vals) - min(thermo_vals)`（当前）| patch 温差对比（phasic）| 在热源中心 ΔT→0，V_feed 归零，丢失进食信号 |
| 口器绝对温度 | 外部环境状态（phasic 在中心稳定，但非进食量）| 表征位置，非能量流入量 |
| **DigestiveInterface.deposit_rate**（本方案）| 实际能量流入速率（tonic，只要在进食就持续 >0）| **本质物理量，选此** |

### 换能推导

DigestiveInterface.tick() 的每步返回值：
```
deposit_rate ≈ g_digest × eta × conductance × area × ΔT × dt
             = 1.0 × 0.02 × 2 × 1 × 5 × 0.001 = 2×10⁻⁴  [energy units/step]
```

FeedRateCapacitor 换能：

**注入电流换算**：`I_feed = deposit_rate / dt`（把每步能量转换为等效电流 A）
```
进食时：I_feed = 2e-4 / 0.001 = 0.2 A
不进食时：I_feed = 0
```

**稳态电压**：`V_ss = I_feed × R_FEED`

目标 V_ss ≈ 1.0V（与 thermal_stability 量级相当）：
```
R_FEED = V_ss / I_feed = 1.0 / 0.2 = 5.0 Ω
```

**时间常数**：tonic 信号需要平滑 phasic 噪声，取 τ = 5000步（5秒）：
```
τ [步] = R × C / dt → C = τ × dt / R = 5000 × 0.001 / 5.0 = 1.0 F
```

**FeedRateCapacitor 参数确认**：
- `C_FEED = 1.0 F`
- `R_FEED = 5.0 Ω`
- V_ss = 1.0V（进食时，ΔT≈5°C），τ ≈ 5000步 ✓

**量纲验证**：
- 注入：`I × dt = (deposit_rate / dt) × dt = deposit_rate` [energy/step → charge/step] ✓
- 泄漏：`V / R × dt = 1.0 / 5 × 0.001 = 2e-4` [charge/step] = deposit_rate ✓ 稳态闭合

### 实施代码

**在 `variant_adapter.__init__` 中**（接 DigestiveInterface 初始化之后）：
```python
# FeedRateCapacitor: DigestiveInterface deposit rate → V_feed [V]
# R_FEED=5.0 → V_ss=1.0V（进食时，ΔT≈5°C）；τ=5000步（tonic 平滑）
# BIO: 胃肠道缓慢积分摄入功率，对应饱腹感慢慢建立（分钟尺度）
# Q3: C=1.0, R=5.0, V_ss = (deposit_rate/dt) × R = 0.2 × 5 = 1.0V ✓
self._feed_rate_cap = Capacitor(capacitance=1.0)
_R_FEED = 5.0
```

**在 `step()` 中**（替换 feed_alignment 的计算和传入，两处改动）：

```python
# 改动 1：保存 digestive_interface.tick() 返回值（原 L967，返回值被丢弃）
deposit_rate = self.digestive_interface.tick(
    self.thermal_mouth, self.energy_store, dt=dt)

# 改动 2：FeedRateCapacitor 换能（替代原 feed_alignment 计算块）
# 原：feed_alignment = max(thermo_vals) - min(thermo_vals)
# 新：
_I_feed = deposit_rate / max(dt, 1e-12)   # energy/step → A
self._feed_rate_cap.inject(_I_feed, dt)
self._feed_rate_cap.leak(_R_FEED, dt)      # _R_FEED = 5.0
v_feed = self._feed_rate_cap.voltage

# circulation_proportion.step() 接收 v_feed（签名不变，第三参数）
circ = self.circulation_proportion.step(
    thermal_stability, body_speed, v_feed, dt)
```

旧的 `feed_alignment = (max(thermo_vals) - min(thermo_vals) ...)` 计算块整体删除（patch 温差对比仍可保留用于其他诊断，但不再传入 CPC）。

### 对 DR5 的影响

DR5 当前用 patch 温差对比间接反映进食对齐。替换后 V_feed 来自实际 deposit rate，DR5 的计算不受影响（DR5 是实验脚本层面的指标，不读 CPC 内部信号）。

## 实施顺序与前置关系

| 修正 | 前置条件 | 实施时机 |
|------|---------|---------|
| 脆弱点3（V_feed 换源）| 无（纯物理化，不改行为逻辑）| **立即可执行**（Phase A 内） |
| 脆弱点1（HC-016 补偿）| 200k 基线测量 vital_output 和 deviation 均值 | Phase B1a（基线后）|
| 脆弱点2（ν-DA 双条件）| 200k 基线统计 v_nu_neg 和 v_xin_decay 分布 | Phase C1（基线后）|

### 脆弱点3优先实施理由

`feed_alignment` 的当前 patch 温差实现（max-min）是 phasic 信号，在热源中心趋零，导致进食环流 V_feed 在正确位置（最近热源处）反而塌陷。这是一个主动破坏 CPC 稳态检测准确性的问题，应优先于 HC-016 的替换修复。实施不改变任何神经元/Bundle，只改 CPC 的输入信号，回归无影响。
