## 二、三项风险分析与预处理方案

### 风险 R1（高）：移除 consume_nearby 后能量链可能断裂

**机制**：  
`consume_nearby` 是被动皮肤吸收（基于身体与热源距离，在 radius 内自动注入能量）。移除后，能量补充路径唯一变为：

```
ThermalMouth.step(T_mouth, ΔT) → raw_intake
→ DigestiveInterface.tick() → deposit_rate ≈ g_digest × raw_intake
→ EnergyStore.deposit()
```

`ThermalMouth` 需要口器处于热源附近且有温度梯度信号才产生 raw_intake；若身体未接触热源，deposit_rate ≈ 0，EnergyStore 持续消耗直至 fill_fraction → 0，导致身体死亡切换（fill < 0.05 触发死亡）。

**影响评估**：  
- `YolkSac` 提供初始垫底（约 500 步），但不可补充。  
- 回归测试（T7.1 Kinetic energy > 0）在 10k 步内依靠 YolkSac + consume_nearby 共同维持；仅凭 10k 步回归**无法验证移除后的长期能量健康**。  
- 若 VariantCircuit 在 50k 步内 fill_fraction 降至 0.05 以下，T7.1 将在长实验中失败，行为实验数据无效。

**预处理方案（R1-Pre）**：  
在移除 consume_nearby **之前**，必须完成以下能量链验证实验：

```
实验 R1-Pre：能量链独立验证
目标：确认仅靠 ThermalMouth→DigestiveInterface，EnergyStore 在 50k 步内不耗尽
配置：单热源，body 初始位置 ≤ 3 单位内
指标：
  - 每 5000 步打印 fill_fraction
  - 最低值 > 0.1（安全余量 2× death threshold）
  - deposit_rate 均值 > 0（表明 ThermalMouth 有效感应热源）
通过标准：fill_fraction 全程 > 0.1，且 deposit_rate > 0 至少 50% 步数
```

若实验通过 → 可安全移除 consume_nearby。  
若实验不通过 → 需先调整 ThermalMouth `eta`（热效率）或 DigestiveInterface `g_digest`，使摄入量足以维持基础代谢，**再**移除。

### 风险 R2（中）：slow_relay τ 修改影响热趋性时序

**机制**：  
`slow_relay` 作为 DC 基线追踪器：`phasic = relay − slow_relay`。τ 越长，slow_relay 追踪越慢，phasic 信号持续时间越长（模拟更强的 SA2 适应延迟）。

`r_leak` 从 5000 → 15000 使τ从 5s 变为 15s（步为单位，dt=1.0 仿真步）。  
效果：phasic 在热前锋通过后继续"尾流"15s（而非原来 5s），可能：
- 正面：更接近 TRPV1 脱敏的生理时间尺度
- 负面：在快速翻转的热场（如 World 2.0 三热源场景）中，phasic 信号积累串扰

**原方案生物依据**：TRPV1 脱敏时间常数约 10-30s（实验室数据），而当前 5s 偏短。方向正确，数值合理。

**预处理方案（R2-Pre）**：  
修改 `r_leak` 前，先记录当前 phasic 时序基线：

```python
# 在短程测试中打印 phasic_left.activation 时序
# 记录：热前锋响应峰值、尾流时长（阈值 0.01 以上持续多少步）
# 对比 τ=5000 和 τ=15000 时的尾流长度
```

允许的修改范围：**一次只改一个 r_leak**（先改 slow_relay_left，验证不影响回归，再改 slow_relay_right）。  
验收标准：21/21 PASS，且 T5.1（Xin peak 频率）不漂移超过 0.1Hz。

### 风险 R3（中）：DwellSensor 施密特触发器参数盲设

**机制**：  
施密特触发器的 on 阈值（0.01）必须低于 phasic 在进食状态下的正常激活幅度，否则 DwellSensor 永不触发，饱腹信号永远为零。

当前代码中 phasic 神经元：`C=0.5, r_leak=100.0`，V_ss = bc_input × R = 依赖 relay→phasic bundle 权重。  
需要先测量 phasic 典型激活幅度后，再确定施密特阈值。

**预处理方案（R3-Pre）**：  
在实现施密特触发器前，先用短程诊断脚本采样：

```python
# 运行 1000 步，打印 phasic_left.activation 的 [min, mean, max, >0 比例]
# 热源在场景内：phasic 应有明显激活（> 0.01）
# 冷场景下：phasic 应接近 0
```

根据实测幅度校准双阈值（on_thresh = 0.5 × mean_active；off_thresh = on_thresh × 0.5）。

## 三、误报删除

**原方案 3.2「float64 显式声明」**：  
Python 的 `float` 类型即 IEEE 754 双精度（64 位）。`Neuron._membrane.voltage`、`EnergyStore.fill_fraction` 等均为 Python float，无 numpy float32 路径。此条款在当前实现中无意义，**从实施计划中删除**。
