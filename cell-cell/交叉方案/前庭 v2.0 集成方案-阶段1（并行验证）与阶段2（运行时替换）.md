# 前庭 v2.0 集成方案：阶段1（并行验证）与阶段2（运行时替换）

**日期**：2026-06-29  
**适用范围**：`variant_adapter.py`、`vestibular/chain_v2.py`、`vestibular/chain.py`  
**目标**：在零回归风险的前提下，将前庭 v2.0 从"单元测试通过"升级为"运行时驱动行为"


## 一、总体策略：特性标志驱动的并行替换

在 `variant_adapter.py` 中引入一个全局配置变量：

```python
# variant_adapter.py 顶部
VESTIBULAR_MODE = "V1_ONLY"   # 阶段0（当前状态）
# VESTIBULAR_MODE = "V2_PARALLEL_LOG"  # 阶段1
# VESTIBULAR_MODE = "V2_ACTIVE_DRIVE"  # 阶段2
```

所有改动均围绕此标志展开。切换标志即可在阶段间回退，无需撤销代码变更。


## 二、阶段1：并行验证（V2_PARALLEL_LOG）

### 2.1 行为定义

- **保留** `VestibularChain`（v1.0）作为 `Motor` 的唯一驱动源。
- **新增** `VestibularChainV2`（v2.0）与 v1.0 **并行运行**，接收相同的物理输入（`deflection_input`）。
- **阻断** v2.0 的任何输出对 `Motor` 和 `EnergyStore` 的影响。
- **记录** v2.0 的内部状态（Enc/Col 激活值、FIFO 填充率、G_eff 值），与 v1.0 的输出进行对比。

### 2.2 修改点（仅限 `variant_adapter.py`）

**位置**：`VariantAdapter.__init__()` 中初始化两个链

```python
# v1.0 始终初始化（驱动源）
self.vestibular_v1 = VestibularChain(dt=self.dt)

# v2.0 按标志初始化（仅用于日志）
if VESTIBULAR_MODE in ["V2_PARALLEL_LOG", "V2_ACTIVE_DRIVE"]:
    self.vestibular_v2 = VestibularChainV2(dt=self.dt)
else:
    self.vestibular_v2 = None
```

**位置**：`VariantAdapter.step()` 中并行执行

```python
# 1. 计算 deflection_input（物理世界的加速度/角速度）
deflection_input = self._compute_deflection()

# 2. v1.0 正常运行（产生 motor 输出）
v1_out = self.vestibular_v1.step(deflection_input)

# 3. v2.0 并行运行（仅日志）
v2_metrics = None
if self.vestibular_v2 is not None:
    v2_out = self.vestibular_v2.step(deflection_input)
    v2_metrics = {
        "enc_avg": np.mean([n.activation for n in self.vestibular_v2.enc_neurons]),
        "col_avg": np.mean([n.activation for n in self.vestibular_v2.col_neurons]),
        "gain_eff": self.vestibular_v2.last_gain,  # 需在 chain_v2.step() 中暴露
        "fifo_util": self.vestibular_v2.fifo_utilization(),  # 需新增方法
    }
    # 关键：丢弃 v2_out，不累加至 velocity

# 4. motor 叠加（仅 v1.0）
self.motor_velocity += v1_out * self.motor_gain

# 5. 日志记录（将 v2_metrics 写入 probe）
if v2_metrics:
    self.probe.record("vestibular_v2", v2_metrics)
```

**位置**：`VariantAdapter._compute_deflection()` 保持原样，v1.0 和 v2.0 接收完全相同的 `deflection_input` 数组（6 维）。

### 2.3 验证标准

| 检查项 | 标准 | 失败时的处置 |
| :--- | :--- | :--- |
| 回归测试（21项） | 全部 PASS | 阶段1失败，保持 V1_ONLY，分析 v2.0 的日志偏差 |
| v2.0 Enc 激活值 | 在 2 Hz 输入下 > 0.30V（理论 0.367V ± 10%） | 检查 G_eff 计算或 FIFO 填充状态 |
| v2.0 FIFO 延迟精度 | `delay_steps` 与实际读出的信号偏移误差 < ±1 步 | 检查 FIFO 环形缓冲区的读写指针逻辑 |
| v2.0 增益稳定性 | G_eff 随 P_avail 波动，无突变（∆G < 0.5/步） | 检查 P_avail 的滞后取值（fill(t-1) 是否生效） |

### 2.4 运行时长

**最少 50,000 步**（约 50 秒模拟时间），覆盖：
- 轨道直线段（纯平移 / oto 激活）
- 轨道弯曲段（旋转 + 平移复合运动）
- 热源补给段（能量池 P_avail 波动，验证增益响应）

### 2.5 阶段1完成标志

- 上述验证标准全部通过。
- v2.0 的 Enc/Col 激活曲线与 v1.0 在**波形特征**上一致（时域延迟差 9ms 以内），**幅度**上因软饱和而更平滑（无硬截断尖峰）。


## 三、阶段2：运行时替换（V2_ACTIVE_DRIVE）

### 3.1 行为定义

- **禁用** v1.0 对 `Motor` 的输出贡献（但仍保留其 `step()` 调用以供对比日志）。
- **启用** v2.0 对 `Motor` 的输出贡献。
- **热觉链路**：保持不变，继续使用 v1.0 的 `HebbianCircuit` 中的热觉束。**关键**：热觉链路**不**经过 v2.0 地址空间，因此前庭 v2.0 的 Col 层仍会通过共享物理层（World）对热觉产生旁路噪声——这是阶段3的目标，阶段2不处理此问题。

### 3.2 修改点（仅限 `variant_adapter.py`）

**位置**：`VariantAdapter.step()` 中的 motor 累加逻辑

```python
# v1.0 始终运行（但输出是否生效由标志控制）
v1_out = self.vestibular_v1.step(deflection_input)
v2_out = None
if self.vestibular_v2 is not None:
    v2_out = self.vestibular_v2.step(deflection_input)

# 根据标志决定驱动源
if VESTIBULAR_MODE == "V2_ACTIVE_DRIVE":
    drive_output = v2_out if v2_out is not None else np.zeros_like(v1_out)
    # 同时记录 v1_out 为参考（不叠加）
    self.probe.record("vestibular_v1_ref", v1_out)
else:
    drive_output = v1_out

# 累加至 motor
self.motor_velocity += drive_output * self.motor_gain
```

**位置**：`VariantAdapter.step()` 中能量消耗的归属

```python
# 当前能量消耗（P_T）是按神经元发放计算的，v1.0 和 v2.0 各自有自己的神经元。
# 由于 v2.0 的神经元发放率可能不同（软饱和改变了 Aff→Enc 的激活模式），
# 需确保 EnergyStore 同时扣减 v1.0 和 v2.0 的消耗（若 v2.0 并行运行）。
# 在阶段2，v1.0 的神经元仍在运行但输出被屏蔽，其发放消耗仍需扣除，以模拟真实对比。

# 建议：在 step() 末尾统一计算：
total_spike_cost = self.vestibular_v1.spike_cost() + (self.vestibular_v2.spike_cost() if v2_out is not None else 0)
self.energy_store.drain(total_spike_cost * self.spike_cost_coeff)
```

**注意**：阶段2中 v2.0 的 `spike_cost()` 必须被计入，否则能量账本会出现"免费午餐"（v2.0 驱动行为但不消耗能量），破坏 TSI 审计的物理一致性。

### 3.3 回归测试预期

| 测试项 | 预期变化 | 原因 |
| :--- | :--- | :--- |
| T2.1（Active encoding） | ≥ v1.0 水平（~0.70） | v2.0 的 G_eff 在满载时等效于 14.7 倍增益，信号更强 |
| T2.2（Quiet encoding） | 无显著变化 | 热觉链路未动，quiet 输入仍为 0 |
| T2.3（Selectivity ratio） | 可能波动 | 旁路噪声仍存在，但 v2.0 的 Col 时序不同可能导致 quiet 激活幅度变化 |
| T5.1（Xin peak freq） | 稳定在 0.5 ± 0.2 Hz | v2.0 的软饱和消除了硬截断尖峰，应比 v1.0 更平滑（二次谐波抑制更好） |
| 其他 17 项（热觉、能量、前庭基础） | 不变 | 热觉回路未动，能量账本已计入 v2.0 消耗 |

**风险点**：T2.3 阈值（1.5x）在阶段2可能偶发失败（与报告中的随机抖动一致）。若阶段2连续运行 5 次中 T2.3 失败 ≥ 2 次，则应**暂缓阶段2**，先启动阶段3（热觉地址隔离）。

### 3.4 回滚计划

阶段2 内嵌一键回滚机制：

```python
# 若阶段2导致任何回归测试失败，在 variant_adapter.py 中执行：
VESTIBULAR_MODE = "V1_ONLY"   # 立即恢复 v1.0 驱动
# 无需重启进程，下次 step() 即生效
```

### 3.5 阶段2完成标志

- 连续 5 次回归测试（每次 100k 步）中，T2.1、T5.1 全部 PASS，T2.3 至少 4 次 PASS。
- v2.0 驱动的物理轨迹（电机速度、能量消耗曲线）与 v1.0 驱动的轨迹在**宏观行为**上一致（热源趋向成功），但**微观波形**更平滑（无硬截断尖峰）。

## 六、风险与缓解措施

| 风险 | 概率 | 缓解措施 |
| :--- | :--- | :--- |
| v2.0 的 FIFO 延迟导致驱动相位滞后，使热源趋向行为失败 | 低 | 阶段1先验证延迟精度；若滞后仍影响趋向，可在 Motor 叠加时加入相位补偿（暂时性方案，待影子层学习补偿） |
| v2.0 的软饱和改变了能量消耗曲线，导致 EnergyStore 提前进入昏迷 | 中 | 阶段2中 v2.0 的 spike_cost 必须精确计算，并在 `P_baseline` 中预留 20% 安全边际 |
| T2.3 在阶段2失败率 > 20% | 中 | 立即回滚至 V1_ONLY，并将阶段3（热觉地址隔离）优先级提升至最高 |
| v2.0 的 `nearby()` 初始化连接与 v1.0 的硬编码拓扑不一致，导致 Motor 输出方向错误 | 低 | 阶段1中额外记录 v2.0 的 motor 输出方向与 v1.0 的差异；若方向相反，调整 `nearby()` 中的地址映射 |
