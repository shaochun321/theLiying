## 一、dt 在量纲锚定中的角色

dt 出现在三个地方：

| 位置 | 作用 | 如果 dt 改变 |
| :--- | :--- | :--- |
| FIFO 延迟计算 | `delay_steps = L / (v_cond × dt)` | dt 变大 → delay_steps 变小 |
| 扫描实验频率 | `steps_per_cycle = 1 / (freq × dt)` | dt 变大 → 每周期步数减少 |
| 增益反推 | `Q_spike = r_supply × dt` | dt 变大 → Q_spike 变大 → synapse_gain 变小 |

**dt 的取值直接影响锚定计算的所有数值结果。** 这不是一个可以“先放着以后再说”的问题——必须在 Phase 1 扫描实验之前确定。

---

## 二、两个可选项

| 选项 | dt 物理含义 | 依据 | 后果 |
| :--- | :--- | :--- | :--- |
| **A：dt = 1 ms** | 当前代码默认值（`dt=0.001`）| 与现有实验脚本一致 | FIFO 延迟 2 步 = 2 ms，在生物 VOR 窗口内 |
| **B：dt = 10 ms** | 也常见于生物模型 | 有些生物模型使用更大步长 | 所有延迟数值缩小 10×，需重新标定 |

## 三、关键判断：当前代码实际上已经假设了 dt=1ms

这不是一个“我们选哪个”的开放问题——**当前代码已经在使用 dt=1ms 的隐含假设**：

| 代码位置 | 数值 | 隐含的 dt 假设 |
| :--- | :--- | :--- |
| `chain.py` cupula 时间常数 | `tau_cupula = 4.0` | 4.0 步 × 0.001 = 4 ms？但生物 cupula τ ≈ 4 s！|
| `chain.py` HC 时间常数 | `tau_gate = 0.005` | 0.005 步 × 0.001 = 5 μs？不合理 |
| `hebbian.py` 资格迹 | `tau_elig = 300` | 300 步 × 0.001 = 0.3 s，合理 |
| `variant_adapter.py` | `dt = 0.001` | 显式声明 |

**问题**：当前代码中的时间常数并非都以 dt=1ms 为基准设计的。`tau_cupula=4.0` 如果按 1ms 算只有 4ms，但生物 cupula 时常数是 4s——差了 1000 倍。

这说明：**当前代码中的时间常数不是生物时间，而是“模型步数”。** dt=1ms 只是一个约定，并不代表所有时间常数都按这个比例尺映射到了生物时间。

---

## 四、我的建议：显式声明 dt = 1ms，但承认它是“模型时间步长”，不是“生物时间映射”

**这不是一个生物物理决定，而是一个工程约定。** 我们不需要让 cupula 时间常数在数值上等于 4s，我们只需要：

1. **所有时间相关参数使用统一的步数单位**
2. **在锚定计算中，使用一致的换算关系**

具体操作：

```
声明：dt = 0.001（模型时间步长），对应 1 ms（工程约定）

换算规则：
  - FIFO 延迟：L / (v_cond × dt) → 步数
  - 扫描实验频率：freq_Hz × dt → 每周期步数
  - 时间常数：τ_biological / dt → 步数（如 cupula τ=4s → 4000 步）
```

**关键**：我们不要求 `tau_cupula=4.0` 在代码中改为 4000——我们只是**在锚定计算中使用 4000 步作为 cupula 时常数的参考值**，用于验证锚定结果是否在生物合理范围内。

## 五、结论

| 问题 | 回答 |
| :--- | :--- |
| 选择 dt = 1ms 还是 10ms？| **dt = 1ms**（与现有代码一致） |
| 是否要求修改代码中的时间常数？| **不要求**——只在锚定计算中使用换算 |
| 扫描实验频率 2Hz → 多少步？| 500 步/周期（`1/(2×0.001)=500`）|
| FIFO 延迟 2 步 → 多少 ms？| 2 ms（在 VOR 生物窗口 5-15ms 内）|

**Phase 1 扫描实验可以按此约定执行。** 扫描脚本中的频率参数使用 2Hz，换算为 500 步/周期。
