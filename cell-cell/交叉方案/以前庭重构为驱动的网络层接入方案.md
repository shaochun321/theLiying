# 方案：以前庭重构为驱动的网络层接入方案

## 一、前庭对网络层的完整需求清单（从审计报告反推）

在定义网络层之前，先列出前庭具体需要从网络层获取什么：

| 前庭组件 | 需要从网络层获取的信息 | 用途 | 调用时机 |
| :--- | :--- | :--- | :--- |
| MET（6个，各轴1个） | 注册后获得地址 | 标识自己，供下游查询 | 初始化 |
| HC（6个） | 注册后获得地址 | 标识自己，供上下游查询 | 初始化 |
| Aff_reg（6个） | 注册后获得地址 | 标识自己，供上下游查询 | 初始化 |
| Aff_irr（6个） | 注册后获得地址 | 标识自己，供上下游查询 | 初始化 |
| Enc（6个） | 注册后获得地址 | 标识自己，供上下游查询 | 初始化 |
| Col（6个） | 注册后获得地址 | 标识自己，供上下游查询 | 初始化 |
| MET→HC 束（6条） | `delay(src, dst)` | 设置 FIFO 延迟长度 | 束初始化 |
| HC→Aff 束（6条，每束双目标） | `delay(src, dst)` | 设置 FIFO 延迟长度 | 束初始化 |
| Aff→Enc 束（12条，reg+irr各6） | `delay(src, dst)` + `energy_cost(src, dst)` | 设置 FIFO 延迟 + 计入 $P_S$ | 束初始化 |
| Enc→Col 束（6条） | `delay(src, dst)` + `energy_cost(src, dst)` | 设置 FIFO 延迟 + 计入 $P_S$ | 束初始化 |
| Col→Motor 拓扑束 | `nearby(addr_Col, radius)` | 查找可连接的 Motor 地址 | sprout 触发时 |

**核心约束**：前庭的所有延迟查询必须在初始化阶段完成并缓存。运行时前庭不调用网络层，以保证实时性。

## 二、为前庭定制的地址系统

### 2.1 地址元组定义

```
Address = (region: u8, layer: u8, τ_class: u8, axis: u8, index: u8)
```

各字段对前庭的具体含义：

| 字段 | 前庭的取值范围 | 说明 |
| :--- | :--- | :--- |
| `region` | `0x02`（脑干前庭核）统一 | 所有前庭神经元属于同一脑区 |
| `layer` | `1`（MET）, `2`（HC）, `3`（Aff）, `4`（Enc）, `5`（Col） | 对应前庭处理层级 |
| `τ_class` | `1`（快，MET/HC/Aff）, `2`（中，Enc/Col） | MET→HC→Aff 为快响应，Enc/Col 为整合级 |
| `axis` | `0`（yaw）, `1`（pitch）, `2`（roll）, `3`（oto_x）, `4`（oto_y）, `5`（oto_z） | 标识所属轴 |
| `index` | 同一 layer 内的唯一序号（0~5） | 区分同层同轴的不同神经元（如 Aff_reg 和 Aff_irr） |

### 2.2 前庭 6 轴的地址编码表（供网络层内部使用）

| 轴 | MET 地址 | HC 地址 | Aff_reg 地址 | Aff_irr 地址 | Enc 地址 | Col 地址 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| yaw | (0x02,1,1,0,0) | (0x02,2,1,0,0) | (0x02,3,1,0,0) | (0x02,3,1,0,1) | (0x02,4,2,0,0) | (0x02,5,2,0,0) |
| pitch | (0x02,1,1,1,0) | (0x02,2,1,1,0) | (0x02,3,1,1,0) | (0x02,3,1,1,1) | (0x02,4,2,1,0) | (0x02,5,2,1,0) |
| roll | (0x02,1,1,2,0) | (0x02,2,1,2,0) | (0x02,3,1,2,0) | (0x02,3,1,2,1) | (0x02,4,2,2,0) | (0x02,5,2,2,0) |
| oto_x | (0x02,1,1,3,0) | (0x02,2,1,3,0) | (0x02,3,1,3,0) | (0x02,3,1,3,1) | (0x02,4,2,3,0) | (0x02,5,2,3,0) |
| oto_y | (0x02,1,1,4,0) | (0x02,2,1,4,0) | (0x02,3,1,4,0) | (0x02,3,1,4,1) | (0x02,4,2,4,0) | (0x02,5,2,4,0) |
| oto_z | (0x02,1,1,5,0) | (0x02,2,1,5,0) | (0x02,3,1,5,0) | (0x02,3,1,5,1) | (0x02,4,2,5,0) | (0x02,5,2,5,0) |

**关键设计**：6 轴在地址空间中的“语义距离”由 `axis` 字段的数值差决定。半规管三轴（axis=0,1,2）彼此相邻（差值为1），耳石三轴（axis=3,4,5）彼此相邻（差值也为1），但簇间（如 axis=2 到 axis=3）差值为1（连续编码）。这看似簇间距离与簇内距离相同，实际上差异通过**网络层的距离函数**实现，而非地址本身的数值差。见下节。

## 三、为前庭定制的距离函数（$L_{total}$）

网络层对前庭地址的 `delay()` 和 `energy_cost()` 查询，使用以下距离计算：

### 3.1 空间分量 $L_{spatial}$（基于 axis 的簇结构）

半规管（axis 0-2）内部距离 = 1  
耳石（axis 3-5）内部距离 = 1  
半规管簇 ↔ 耳石簇距离 = 3（固定偏移）

数学表达：
```
if axis_i <= 2 and axis_j <= 2: L_spatial = 1
else if axis_i >= 3 and axis_j >= 3: L_spatial = 1
else: L_spatial = 3  # 跨簇
```

### 3.2 时间分量 $L_{temporal}$（基于 τ_class 差异）

```
L_temporal = |τ_class_i - τ_class_j| × 0.5
```

### 3.3 层级分量 $L_{layer}$（基于 layer 差值）

```
L_layer = |layer_i - layer_j| × 1.0
```

### 3.4 总距离

```
L_total(a_i, a_j) = L_spatial + L_temporal + L_layer
```

**前庭内部典型延迟值示例**：

| 连接 | L_spatial | L_temporal | L_layer | L_total | delay_steps (v_cond=1, dt=0.001) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| MET_yaw → HC_yaw（同轴同簇，layer差1） | 1 | 0 | 1 | 2 | 2000 |
| HC_yaw → Aff_yaw（同轴同簇，layer差1） | 1 | 0 | 1 | 2 | 2000 |
| Aff_yaw → Enc_yaw（同轴同簇，layer差1，τ差1） | 1 | 0.5 | 1 | 2.5 | 2500 |
| Enc_yaw → Col_yaw（同轴同簇，layer差1，τ相同） | 1 | 0 | 1 | 2 | 2000 |
| yaw → oto_x（跨簇，layer相同，τ相同） | 3 | 0 | 0 | 3 | 3000 |

**物理意义**：跨簇（半规管↔耳石）的信号延迟比簇内多 1000 步（1秒模拟时间），使 STDP 能够区分旋转和平移的因果关系。

## 四、为前庭定制的增益标定（解决审计 3% 裕量）

网络层的 `energy_cost()` 查询结果不仅用于 $P_S$，还直接参与前庭的增益计算：

### 4.1 增益公式（与前庭地址绑定）

每个前庭 Aff→Enc 束的增益不是全局常量，而是由网络层根据源地址和目标地址的**关系**返回一个增益系数：

```
G_eff(a_src, a_dst) = G_base × (1 + α × P_avail/P_baseline) × (1 + β × (1 - L_temporal/L_max))
```

- 第一项：能量门控（与合取报告一致）
- 第二项：时间差异补偿——τ_class 差异越大的连接，增益越高（弥补时间常数不匹配造成的信号衰减）

**具体数值（针对前庭）**：
- `G_base`：2.0（与热觉回归测试兼容）
- `α`：**5.0**（修正了 document 40 中 α=0.1 的致命缺陷）
- `β`：0.3（时间差异补偿系数）
- `L_max`：最大可能的时间距离（= 4 × 0.5 = 2.0）

**2 Hz 工况下的验证**：
- `P_avail/P_baseline = 1.0`（满载），`L_temporal = 0.5`（Aff 到 Enc 的 τ 差）
- `G_eff = 2.0 × (1 + 5.0 × 1.0) × (1 + 0.3 × (1 - 0.5/2.0)) = 2.0 × 6.0 × 1.225 = 14.7`
- 2 Hz 输入 → `V_ss = 2.0 × 2.5 × 14.7 × 0.001 × 5.0 = 0.367V`，超过 Enc 阈值 0.30V，**有 22% 裕量**。

**关键设计决策**：`α=5.0` 仅应用于前庭地址段（region=0x02），不影响热觉束。网络层的 `energy_cost()` 查询隐式携带此信息——增益系数是地址查询的副产品，而非全局参数。

## 五、为前庭定制的软饱和与 FIFO（网络层工具函数）

网络层提供两个标准工具函数，专供前庭束初始化时使用：

### 5.1 软饱和函数（替换审计发现的硬截断）

```
def soft_saturate(I_in, r_supply=0.05):
    return I_in / (1.0 + I_in × r_supply)
```

**调用点**：前庭所有 MET→HC 和 HC→Aff 束在传递电流时调用。

### 5.2 FIFO 延迟缓冲区

```
def delay_buffer(delay_steps):
    # 返回一个环形缓冲区，容量 = delay_steps
    # 写入时存入当前值，读出时返回 delay_steps 步前的值
```

**调用点**：前庭每个束在初始化时通过 `delay(src, dst)` 查询 `L_total`，计算 `delay_steps = ceil(L_total / (v_cond × dt))`，然后实例化一个对应长度的 FIFO。

**前庭各束的 FIFO 长度表**：

| 束 | L_total | delay_steps (v_cond=1.0, dt=0.001) |
| :--- | :--- | :--- |
| MET→HC（同簇） | 2 | 2000 |
| MET→HC（跨簇） | 4 | 4000 |
| HC→Aff（同簇） | 2 | 2000 |
| HC→Aff（跨簇） | 4 | 4000 |
| Aff→Enc（同簇） | 2.5 | 2500 |
| Aff→Enc（跨簇） | 4.5 | 4500 |
| Enc→Col（同簇） | 2 | 2000 |
| Enc→Col（跨簇） | 4 | 4000 |

## 六、为前庭定制的拓扑生长接口（OTO 轴平等化）

网络层提供 `nearby(addr, radius)` 查询，专供前庭 Col→Motor 的 sprout 决策：

### 6.1 查询语义

```
nearby(addr_Col, radius=3) → 返回所有地址与 addr_Col 的 L_total ≤ 3 的 Motor 神经元列表
```

### 6.2 初始拓扑分配（解决 oto 轴弱连接问题）

在前庭初始化时，网络层为每个 Col 地址查询附近的 Motor 地址，并建立初始连接：

| Col 地址 | nearby(radius=3) 返回的 Motor | 初始权重 |
| :--- | :--- | :--- |
| Col_yaw | Motor_rotation_x（+ 附近的其他 Motor） | 0.25 |
| Col_pitch | Motor_rotation_y（+ 附近的其他 Motor） | 0.25 |
| Col_roll | Motor_rotation_z（+ 附近的其他 Motor） | 0.25 |
| Col_oto_x | Motor_translation_x（+ 附近的其他 Motor） | 0.25 |
| Col_oto_y | Motor_translation_y（+ 附近的其他 Motor） | 0.25 |
| Col_oto_z | Motor_translation_z（+ 附近的其他 Motor） | 0.25 |

**关键设计**：所有 6 轴的初始权重均为 0.25，OTO 轴不再被预设为弱连接。网络层的 `nearby()` 查询是这一平等化的基础设施——它只基于拓扑距离，不包含任何关于“轴类型”的偏见。

## 七、前庭-网络层交互的完整时序图

```
系统启动
    │
    ├─ [初始化阶段]
    │   │
    │   ├─ 1. 前庭创建 24 个神经元（MET×6, HC×6, Aff_reg×6, Aff_irr×6, Enc×6, Col×6）
    │   │
    │   ├─ 2. 每个神经元调用 network.register(neuron) → 获得 Address
    │   │
    │   ├─ 3. 对每条束（共 12+23=35 条）：
    │   │       ├─ delay = network.delay(src_addr, dst_addr) → 计算 L_total
    │   │       ├─ cost = network.energy_cost(src_addr, dst_addr) → 计算维持税
    │   │       ├─ 创建 FIFO(delay_steps = ceil(delay / (v_cond × dt)))
    │   │       └─ 将 cost 累入 EnergyStore.P_S
    │   │
    │   ├─ 4. 对每个 Col 地址：nearby = network.nearby(col_addr, radius=3)
    │   │       └─ 创建初始拓扑连接（权重 0.25）
    │   │
    │   └─ 5. 前庭增益系数：G_eff = network.gain_coeff(src_addr, dst_addr) → 存入束配置
    │
    ├─ [运行阶段]（网络层不再参与）
    │   │
    │   ├─ MET.step() → 软饱和 → FIFO(MET→HC) → HC.step()
    │   ├─ HC.step() → 软饱和 → FIFO(HC→Aff) → Aff.step()
    │   ├─ Aff.spike() → FIFO(Aff→Enc) → Enc.step()（使用预存的 G_eff）
    │   ├─ Enc.act() → FIFO(Enc→Col) → Col.step() → 侧抑制
    │   └─ Col.act() → 拓扑束（权重 0.25 起）→ Motor.step()
    │
    └─ [触发扩展时]
            ├─ 新神经元 register() → 获得新地址
            ├─ network.nearby() → 查找可连接的目标
            └─ 新束查询 delay + cost → 创建 FIFO
```

## 八、与前庭审计问题的完整闭环声明

| 审计问题 | 本方案中的解决机制 | 涉及的网络层功能 |
| :--- | :--- | :--- |
| PowerRail 硬截断 | 软饱和函数 `soft_saturate()` | 网络层工具函数 |
