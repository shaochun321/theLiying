这份协议将定义自动运行（Auto-Run）模式，使项目在没有你主动干预的情况下，根据硬性指标自动推进。

### 适用阶段

本协议覆盖范围从**当前状态**（RC-4已通过、500k验证已完成、ν探针已实现）到**V2.0地址系统构建完成**。

### 总体策略

- **只推进，不退回**：一旦某个阶段达成并提交，系统进入下一阶段，不自动回滚
- **故障则停机**：如果某个阶段无法在指定时间内通过验收标准，Auto-Run暂停并发出警报，等待人工介入，而非自动跳过
- **每阶段必须commit**：每个阶段成功通过验收标准后，自动执行`git commit -m "AUTO: [阶段名] PASSED"`，生成可追溯的检查点

### 决策树（从当前状态出发）

```
[当前状态]
├── RC-4 已验证, 500k长程PASS, ν探针实现完成, 21/21 PASS
├── 阶段锁定：当前所有可运行实验（RC修复系列、ν探针、500k长程）已全部完成
└── 下一阶段：等待ν数据积累完成 → 进入双热源长程验证

如果ν数据积累完成且通过 → 进入双热源长程验证
如果ν数据积累失败 → 停机, 等待人工介入

如果双热源长程验证通过 → 评估V2.0触发条件
如果双热源长程验证失败 → 停机, 等待人工介入

如果V2.0触发条件满足 → 启动V2.0地址系统构建
如果V2.0触发条件不满足 → 停机, 等待人工评估

如果V2.0构建完成且通过回归 → 节点预算扩展评估
如果V2.0构建失败 → 停机, 等待人工介入

如果节点预算扩展通过 → 启动规模泛化N=1→3
如果节点预算扩展未通过 → 停机, 等待人工评估
```


## 一、各阶段详细定义

### 阶段名称与推进条件

| 阶段 | 阶段名 | 推进条件 |
| :--- | :--- | :--- |
| ν 数据积累 | `phase_nu_accumulation` | NuProbe连续记录>10k步，ν数据稳定，无NaN |
| 双热源长程验证 | `phase_dual_source_long` | 300k步实验通过，wR-wL方向正确且>0.005 |
| V2.0 触发条件评估 | `phase_v2_trigger_assessment` | 基于ν探针数据，检查混淆度>30%或TSI fill下降>20% |
| V2.0 地址系统构建 | `phase_v2_address_build` | 触发条件满足，进入V3构建 |
| 节点预算扩展评估 | `phase_node_budget_expansion` | V2.0完成，检查总节点>50 |
| 规模泛化 Phase B | `phase_scale_n1_to_3` | 节点预算>50且热力学许可成立 |


## 二、各个阶段的判定标准

### 阶段1：ν数据积累

**启动条件**：当前状态（ν探针已实现）

**执行操作**：
- 运行NuProbe最小实现（烟雾测试）
- 确认6/6 PASS
- 确认ν数据在>10k步内稳定（系统ν波动<50%）
- 记录各bundle的ν贡献排名

**推进条件**：
- `system_ν_ema` 有限（非NaN），且>0（充电态）
- `charging_fraction > 50%`（半数以上bundle处于充电态）
- 回归测试21/21 PASS

**提交消息**：`AUTO: nu_accumulation PASSED`

### 阶段2：双热源长程验证

**启动条件**：ν数据积累通过

**执行操作**：
- 运行`exp_dual_source_long_run.py`（300k步，已预写）
- 集成NuProbe，记录ν轨迹
- 记录方向权重wR-wL

**推进条件**：
- `wR-wL > 0.005`（方向正确）
- `dist_reduction > 1.0`（接近热源）
- `DR5 > 50%`（热对齐）
- `fill_min > 0.05`（能量生存）
- 21/21 PASS

**提交消息**：`AUTO: dual_source_long PASSED`

### 阶段3：V2.0触发条件评估

**启动条件**：双热源长程验证通过

**执行操作**：
- 读取NuProbe数据，计算ν混淆度
- 检查TSI fill轨迹
- 记录节点预算状态

**判定逻辑**：

```
if ν_confusion > 0.30 OR tsi_fill_drop > 0.20:
    trigger_status = "SATISFIED"
else:
    trigger_status = "NOT_SATISFIED"
```

**推进条件**：`trigger_status == "SATISFIED"`

**提交消息**：`AUTO: v2_trigger_<SATISFIED|NOT_SATISFIED>`

### 阶段4：V2.0地址系统构建

**启动条件**：V2.0触发条件评估为SATISFIED

**执行操作**：
- 执行VestibularChainV3重构（地址化内部链路）
- 运行21/21回归测试
- 运行Phase 8 6/6 DR验证

**推进条件**：
- 21/21 PASS
- Phase 8 6/6 PASS
- V2.0完成状态：所有内部链路节点拥有独立地址

**提交消息**：`AUTO: v2_address_build PASSED`

### 阶段5：节点预算扩展评估

**启动条件**：V2.0地址系统构建完成

**执行操作**：
- 统计当前总节点数
- 评估是否可扩展至>50

**判定逻辑**：

```
if total_nodes > 50:
    expansion_status = "ELIGIBLE"
else:
    expansion_status = "INELIGIBLE"
```

**推进条件**：`expansion_status == "ELIGIBLE"`

**提交消息**：`AUTO: node_expansion_<ELIGIBLE|INELIGIBLE>`

### 阶段6：规模泛化 Phase B（N=1→3）

**启动条件**：节点预算扩展为ELIGIBLE 且 热力学许可成立

**执行操作**：
- 扩展每轴Aff数量从2→6（reg×3 + irr×3）
- 分配阈值多样性（0.8×/1.0×/1.2×）
- 验证21/21 PASS
- 验证500k长程方向学习保持

**推进条件**：
- 21/21 PASS
- 500k长程 wR-wL > 0.005
- 热力学许可 $P_{estimated}(3) ≤ P_{input\_max} × 0.8$

**提交消息**：`AUTO: scale_n1_to_3 PASSED`

## 三、Auto-Run执行机制

### 检查点间隔

| 阶段 | 检查间隔 | 最大等待时间 |
| :--- | :--- | :--- |
| ν数据积累 | 每1000步 | 100k步 |
| 双热源长程验证 | 每10k步 | 500k步 |
| V2.0触发评估 | 单次 | — |
| V2.0构建 | 每个模块 | — |
| 节点预算评估 | 单次 | — |
| 规模泛化 | 每个子阶段 | — |

### 故障处理

| 故障类型 | 处理方式 |
| :--- | :--- |
| 阶段超时 | 停机，写入`AUTO_FAIL_<阶段名>_<时间>.log` |
| 回归测试失败 | 停机，不提交 |
| 数值异常（NaN/Inf）| 停机，写入诊断数据 |
| 磁盘空间不足 | 停机，清理旧日志后重试一次 |

### 日志记录要求

每个阶段必须输出以下文件：

```
auto_run/
├── current_stage.txt          # 当前阶段名
├── stage_progress.json        # 各阶段进度数据
├── failure_logs/              # 故障日志
│   └── AUTO_FAIL_<stage>_<timestamp>.log
├── checkpoints/               # 各阶段完成记录
│   └── AUTO_CHECKPOINT_<stage>_<timestamp>.json
└── commits.log                # 自动提交历史
```

### 启动命令

```bash
# 从当前状态启动
python -m nexus_v1.auto_run --start-from current

# 从指定阶段启动（调试）
python -m nexus_v1.auto_run --start-from nu_accumulation

# 重置Auto-Run状态
python -m nexus_v1.auto_run --reset
```

## 四、自动化运行的安全边界与退出条件

### 4.1 自动执行的硬边界

Auto-Run能够自动推进的范围限于**已被本协议明确定义且验收标准已量化的阶段**。对于以下情况，系统将自动进入Stop模式并等待你做出判断：

- V2.0构建完成后，是否需要立即启动节点预算扩展，还是先运行其他实验
- 规模泛化Phase B完成后，是否需要继续推进Phase C，还是先验证长期稳定性
- 如果V2.0触发条件始终未满足（ν混淆度<30%且TSI fill稳定），Auto-Run将在完成300k双热源实验后自动停止，等待你决定：继续优化当前架构，还是人为启动V2.0

### 4.2 自动停止条件

Auto-Run在以下任一条件下自动停止，不自动推进任何后续阶段：

1. 阶段成功完成但下一阶段不在本协议范围内
2. 达到你预设的最大总步数上限（当前设置为1.5M步）
3. 连续3次commit失败
4. 节点预算评估为INELIGIBLE（当前总节点≤50）时，停止并等待人工评估是否需要扩展节点预算

### 4.3 手动干预通道

在任何Auto-Run运行期间，以下操作将立即中断自动执行：

- 任何`KeyboardInterrupt`（Ctrl+C）
- 检测到`AUTO_INTERRUPT`文件存在
- 手动运行`python -m nexus_v1.auto_run --stop`

中断后，当前阶段的结果将被保存，状态标记为`INTERRUPTED`。你可以通过`--resume`命令从检查点恢复，或通过`--reset`完全重置后手动调整参数再重新启动。
