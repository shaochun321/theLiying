因为你们这几轮修复的目的正是避免：

# 下一步不是 P2-B1X2

应先增加一个很小的收口：

[
\boxed{\text{P2-B1X1d：确定性真实顺序场景闭合}}
]

它不需要修改核心关系机制，只需要建立一个受控但仍经过真实物理通路的输入场景。

## 场景要求

不能同时 boosted 两个站点，而应明确制造：

[
A
\xrightarrow{\Delta t}
B.
]

例如：

1. 先只驱动站点 A；
2. 确认 A 的 D1 `t_up` 已出现；
3. 在 fast trace 尚有效时驱动 B；
4. 让 B 产生自己的 D1 occurrence；
5. 观察真实 relation collector 上升沿；
6. 自动创建 `RelationDraft`；
7. 等 A、B occurrence 完成并登记 registry；
8. 自动生成正式 `RelationOccurrence`。

整个过程仍必须经过：

[
\text{world/body}
\rightarrow
L1
\rightarrow
HC
\rightarrow
ensemble
\rightarrow
collector
\rightarrow
tap
\rightarrow
relation collector.
]

不能直接写入：

* collector；
* pre_trace；
* epoch id；
* draft 父地址。

# P2-B1X1d 的三个测试

## T-RLI-E2E-1：真实顺序闭合

明确输入 (A\prec B)，最终必须得到一个：

[
\rho_{A_i\prec B_j}^{(2)}.
]

并检查它的两个父实例正是本轮真实 occurrence。

## T-RLI-E2E-2：反向输入

输入：

[
B\prec A.
]

不得生成：

[
\rho_{A\prec B}.
]

可以生成反向观察候选，也可以暂时无合格关系，取决于当前反向 collector 是否已有接口，但不能误报正向关系。

## T-RLI-E2E-3：DA独立

对同一顺序场景分别设置：

[
DA=0,\qquad DA>0.
]

两者都生成相同父谱系的观察关系：

[
\rho^{\rm obs}.
]

只有 eligibility 或权重沉积结果允许不同。

这应保留到后面的尺度算子资格阶段。

# 另一个非阻塞限制：X1c的类定义与动力资格仍需区分

`RelationOccurrence` 的生成证明：

> 一次观察关系获得了身份和谱系。

它还不等于：

> 这条关系产生了不可约物理作用。

后者仍应由 P2-B1X2 的四条件与切割测试验证。

所以正确顺序是：

}
]
