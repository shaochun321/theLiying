[
\boxed{
\omega_n[W]
\longrightarrow
\mathfrak C_{\omega_n}[W]

### 外部发生过程—内部生成活动云映射

对于模态 (m) 在物理窗口 (W) 内的一次外部发生过程

[
\omega_m[W]\in\Gamma(\mathcal P_m,W),
]

定义窗口化过程映射算子

[
\mathcal M_{m,\alpha}[W]:
\omega_m[W]
\rightharpoonup
\mathfrak C_{\alpha,\omega}[W].
]

其中：

* (\omega_m[W]) 是外部物理支撑在窗口 (W) 内的真实演化过程；
* (\mathcal M_{m,\alpha}[W]) 由换能边界、基础生成元内部动力学和输出边界共同构成；
* (\mathfrak C_{\alpha,\omega}[W]) 是该外部发生过程中实际形成的地址化内部生成活动云；
* (\rightharpoonup) 表示该算子是部分定义的：并非任意外部扰动都会形成有效生成活动云。

展开后：

[
\mathcal M_{m,\alpha}[W]
========================

\mathcal O_\alpha
\circ
\Phi_{\alpha,W}
\circ
\mathcal T_{\alpha}^{(m)}.
]

即：

[
\boxed{
\text{外部发生过程}
\xrightarrow{\mathcal T}
\text{合法输入过程}
\xrightarrow{\Phi}
\text{内部生成活动过程}
\xrightarrow{\mathcal O}
\text{地址化生成活动云}.
}
]

这里的“映射”不是把外部位置、数值或语义标签复制到内部，而是由具体物理结构在有限窗口中执行的一次过程转换。

因此：

[
\mathfrak C_{\alpha,\omega}[W]
==============================

\mathcal M_{m,\alpha}[W]
\bigl(
\omega_m[W];
x_\alpha(t_0),\vartheta_\alpha
\bigr),
]

它同时依赖：

* 外部发生的完整轨迹；
* 基础生成元的初始内部状态；
* 生成元的物理参数；
* 作用窗口；
* 局部耦合与历史残留。

所以它通常是历史依赖、多对一且局部不可逆的过程映射，而不是静态函数表。

生成元激活也不再定义为一个静态布尔标签，而定义为：

[
\operatorname{Act}*{\mathcal G*\alpha}
\bigl(\omega_m[W]\bigr)
=======================

\begin{cases}
1,
&
\mathfrak C_{\alpha,\omega}[W]
\text{满足生成元的结构闭合与输出条件},[4pt]
0,
&
\text{否则}.
\end{cases}
]

更严格地说，激活本身也是一个过程量：

[
A_\alpha[W]
===========

\mathcal A_\alpha
\bigl(
\mathfrak C_{\alpha,\omega}[W]
\bigr),
]

它可以包含进入、维持、衰减与退出，而不是只记录一次瞬时越阈。

由此，项目主线可以写成：

[
\boxed{
\text{外部发生过程}
\rightarrow
\text{内部生成活动云}
\rightarrow
\text{时间／空间／尺度生成算子}
\rightarrow
\text{耦合生成元}.
}
]

其中每一步都是有物理载体、有作用窗口、有输入输出边界的算子作用，不依赖静态语义标签。

对应地，GeneratorActivationCloud不应被解释为“外部世界的内部表示”，而应解释为：

外部发生过程经过基础生成算子后形成的内部过程结构。
	​


TSS-A0也可以改称：

外部发生过程—内部生成活动云映射契约

后续运行时闭合阶段则称：

外部发生过程—内部生成活动云映射实例化

这样比“物理支撑—地址—活动云桥接层”更符合项目的过程本体，也避免把地址、活动云或生成元冻结为静态对象。
