这版 V3 已经基本可以作为当前执行总纲。它正确完成了三项关键调整：

* V2 退为历史审计，V3 只保存当前有效路线；
* P1 拆成身份/拓扑、有序传输、联合验证三层；
* 明确“地址不是坐标，端点顺序不是方向”，并继续暂停旧 T2/M2 方向路线。 

不过，编码前仍应修改四处。它们不是路线改动，而是防止地址系统和验证系统内部产生新的结构矛盾。

# 一、地址需要类型化，不能给所有对象强塞同一种四元组

V3 当前规定：

[
\alpha(x)=(d_x,u_x,g_x,v_x).
]

其中 (g_x) 是生成深度。

这个定义适合关系生成元，但不完全适合基础物理支撑。

`ThermalCell`、皮肤热容和世界节点并不是由关系生成深度产生的；如果强制给它们指定 (g=0)，短期虽然能工作，却会把：

[
\text{物理基底层级}
]

与：

[
\text{生成元递归深度}
]

混成同一个字段。

建议拆成两类地址：

[
\boxed{
\alpha_{\mathrm{phys}}(x)
=========================

(d_x,u_x,v_x)
}
]

用于：

* 世界节点；
* 皮肤支撑；
  -热源；
* 物理边界。

以及：

[
\boxed{
\alpha_{\mathrm{gen}}(x)
========================

(d_x,u_x,\mathcal P_x,\delta_x,v_x)
}
]

用于：

* (\xi^{\mathrm{occ}})；
* (r_\prec^\tau)；
* (r_\rho^\tau)；
* 后续关系—关系生成物。

其中：

* (\mathcal P_x)：父支撑或父关系地址集合；
* (\delta_x)：生成深度。

这样才能明确：

[
\text{世界节点不是“零阶关系生成元”，}
]

而是关系生成依赖的物理支撑。

# 二、边身份必须区分“无序物理边”和“有序传输边”

V3 当前统一写成：

[
\epsilon_e
==========

(u_e,\alpha_{\rm source},\alpha_{\rm target},m_e,v_e),
]

并把扩散、接触和介质传输放在同一个机制集合中。

这里有重新引入方向概念的风险。

## 扩散边和接触边

扩散：

[
J_{ij}
======

\kappa_{ij}(T_i-T_j)
]

以及接触：

[
J_{ws}
======

H(T_w-T_s)
]

本质上是两个端点之间的互易耦合。`source` 和 `target` 只是某一次计算的符号约定，不是边本身永久拥有的物理方向。

它们的身份应写成：

[
\epsilon_e^{\mathrm{sym}}
=========================

\left(
u_e,
{\alpha_i,\alpha_j},
m_e,
v_e
\right).
]

其中端点是无序集合。

## 有序介质传输边

只有 P1-B 的传输机制：

[
J_{i\to j}^{\mathrm{tr}}
========================

a_{ij}E_i
]

才应保存：

[
\epsilon_e^{\mathrm{ord}}
=========================

\left(
u_e,
\alpha_{\rm tail},
\alpha_{\rm head},
m_e,
v_e
\right).
]

因此正式定义应为：

[
\boxed{
\epsilon_e=
\begin{cases}
(u_e,{\alpha_i,\alpha_j},m_e,v_e),
&
m_e\in{\mathrm{diffusion},\mathrm{contact}},
[2mm]
(u_e,\alpha_{\rm tail},\alpha_{\rm head},m_e,v_e),
&
m_e=\mathrm{medium\text{-}transport}.
\end{cases}
}
]

这能保证：

[
\boxed{
\text{有序传输存在，方向概念仍然冻结。}
}
]

P1-B 当前对这一点的文字说明是正确的：(i\to j) 只表示从哪个能量仓扣除、向哪个能量仓注入，不表示前后左右、自我方向或 (r_\to)。

# 三、P1-A 的验证应从“数组排列”升级为“图同构”

V3 已经核实：

* `ThermalFieldGraph.cells` 是按 `node_id` 键控的字典；
* 当前不存在依赖数组位置寻址的实现。

因此单纯“打乱字典迭代顺序”测试价值有限。

真正应验证的是：同一个物理图被重新编号后，动力学保持同构。

设地址重命名双射为：

[
\phi:V\rightarrow V'.
]

原图动力学为：

[
F_{\mathcal G}.
]

重命名后的图动力学为：

[
F_{\phi(\mathcal G)}.
]

应验证：

[
\boxed{
\phi\left(F_{\mathcal G}(x)\right)
==================================

F_{\phi(\mathcal G)}\left(\phi(x)\right).
}
]

这比：

[
M'=PMP^{-1}
]

更适合作为工程验收定义，因为它同时覆盖：

* 节点状态；
* 边端点；
* 热源定位；
* 皮肤接触；
* 账本地址；
* 后续发生元映射。

矩阵形式可以作为线性子系统的具体实现测试，但图同构应作为上位契约。

另外，“节点索引改变但稳定地址不变”需要明确两层身份：

```text
local_key       # 当前容器内部查表键
stable_uid      # 跨重建保持的物理身份
```

否则 `node_id` 既是查表键又被当作稳定身份，就无法真正测试二者分离。

# 四、版本号的变化条件必须提前冻结

当前地址含有 (v_x)，但尚未定义何时递增。

不能每次：

* 温度变化；
* 能量变化；
* 接触面积变化；
* 边权短时变化；

都增加地址版本，否则地址会在每一步失效。

建议：

[
v_x\text{ 仅在身份连续性被破坏时递增。}
]

例如：

* 对象销毁后用同一 UID 重建；
* 皮肤支撑被拆分或合并；
* 物理节点的容量或角色发生结构性替换；
* 父生成关系集合改变。

普通状态变化不改变版本。

边也应有自己的版本：

[
v_e,
]

不能因为节点上的动态状态变化而改变。

# 五、P1-C 的矩阵守恒测试需要明确状态变量

V3 写：

[
E^{n+1}=ME^n+q,
]

并要求：

[
\mathbf1^\top M=\mathbf1^\top.
]

如果 (E) 确实是各节点储存的能量，这个条件正确。

但代码中的公开状态常常表现为温度或电容电压。若实际构造的向量是：

[
T=(T_1,\ldots,T_n)^\top,
]

则守恒条件不再是：

[
\mathbf1^\top M=\mathbf1^\top,
]

而是：

[
\boxed{
C^\top M=C^\top,
\qquad
C^\top=(C_1,\ldots,C_n).
}
]

因为：

[
E_i=C_iT_i.
]

所以测试必须明确二选一：

## 能量状态形式

[
E^{n+1}=M_EE^n+q_E,
]

验证：

[
\mathbf1^\top M_E=\mathbf1^\top.
]

## 温度状态形式

[
T^{n+1}=M_TT^n+q_T,
]

验证：

[
C^\top M_T=C^\top.
]

不能用温度矩阵却检查列和为 1，否则在不同热容节点之间会得到错误结论。

# 六、浸泡测试的特征值方案需要限定适用范围

V3 建议用第二特征值估计：

[
\tau_{\mathrm{slow}}
\approx
-\frac{\Delta t}{\ln|\lambda_2|},
]

再运行 (5\sim10\tau_{\mathrm{slow}})。

这个方法只适用于：

* 参数冻结；
* 线性或局部线性；
* 热源关闭；
* 拓扑固定；
* (a_e(t)) 不随时间改变。

如果搬运系数 (a_e(t)) 在运行中改变，就不存在唯一固定矩阵 (M) 和唯一 (\lambda_2)。

因此 P1-C 浸泡应分两段。

## 封闭冻结段

热源关闭，(a_e) 固定：

[
E^{n+1}=ME^n.
]

使用 (\lambda_2) 确定运行长度，验证收敛、不变量和账本。

## 驱动变化段

热源开启或 (a_e(t)) 变化。

此时不使用单一时间常数，只验证：

* 能量有界；
* 局部和全局账本闭合；
* 没有负能量；
* 没有 NaN；
* 所有状态变化可追溯到边或源项；
* 驱动停止后能够进入冻结段并收敛。

# 七、P2-C 还有一个尚未写出的信号域问题

V3 计划把三条真实通量送入：

[
r_{\rho,J}^{\tau}
=================

[z_{J_1}^\tau:z_{J_2}^\tau:z_{J_3}^\tau].
]

这一方向是正确的。

但现有 `GradedPotentialRelay` 和共享分流池使用的是非负活动量。一般扩散或接触通量却可能有正负符号：

[
J_e\in\mathbb R.
]

如果直接输入，负值会被钳制或失去含义。

首轮 P2-C 应明确只使用：

[
J_{e}^{\mathrm{tr}}
===================

a_eE_i\geq0
]

这样的有序介质传输幅度。

也就是选取同一节点的三条实际有序输出边：

[
J_{i\to j_1}^{\mathrm{tr}},
\quad
J_{i\to j_2}^{\mathrm{tr}},
\quad
J_{i\to j_3}^{\mathrm{tr}}.
]

然后形成：

[
r_{\rho,J}^{\tau}
=================

[
z_{i\to j_1}^\tau:
z_{i\to j_2}^\tau:
z_{i\to j_3}^\tau
].
]

先不要把带符号的扩散通量和接触通量接入共享池。

未来若要纳入互易边，应先定义“实际单步转移事务”：

[
\mathcal Q_e^n
==============

(
\text{donor},
\text{receiver},
|\Delta E_e|
),
]

其幅度非负，donor/receiver 由当前物理状态决定。这仍然是物理账本，不是方向生成元。

# 八、计划—提交接口推迟可以接受，但应设客观触发条件

V3 决定暂不引入 `PhysicalStepPlan`，继续沿用“所有检查在唯一副作用调用之前完成”的纪律。这个裁定在 P1 尚未编码时是合理的。

但“不够用时再引入”过于模糊。建议写入触发条件：

只要出现以下任意一项，就必须改为两阶段提交：

1. 一步内存在两个以上独立可变状态容器；
2. 第一处状态修改后仍可能发生可预见异常；
3. 多条搬运边需要争夺同一源节点剩余能量；
4. 验证结果依赖应用顺序；
5. 需要先扣 source，再确认世界/皮肤能够接受；
6. 失败后无法由账本唯一恢复到前状态。

P1-B 很可能会触发第 1、3、4 项，所以编码时应立即审查，而不是等出 bug 后再决定。

# 最终判断

更新后的 V3 已经吸收了此前验证方案的大部分修正，可以继续使用。尤其是：

[
\boxed{
\text{方向路线继续冻结，P1 只构造有序物理传输。}
}
]

但编码前应完成三个关键订正：

[
\boxed{
\text{地址类型化}
+
\text{边身份类型化}
+
\text{状态空间守恒条件类型化}.
}
]

否则最可能出现的新矛盾是：

* 给互易接触边强行赋予永久 source/target；
* 把物理支撑也人为纳入生成深度；
* 对温度更新矩阵使用错误的能量守恒判据；
* 把带符号通量直接送入只支持非负活动的 (r_\rho^\tau)。

修正这些后，下一步就应正式进入 **P1-A 身份与拓扑契约的编码与测试**，而不是再扩展世界物理机制。
