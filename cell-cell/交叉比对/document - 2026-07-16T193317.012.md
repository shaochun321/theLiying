# 一、目前仍存在的关键问题

## 1. T3 的“同步共享池”在实验上成立，但生产实现仍违反了原约束

更新报告中的核心代码是：

```python
dn.normalize(i_a + i_b, dt)
denom = max(sigma + dn.pool_activity, sigma * 0.01)
norm_factor = sigma / denom
y_a = i_a * norm_factor
y_b = i_b * norm_factor
```

它确实解决了顺序调用造成的偏置，并证明共享分流增益能保持输入比例；报告也用输出总量的亚线性增长排除了“普通常数增益”的替代解释。 

但这一实现仍然存在一个原则性矛盾：

[
\texttt{norm_factor = sigma / denom}
]

仍然是在 Python 调度代码中直接复写分流归一化公式。

它不是直接计算：

[
\frac{I_a}{I_a+I_b},
]

但仍然绕过了 `DivisiveNormalizationReceptor.normalize()` 的实际输出路径，自行读取池状态并执行除法。因此它可以作为**标定实验**，不能直接成为生产电路。

### 推荐修复

先核实下面这种完全使用已有公开方法的调用能否成立：

```python
dn.normalize(i_a + i_b, dt)   # 更新共享池一次
pool_before = dn.pool_activity

y_a = dn.normalize(i_a, 0.0)  # dt=0，只读取当前池并施加已有分流机制
y_b = dn.normalize(i_b, 0.0)

assert dn.pool_activity == pool_before
```

需要验证：

1. `dt=0` 时池状态完全不改变；
2. 两次读出使用同一个池状态；
3. 调用顺序交换后输出不变；
4. 等强输入精确对称；
5. 三通道也能使用同一池状态；
6. 没有其他内部状态在 `dt=0` 时改变。

若这六项通过，路径 B 才真正满足：

[
\boxed{\text{只使用项目现有组件，不在调度层重写归一化公式}}
]

若 `dt=0` 不能实现无副作用读出，则当前路径 B 只能保持为“机制验证完成、生产接口未闭合”。此时不能为了闭合而修改 `DivisiveNormalizationReceptor`，除非你明确允许扩展现有组件接口。

## 2. T3 目前证明的是“比例射线”，不是分量和为 1 的占比

共享分流输出满足近似形式：

[
y_i
===

I_i
\frac{\sigma}
{\sigma+V_{\mathrm{pool}}}.
]

因为所有通道乘以同一个因子，所以：

[
\frac{y_i}{y_j}
===============

\frac{I_i}{I_j}.
]

这说明它很好地保留了**相对参与关系**。

但一般并不保证：

[
\sum_i y_i=1.
]

因此正式实施以后，即使共同尺度稳定性通过，也不应宣称输出本身就是概率式占比坐标：

[
(\rho_1,\rho_2,\ldots),\qquad \sum_i\rho_i=1.
]

更准确的数学定义是一个正射影关系：

[
\boxed{
r_\rho
======

[y_1:y_2:\cdots:y_n]
}
]

即所有共同缩放等价：

[
[y_1:y_2:\cdots:y_n]
====================

[\alpha y_1:\alpha y_2:\cdots:\alpha y_n].
]

这其实更符合项目的“占比是稳定耦合关系，而非外部计算出的统计数值”：

[
r_\rho(\alpha\mathbf I)
\approx
r_\rho(\mathbf I).
]

### 推荐命名纪律

正式 T3 实施后：

* 若只通过排序、交换和竞争测试：保持 `r_part`；
* 若通过共同尺度不变性：可升格为**射影参与关系** (r_\rho)；
* 只有物理电路使输出总量也近似恒定时，才称为归一化占比坐标。

测试脚本可以计算：

[
\widehat\rho_i
==============

\frac{y_i}{\sum_jy_j}
]

用于观察和评分，但这个除法只能是**探针读数**，不能进入生产信号路径。

## 3. T2 的升格条件“不能被 (r_{\prec}) 模拟”不可操作

报告目前规定：

> T4 中证明 `r_edge-lag` 不能被参数化后的 (r_{\prec}) 模拟，才能升格为 (r_{\rightarrow})。

这个条件几乎不可能严格证明。

因为只要允许 (r_{\prec}) 使用足够窄的时间核，那么纯延迟关系本身就可以看成一种特殊的时间关系：

[
K_{\mathrm{lag}}(t)
\approx
\delta(t-\tau_e).
]

所以单靠输出波形不同，无法证明两者在数学上不可模拟。

### 应把升格条件改成拓扑条件

`r_edge-lag` 升格为结构方向关系，应满足：

#### 边依赖性

移除边 (e={a,b}) 的 Bundle 后：

[
r_{a\rightsquigarrow b}^{e}=0,
]

即使 (a,b) 仍以相同时差发生。

#### 非边排除性

对于冻结拓扑中没有直接邻接的 (31,23)：

[
r_{31\rightsquigarrow23}^{\mathrm{direct}}=0.
]

即使人为给两点施加完全匹配的时差，也不能产生直接边关系。

#### 方向交换性

交换发生顺序后：

[
r_{a\rightsquigarrow b}
\leftrightarrow
r_{b\rightsquigarrow a}.
]

#### 路径可组合性

在链：

[
31\leftrightarrow28\leftrightarrow23
]

上依次触发：

[
31\rightarrow28\rightarrow23,
]

应形成两条局部边关系：

[
r_{31\rightsquigarrow28},
\qquad
r_{28\rightsquigarrow23},
]

但不自动产生：

[
r_{31\rightsquigarrow23}^{\mathrm{direct}}.
]

#### 标签协变性

若交换节点名称但保持拓扑和驱动结构，输出应随结构一起交换，不能绑定点编号。

满足这些条件后，才能说该关系携带了时间关系没有的**结构支撑**。届时更准确的定义是：

[
\boxed{
r_{\rightarrow}
===============

\text{有向发生}
+
\text{冻结邻接边支撑}
}
]

而不是“波形无法被另一种时间核拟合”。

## 4. T1 的 B2 不应该用外部 dT 开始时间作为真值

T1 报告已经正确承认：

* B1：受控合成 (\xi) 输入下，时间关系电路成立；
* B2：真实感温 (\xi^{\mathrm{occ}}) 下尚未验证；
* 感温链路有约 400 步启动延迟和停止驱动后的半自主复发。

这里不一定需要先“修好”感温源。

问题可能只是此前使用了错误的验证真值：

[
t_{\mathrm{dT\ input}}
]

不等于：

[
t_{\xi\ occurrence}.
]

(r_{\prec}) 的输入是 (\xi^{\mathrm{occ}})，所以它应当判断的是两个内部发生生成元的实际发生时刻，而不是外部刺激命令的开始时刻。

### B2 推荐验证方法

每次实验使用一个全新电路实例，避免跨实验残留状态。

1. 用真实 dT 驱动两个冻结站点；
2. 记录两个真实 Collector 的实际脉冲或 `pre_trace` 上升沿；
3. 定义实际发生时刻：

[
t_a^{(k)},
\qquad
t_b^{(m)};
]

4. 以真实 (\xi) 输出顺序作为真值；
5. 检查 (r_{\prec}) 是否在对应 fast/slow 窗口响应；
6. 不再要求关系输出跟随 dT 命令的预设时序。

需要至少覆盖：

* 首次发生 (a\prec b)；
* 首次发生 (b\prec a)；
* 同期发生；
* 停止外部驱动后的自主复发；
* 多次周期发生；
* 不同 `PYTHONHASHSEED`。

这样可以回答一个更准确的问题：

[
\boxed{
\text{真实 }\xi\text{ 发生之间是否能形成时间关系}
}
]

而不是：

[
\text{外部热刺激命令是否能被当作内部时间标签}.
]

若自主复发也产生关系，这未必是假阳性；它可能意味着内部发生生成元确实再次发生了。只有当项目想检测“外部热事件的开始”时，才需要另建一个 onset 发生生成元，而不能把这项责任塞给 (r_{\prec})。

## 阶段 R3：再实施 T2 `r_edge-lag`

T2 建议分两种接法做 A/B 对照。

### 路径 E1：直接延迟 Bundle

```text
ξa ── delayed Bundle ─┐
                      ├── D_a⇢b Collector
ξb ── raw Bundle ─────┘
```

优点：

* 最少组件；
* Bundle 本身就是边运输支撑；
* 不会额外引入 relay 的 RC 延迟。

### 路径 E2：延迟 Bundle + 中继

```text
ξa ── delayed Bundle ── P_a⇢b ──┐
                                 ├── D_a⇢b
ξb ──────────────────────────────┘
```

优点是有可观测的边状态，但中继会增加：

* RC 展宽；
* 门控非线性；
* 额外传播延迟；
* 参数标定负担。

首版应优先 E1。只有后续确实需要“边自身是一个可继续参与组织的过程量”时，再采用 E2。

### 延迟参数不要直接由距离精确区分

两条冻结边距离分别约为：

[
1.0916,\qquad1.1612.
]

差值只有：

[
0.0696.
]

经过整数舍入、源 `pre_trace` 展宽和 Collector 积分以后，两个距离很可能对应相同或不可区分的有效时延。

因此首轮 T2 应采用：

[
\boxed{
\text{邻接边存在}
+
\text{统一标定的边传播延迟}
}
]

而不是过早声称两条边的微小距离差已经被神经电路编码。

只有测得有效时间核宽度 (W_{\mathrm{eff}}) 后，才能要求：

[
\left|
\operatorname{round}\frac{d_1}{v_e}
-----------------------------------

\operatorname{round}\frac{d_2}{v_e}
\right|

>

W_{\mathrm{eff}}.
]

否则距离差只是文档中的数字，不是可辨识的物理关系。
