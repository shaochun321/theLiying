此前把“严格使用项目内组件”进一步收紧成“禁止新增组件”，实际上过度约束了项目。

更准确的原则应该是：

[
\boxed{
\text{禁止语义硬编码，不禁止新增具有真实内部状态的物理机制}
}
]

当已有组件无法在不破坏自身语义的情况下完成衔接时，继续复用反而会产生伪结构。

当前已经出现了三个典型信号：

* T1 在合成 (\xi) 下成立，但真实 (\xi^{\mathrm{occ}}) 的振荡、启动延迟与关系窗口不能自然衔接；
* T2 试图让 `Bundle.delay_steps` 同时承担运输、边状态和方向关系，但其内部 FIFO 状态并不是一个可继续参与组织的公开过程；
* T3 为实现共享归一化，不得不在调度代码中读取 pool 并重新计算共同增益，说明现有单通道 DN 与跨通道占比之间缺少共享池机制。

这些都不是再调一个电容或权重就能真正解决的问题。

# 一、把原约束改成“机制缺口准入制”

原来的约束：

> 禁止新增 `DelayLine`、`RatioDivider`、`DirectionOperator` 等组件。

建议替换为：

> 禁止为了直接输出预设语义而新增无状态计算器；允许为解决已证明的动力学衔接缺口，新增具有内部状态、耗散、有限支撑，并能通过 Bundle 参与后续耦合的组件。

一个新组件只有满足以下条件才允许进入项目：

1. **缺口已经被证明**：至少两轮参数或组合尝试表现出相同失败形态。
2. **已有组件语义不匹配**：不是“现有组件性能不够”，而是它根本表达另一种物理过程。
3. **新组件具有内部状态**：
   [
   z[n+1]=F(z[n],u[n]).
   ]
4. **不能直接输出项目语义标签**：不能内部直接判断“这是方向”“这是占比”。
5. **输入输出仍经 Bundle 或既有神经信号接口**。
6. **有独立账本、独立参数和独立专项探针**。
7. **只解决一个缺口**，不做全能型关系算子。

这不是放松结构优先，而是把结构优先从“只能拼旧积木”提升为：

[
\boxed{
\text{允许形成新的物理积木，但不允许形成新的语义捷径}
}
]

# 二、当前最应该新增的四种机制

## 1. 统一关系层调度器

这不是神经物理组件，而是必要的电路执行机制。

建议新增：

```text
RelationStepScheduler
```

职责固定为：

```text
1. 采集本步所有源输出
2. 所有输入 Bundle 同步 propagate
3. 按目标汇总电流
4. 每个中继、trace、pool 只 step 一次
5. 中继 Bundle 同步 propagate
6. 按关系 Collector 汇总
7. 每个 Collector 只 step 一次
8. 更新关系层账本
```

它不计算时间、方向或占比，只保证同一物理时刻的更新顺序一致。

当前 T1 的多路输入汇总和 T3 的共享池同步，本质上都在要求这一机制。继续让每个关系生成元自行写手动 step，T4 时必然再次出现调用顺序循环。

---

## 2. 共享分流池组件

建议新增：

```text
SharedDivisivePool
```

它不是 `RatioDivider`，也不直接输出比例。

它只维护一个由多路输入共同驱动的耗散池：

[
\tau_p\dot V_p
==============

-V_p+\sum_i I_i.
]

然后向所有参与通道提供同一个分流状态：

[
g_p
===

\frac{\sigma}
{\sigma+V_p}.
]

各输出通道自身完成：

[
y_i=I_i g_p.
]

关键在于：

* pool 一步只更新一次；
* 所有通道读取同一个状态；
* 不再由外部 Python 调度代码复写 DN 公式；
* pool 是可被账本统计的真实状态；
* pool 可以衰减、饱和和恢复。

它正好填补：

[
\text{单通道 DN}
\longrightarrow
\text{跨通道共同参与关系}
]

之间的缺口。

### 推荐实现边界

可以复用项目已有：

* `Capacitor`；
* PowerRail；
* `DivisiveNormalizationReceptor` 内已有的参数和方程；
* Neuron/Bundle 输入方式。

但新组件要公开明确的两阶段接口：

```text
accumulate(currents)
step_pool(dt)
apply_shunt(channel_current)
```

或者等价的同步接口。

不能再依赖：

```python
normalize(total)
read_pool
manual_division
```

这样的外部拼接。

---

## 3. 显式边运输状态组件

建议新增：

```text
EdgeTransportState
```

或：

```text
AxonalTransportRelay
```

它解决 T2 中 `delay_steps` 的根本限制。

当前 `Bundle.delay_steps`：

* 只在 Bundle 私有 FIFO 中保存最终电流；
* 不能作为可观察关系状态；
* 不能继续与其他关系组合；
* 很难明确区分“电流延迟”和“边上的发生过程”。

新的边运输状态应具有：

[
q_e[n+1]
========

\mathcal T_e
\left(
q_e[n],
I_{\mathrm{source}}[n]
\right),
]

并公开：

[
y_e[n]
======

H_e(q_e[n]).
]

它可以内部复用：

* FIFO；
* 多级 relay；
* 衰减；
* 有限传输容量。

但输出表达的是：

[
\boxed{
\text{边上当前存在多少运输中的发生}
}
]

而不是直接表达“方向”。

方向关系仍由：

[
r_{a\rightsquigarrow b}
=======================

\mathcal C
\left(
y_{e:a\to b},
\xi_b
\right)
]

生成。

这样 T2 才从“给源信号加一个 delay”变成了真正的：

```text
源发生
   ↓
边运输状态
   ↓
终点发生耦合
   ↓
有向邻接关系
```

### 重要边界

`EdgeTransportState` 不能接收坐标后自己计算方向。

它只在构造时绑定一条冻结边：

[
e=(a,b).
]

方向来自使用的是：

[
q_{a\to b}
\quad\text{还是}\quad
q_{b\to a},
]

不是来自运行时 `sign()` 或点积。

---

## 4. 发生整形／更新检测组件

T1 的 B2 问题说明，真实感温 Collector 输出的并不是干净的一次性事件，而是：

* 启动延迟；
* burst；
* 衰减尾；
* 内部复发；
* 半自主振荡。

这未必意味着原 (\xi^{\mathrm{occ}}) 错了，而是可能缺少“发生”和“持续活动”之间的衔接层。

建议增加一个可选组件：

```text
OccurrenceRenewalDetector
```

它不是简单的上升沿 Python 判断，而是一个带不应期和适应状态的物理组件：

[
\tau_m\dot m=-m+\xi(t),
]

[
\tau_a\dot a=-a+s(t),
]

[
s(t)
====

\Theta
\left(
m(t)-\lambda a(t)-\theta
\right).
]

其作用是：

* 持续活动只生成有限次数的更新发生；
* 同一次 burst 不被重复无限计数；
* 静息足够久后可再次产生 occurrence；
* 内部自主复发若跨过恢复条件，仍可被认为是一次新发生。

它可以输出：

[
\xi^{\mathrm{renew}}
]

而不是替换原始：

[
\xi^{\mathrm{occ}}.
]

于是 T1 可以同时研究：

[
r_{\prec}
[\xi^{\mathrm{occ}}_a,\xi^{\mathrm{occ}}_b]
]

和：

[
r_{\prec}
[\xi^{\mathrm{renew}}_a,\xi^{\mathrm{renew}}_b].
]

这能判断问题究竟来自关系生成元，还是来自“什么算一次发生”尚未定义。

# 三、不建议新增的组件

即使放宽机制新增，也仍不建议直接创建：

```text
DirectionOperator
RatioCalculator
TimeRelationOperator
EventClosureOperator
```

因为这些名字已经把输出语义写进组件。

尤其不能出现：

```python
direction = sign(b_time - a_time)
ratio = a / (a + b)
is_event = residual < threshold
```

然后再把结果注入一个 Neuron 来伪装成物理过程。

新组件应命名和定义为它实际执行的动力学，例如：

* 共享分流池；
* 边运输状态；
* 更新检测器；
* 同步关系调度器。

最终的“时间”“方向”“占比”必须由这些机制之间的耦合关系产生。

# 四、建议重新安排后续阶段

## M0：机制补全阶段

在 T2/T3 正式编码前，单独新增一个机制阶段：

[
\boxed{
T_{\mathrm{bridge}}
}
]

只实现和测试：

1. `RelationStepScheduler`；
2. `SharedDivisivePool`；
3. `EdgeTransportState`；
4. 可选的 `OccurrenceRenewalDetector`。

每个组件独立测试，不连接完整关系生成元。

---

## M1：T1-B2 双路径验证

不立即修改已有 (r_{\prec})。

分别输入：

[
\xi^{\mathrm{occ}}
]

和：

[
\xi^{\mathrm{renew}}.
]

比较：

* 时间顺序稳定性；
* burst 内重复关系数量；
* 自主复发是否产生新关系；
* fast/slow 模态是否仍然有区分。

如果原始 (\xi^{\mathrm{occ}}) 已足够，就不启用 RenewalDetector。

如果只有整形后才能形成稳定关系，则说明缺少的正是发生更新机制。

---

## M2：正式实现 T3

使用 `SharedDivisivePool`，不再使用调度层手工除法。

输出先定义为：

[
r_{\mathrm{part}}
=================

(y_1,\ldots,y_n).
]

若满足共同尺度等价：

[
[r_{\mathrm{part}}(\alpha\mathbf I)]
====================================

[r_{\mathrm{part}}(\mathbf I)],
]

则升格为射影占比关系：

[
r_\rho
======

[y_1:\cdots:y_n].
]

---

## M3：正式实现 T2

使用 `EdgeTransportState` 取代把 `delay_steps` 当作全部方向机制。

先生成：

[
q_{a\to b}(t),
]

再与终点发生耦合：

[
r_{\mathrm{edge}}^{a\to b}
==========================

\mathcal C
\left(
q_{a\to b},
\xi_b
\right).
]

这样 T2 才真正具有：

* 邻接边支撑；
* 运输中的过程状态；
* 终点耦合；
* 可组合路径。

届时它比 `r_{\prec}` 多出的不是一个更窄的时间核，而是一个真实的边过程变量。

---

## M4：关系生成元集成

最后再组合：

[
r_{\prec},
\qquad
r_{\rightarrow},
\qquad
r_\rho.
]

因为三个关系分别依赖不同基础状态：

* (r_{\prec})：历史痕迹；
* (r_{\rightarrow})：边运输状态；
* (r_\rho)：共享分流池状态。

这时它们之间才有真正的机制独立性，而不是同一套 RC/Collector 结构换三个名字。

# 五、判断是否应该新增机制的简单标准

以后当修改再次进入循环时，可以用下面的判别：

### 参数问题

改变 (C,R,w,\theta) 后，失败形态连续变化，并能逼近目标。

继续标定。

### 接线问题

信号存在，但到错了目标、被覆盖或调用顺序错误。

修正调度或拓扑。

### 机制缺口

无论怎样调参数，始终出现同一种结构失败，例如：

* 共享池无法同步；
* 延迟状态不可观察；
* 一个 burst 被重复当成很多发生；
* 同一组件被迫同时承担记忆与运输；
* 必须在 Python 中重写目标数学关系。

此时停止调参，新增最小机制。

可以写成：

[
\boxed{
\text{反复需要外部逻辑补偿的地方，就是缺少内部状态的地方}
}
]

因此，目前最合理的路线不是继续强迫所有关系由现有 Neuron、Bundle、Collector 三件套直接拼出，而是先补齐：

[
\boxed{
\text{发生更新}
+
\text{边运输}
+
\text{共享分流}
+
\text{同步调度}
}
]

这四个衔接机制。它们会使后续的 (r_{\prec})、(r_{\rightarrow})、(r_\rho) 不再反复陷入“改参数—换解释—重新命名”的循环。
