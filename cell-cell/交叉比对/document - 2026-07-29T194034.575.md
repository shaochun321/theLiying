# 第二份报告需要怎样修正

建议直接做下面五处替换。

## 1. 标题已经正确，正文目标也要改

原文仍写：

> 实现事件元支撑绑定器。

改成：

## 2. 三个类型只保留代码名，不再赋予事件资格

建议改写为：

```text
EventKernelSpec
当前历史命名保留；实际资格为关系谱系候选规格，
不表示事件核已经形成。

当前用于绑定D2关系及其两个D1父发生与结构支撑。

EventInstanceCandidate
当前表示关系谱系材料完整且一致，
```

## 3. “元支撑集合”改成“关系支撑谱系集合”

原式：

[
\mathfrak M_{A\prec B}
======================

{u_A,u_B,T_A,C_{A\prec B},B_\rho,I_{\rho\to DA}}
]

数学对象可以暂时保留，但不应再称作已经成立的事件元支撑。

改称：

[
\boxed{
\mathfrak S_{\rho}^{\rm lineage}
================================

\left{
u_A^{(1)},
u_B^{(1)},
T_A^{\rm fast},
C_{A\prec B},
B_\rho,
Q_{\rm local}^{\rm type}
\right}.
}
]

其中最后一项更准确地写成：

[
Q_{\rm local}^{\rm type},
]

因为当前只有“这种 bundle 类型具有局部作用”的离线资格，还不是每一个关系实例都在线测得了 (I_{\rho}^{\rm local}(t))。

---

其含义仅是：

它不表示真实动力学必要性，也不表示事件连续性。

# P2-C 也需要先避免另一个陷阱

修正报告提出用：

[
\rho_{A\prec B},
\qquad
\rho_{B\prec C}
]

构造关系—关系生成。

但当前工程实际只验证了一个方向和一个时间尺度：

[
\rho_{A\prec B}^{\rm fast}.
]

项目尚未拥有已取得同等级资格的：

[
\rho_{B\prec C}.
]

因此不能马上假装有两条不同关系可组合。

P2-C 前还需要一个非常小的准备动作：

[
\boxed{\text{建立第二条独立、同等级、有完整D2→D1谱系的关系实例。}}
]

这里有两种路线。

### 路线 A：相同关系类型，不同 occurrence 对

例如：

[
\rho_{A_i\prec B_j}^{\rm fast},
\qquad
\rho_{A_m\prec B_n}^{\rm fast}.
]

这能测试“关系实例—关系实例”的组合，但结构丰富度有限。

### 路线 B：新增第三个 D1 来源 C

形成：

[
\rho_{A\prec B}^{\rm fast},
\qquad
\rho_{B\prec C}^{\rm fast}.
]

这更符合真正的关系—关系生成，但会增加新的输入站点、关系 collector 和谱系工作。

对当前项目而言，路线 B 更有理论价值，但不应在文档里默认它已经存在。
