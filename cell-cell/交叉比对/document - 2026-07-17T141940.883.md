## 判断

P1-B0/B1 的**单边代数机制可以通过**：

[
u_i^{n+1}=(1-a\Delta t)u_i^n,\qquad
u_j^{n+1}=u_j^n+a\Delta t,u_i^n
]

已经完成单步解析比对、多步收敛、边级守恒和无隐藏状态验证，且回归无损。

但它还不能整体冻结。B0 中存在两个基础定义问题；在修正前，不应进入多边竞争。

[
\boxed{
\text{B1 算法核条件通过；B0 物理状态定义尚未完全闭合。}
}
]

# 一、最重要的问题：`capacitor.charge` 不是绝对热能

B0 将：

[
u_i=\texttt{ThermalCell.capacitor.charge}
]

定义为“固定零点的绝对能量状态”。

但原世界模型的实际结构是：

[
T_i=T_{ambient,i}+V_i,
]

而电容 charge 对应：

[
q_i=C_iV_i
==========

C_i(T_i-T_{ambient,i}).
]

也就是说，charge 的零点是：

[
T_i=T_{ambient,i},
]

不是热力学绝对零度。原 W1 报告明确写明温度由环境温度与电容电压相加构成，并通过电阻向环境泄漏。

因此它更准确地表示：

[
\boxed{
q_i=\text{相对于局部环境基线的热偏差状态}
}
]

而不是完整热含量。

这会带来一个直接问题：当节点低于环境温度时，

[
q_i<0.
]

现有机制：

[
p_e=a_eq_i
]

会得到负功率，相当于实际转移端点反转；但边身份仍保持原来的 tail/head。这样会破坏：

* 非负有序通量假设；
* tail 是供体、head 是受体的账本语义；
* P2-C 只接受非负有序通量的前提。

B1 的现有测试只证明了正能量区域的递推，没有证明负 charge 情况下的语义。

## 建议修正

现阶段不要把它叫“总热能转移”，而应限定为：

[
\boxed{
\text{高于统一环境基线的有序过剩热量转移}
}
]

定义：

[
u_i^+
=====

\max(q_i,0),
]

[
p_e=a_eu_i^+.
]

这样：

* tail 低于或等于环境基线时不提供过剩热量；
* (p_e\geq0)；
* tail/head 身份保持稳定；
* 仍然使用已有 charge 状态，不必新增介质质量。

相应名称最好改成：

```text
OrderedExcessThermalEnergyLink
```

如果暂时不改类名，至少要把报告语义改成：

> `OrderedThermalEnergyLink` 当前搬运的是统一环境基线以上的规范化过剩热状态，不是节点的完整热力学内能。

还必须加一个前提：

[
T_{ambient,i}=T_{ambient,j}.
]

如果两个节点使用不同环境基线，那么：

[
q_i=C_i(T_i-T_{ambient,i})
]

和：

[
q_j=C_j(T_j-T_{ambient,j})
]

并不处于同一个能量参考系，不能直接一端扣除、另一端等量注入。

# 二、环境泄漏稳定性公式目前量纲有误或至少严重含糊

V3 当前写：

[
\eta_i^{joint}
==============

\Delta t
\left[
\frac{
\sum_j\kappa_{ij}
+
\sum_sH_{is}
+
\lambda_i
}{C_i}
+
\sum_ea_e
\right].
]

并说 (\lambda_i) 来自 `r_leak_ambient`。

但项目已有接口是：

```text
Capacitor.leak(resistance, dt)
```

而 W1 参数表中的 `DEFAULT_R_LEAK_AMBIENT≈3.57e6` 明确是电阻量。 

所以环境泄漏应先转成导纳：

[
G_i^{env}
=========

\frac{1}{R_i^{env}}.
]

正确写法有两种。

## 导纳形式

[
\boxed{
\eta_i^{joint}
==============

\Delta t
\left[
\frac{
\sum_j\kappa_{ij}
+
\sum_sH_{is}
+
G_i^{env}
}{C_i}
+
\sum_{e:\operatorname{tail}(e)=i}a_e
\right]
}
]

其中：

[
G_i^{env}=\frac1{r_{\mathrm{leak,ambient}}}.
]

## 速率形式

先定义：

[
\lambda_i^{env}
===============

\frac1{R_i^{env}C_i},
]

再写：

[
\boxed{
\eta_i^{joint}
==============

\Delta t
\left[
\frac{
\sum_j\kappa_{ij}
+
\sum_sH_{is}
}{C_i}
+
\lambda_i^{env}
+
\sum_ea_e
\right].
}
]

不能把已经是速率的 (\lambda_i) 再放进括号中除一次 (C_i)。

因此当前“(\lambda_i) 来自 `r_leak_ambient`”必须改成显式转换关系，不能只改变量名。

# 三、`τ_e=2.0` 只能算 EXP 起点

当前报告以 `GradedPotentialRelay` 的 RC 时间量级作为依据，选：

[
\tau_e=2.0,\qquad a_e=0.5.
]



这可以作为数值机制测试参数，但不能称为物理推导。神经分级电位中继的时间常数，与外部世界中有序热量转移的时间常数没有同一物理来源。

更严谨的写法应是：

[
\boxed{
\tau_e=2.0\text{ 是 EXP 机制测试起点，尚未物理标定。}
}
]

未来参数应由“一个参考时间内希望转移多少比例”定义。

若希望在参考时间 (t_r) 内剩余比例为 (r)，连续模型：

[
u(t_r)=u(0)e^{-a_et_r}
]

给出：

[
\boxed{
a_e=-\frac{\ln r}{t_r}.
}
]

或者用半衰时间：

[
a_e=\frac{\ln2}{t_{1/2}}.
]

这样参数的物理或实验含义是清楚的，而不是跨系统借用时间常数。

# 四、B1 还缺少非负性稳定门

单边离散递推：

[
u_i^{n+1}
=========

(1-a_e\Delta t)u_i^n.
]

若要保持：

[
u_i^{n+1}\geq0,
]

必须满足：

[
\boxed{
0\leq a_e\Delta t\leq1.
}
]

报告中的六项测试没有覆盖：

[
a_e\Delta t>1.
]

在这种情况下，解析递推仍然“算得出来”，但 tail 会变成负能量。因此 B1 还应增加：

* (a_e\Delta t<1)：正常部分转移；
* (a_e\Delta t=1)：恰好全部转移；
* (a_e\Delta t>1)：执行前拒绝，两端均不变化；
* tail 可用过剩能量为零：转移量为零；
* tail 与 head 相同：构造或执行时拒绝。

不建议使用：

[
q_e=\min(a_eu_i\Delta t,u_i)
]

静默钳制，因为这会把线性模型变成分段模型，并隐藏不稳定配置。应当 fail-fast。

# 五、B2 与 B3 的当前顺序应合并调整

报告现在安排：

* P1-B2：多边竞争；
* P1-B3：`ThermalTransportPlan` 与故障语义。

但多边竞争正是计划对象存在的原因。

假设同一 tail 有两条边：

[
i\to j,\qquad i\to k.
]

若没有计划阶段，就无法保证两条边都从同一个 (u_i^n) 快照计算，也无法彻底消除遍历顺序影响。

因此建议改为：

## P1-B2：计划生成与多边竞争一起实现

实现：

```text
prepare_thermal_transport(...)
    → ThermalTransportPlan
```

计划包含：

* 图/地址注册表版本；
* 节点状态修订号；
* 所有边身份及版本；
* 每个 tail 的能量快照；
* 每条边的 (a_e)、(p_e)、(\Delta u_e)；
* 每节点总入流、总出流；
* 联合稳定性预览；
* 边级账本预览。

并直接验证：

[
q_{ij}=a_{ij}u_i^n\Delta t,
\qquad
q_{ik}=a_{ik}u_i^n\Delta t.
]

调换边注册和遍历顺序，结果完全相同。

## P1-B3：提交与故障语义

实现：

```text
apply_thermal_transport_plan(plan)
```

测试：

* stale 地址；
* stale 边版本；
* plan 后节点状态已改变；
* plan 后拓扑已改变；
* 重复 apply；
* 同一 plan 被两个调用方竞争提交；
* prepare 失败；
* 联合出流超过可用过剩能量。

所有拒绝都必须满足：

[
\Delta u=0.
]

# 六、B1 的直接 `step_ordered_transport()` 应降级为诊断接口

当前单边函数直接：

[
\text{读取 tail}
\rightarrow
\text{计算}
\rightarrow
\text{修改两端}.
]

这对 B1 单边解析测试合适。

但进入 B2 后，它不能继续作为生产联合调度接口，否则调用方仍可绕过计划对象逐边执行。

建议明确标注：

```text
step_ordered_transport()
    # SINGLE-EDGE DIAGNOSTIC ONLY
```

生产联合调度只允许走：

```text
prepare_thermal_transport()
apply_thermal_transport_plan()
```

或者让 `step_ordered_transport()` 内部也构造一个单边计划，再调用统一 apply，避免形成两条行为路径。

# 七、还需要登记“外部驱动”欠账

有序热量转移：

[
p_e=a_eu_i
]

不依赖温差。

因此它可以把过剩热量从较冷节点搬到较热节点。这不是被动扩散，而是一个主动或由未建模介质驱动的过程。

能量两端仍守恒：

[
\Delta u_i+\Delta u_j=0,
]

但驱动该传输的机械功、压力差或介质动能没有进入当前模型。

所以 P1-B 应明确声明：

[
\boxed{
\text{热能账本闭合，不代表完整热力学账本闭合。}
}
]

建议增加一个非能量数值字段或状态标志：

```text
transport_drive_mode = "exogenous_normalized"
```

并在报告中写明：

* 外部驱动的机械能暂未建模；
* 当前不作熵增或第二定律资格宣称；
* P1-C 只验证热量转移守恒、稳定性和结构可追溯性；
* 进入 physical-anchor/advection 阶段后再加入质量流与驱动功账本。

否则以后容易把“总热能没丢”误写成“整个物理过程封闭”。

# 八、P1-C 的规划应随之修正

P1-C 当前规划的三级账本、联合失稳、矩阵守恒、步长收敛和双段浸泡是正确的。

但必须在状态变量修正后再冻结矩阵形式。

如果采用“统一环境基线以上的过剩能量”：

[
u_i^+=\max(q_i,0),
]

完整更新将是分段线性的，不再能全局写成一个固定：

[
u^{n+1}=Mu^n+q.
]

只有在所有参与 tail 始终满足：

[
q_i>0
]

的固定工作区间中，才可以构造局部线性矩阵。

因此 P1-C 的矩阵测试应分成：

## 线性正域测试

选择整个运行过程中：

[
q_i>0
]

的夹具，验证真实运行算子等于 (M_E)。

## 边界测试

让某个 tail 接近：

[
q_i=0.
]

验证：

* 不出现负转移；
* 不发生供体/受体隐式翻转；
* 账本闭合；
* 进入零可用能量后该边功率归零。

# 九、建议下一轮执行范围

下一轮不要直接做完整 P1-C。

先做：

[
\boxed{
\text{P1-B1.5 定义修复}
+
\text{P1-B2 计划生成与多边竞争}
}
]

具体包括：

1. 明确 charge 是相对环境基线的热偏差，不是绝对内能；
2. 决定是否正式采用“过剩热量转移”；
3. 要求有序边两端使用相同环境基线；
4. 修正环境泄漏稳定性公式：
   [
   G^{env}=1/R^{env};
   ]
5. 把 (\tau_e=2.0) 降级为 EXP 起点；
6. 加入 (a_e\Delta t\leq1) 门；
7. 实现不可变 `ThermalTransportPlan`；
8. 同一 tail 两条出边统一快照；
9. 验证边遍历顺序不影响结果；
10. 保留 `step_ordered_transport()` 仅作单边诊断。

随后单独做 P1-B3 故障语义，最后才进入 P1-C 联合资格测试。

## 最终结论

这轮没有白做。`OrderedThermalEnergyLink` 的单边数学更新和实现方式已经得到有效验证。

但当前最重要的新发现是：

[
\boxed{
\texttt{capacitor.charge}
\text{ 是相对于环境基线的有符号热偏差，}
\text{不是报告所称的绝对热能。}
}
]

以及：

[
\boxed{
\texttt{r_leak_ambient}
\text{ 是电阻，联合稳定性必须使用 }
1/r_{\mathrm{leak,ambient}}.
}
]

这两项都属于 B0 基础定义层，优先级高于继续扩展多边代码。修正后，P1-B2/B3 和 P1-C 才会建立在一致的状态空间与量纲上。
