可以。先给结论：

[
\boxed{
\text{下一步完成 P1-B3，然后直接进入 P1-C。}
}
]

不建议继续拆出新的单边修补阶段。B2 已经证明不可变计划可以从统一快照生成，多边共享 tail 时没有遍历顺序依赖，组合超额会在生成计划阶段拒绝，地址错误和账本问题也有覆盖。

你对“降级导致方案变形”的担心是合理的。但需要区分：

[
\boxed{
\text{资格收紧}
\neq
\text{路线降级}
\neq
\text{方案变形}.
}
]

近期大部分变化属于第一种：把尚未获得的资格从名称和结论中撤掉，而不是把最终目标取消。

# 一、下一步：P1-B3 提交与故障语义

当前 B2 只生成：

[
\texttt{ThermalTransportPlan},
]

尚未实现：

[
\texttt{apply_thermal_transport_plan()}.
]

报告也明确把提交与故障语义留在 B3。

B3 应当只解决一件事：

[
\boxed{
\text{已经生成的计划，能否恰好提交一次，}
\text{并且失败时不留下部分修改。}
}
]

## 1. 先补状态过期检测

B2 当前保存了：

* `registry_revision`；
* 边快照；
* tail 能量快照；
* 节点净变化。

但报告列出的计划字段中没有独立的 `state_revision`。

`registry_revision` 能发现：

* 节点重建；
* 地址变化；
* 边注册变化；
* 拓扑变化。

但它不能发现：

> 计划生成后，某个节点的 charge 被其他物理过程修改。

所以 B3 必须增加以下两种方案之一。

### 方案 A：节点状态快照比对

计划保存所有参与节点：

[
S_{\mathrm{plan}}
=================

{
(\alpha_i,q_i^{snapshot})
}.
]

提交前验证：

[
q_i^{current}=q_i^{snapshot}.
]

任何不一致都拒绝提交。

这是当前更适合的方案，因为不需要修改所有已有物理组件去维护一个全局状态计数器。

### 方案 B：状态修订号

每次物理状态提交后：

[
state_revision\leftarrow state_revision+1.
]

计划记录生成时的修订号，提交时比较。

这个方案长期更快，但会影响所有状态修改入口，目前范围更大。

因此建议 B3 首轮使用方案 A。

## 2. 计划只能提交一次

必须禁止：

```text
apply(plan)
apply(plan)
```

否则同一份能量转移会被执行两次。

可使用一个最小提交登记表：

```text
applied_plan_ids
```

成功提交后登记：

[
plan_id\in applied_plan_ids.
]

再次提交立即拒绝。

不需要建设大型事务管理器。

## 3. 提交前只做一致性检查，不重新计算物理量

`apply()` 不应重新计算：

* (u_i^+)；
* (a_e)；
* 功率；
* 单步转移能量；
* 出流比例；
* 节点净变化。

这些都已经被冻结在计划中。

正确结构是：

```text
prepare:
    validate → snapshot → calculate → aggregate → freeze

apply:
    validate plan freshness → apply frozen deltas → record receipt
```

如果 `apply()` 再计算一遍，就可能出现：

[
\text{计划审计的是一组值，实际提交的是另一组值。}
]

## 4. 必须选择一种异常语义

### 推荐：提交前快照加回滚

提交前保存所有被修改节点的最小状态：

[
Q_{\mathrm{before}}
===================

(q_1,\ldots,q_n).
]

然后依次应用计划。

若任何一步异常：

[
Q\leftarrow Q_{\mathrm{before}}.
]

但这里不能只恢复 `charge`，还要核查 `Capacitor.inject()` 是否同时修改：

* KCL 账本；
* 最近注入量；
* 电流累计；
* 其他诊断状态。

如果存在这些字段，必须一起恢复。

另一条路线是证明提交区只包含不会抛出可预见异常的直接写入。但在尚未完成源码级副作用审计前，不应先作这个假设。

## 5. 成功提交必须返回收据

建议返回：

```text
ThermalTransportReceipt
```

包含：

* `plan_id`；
* 提交前后节点状态；
* 实际应用的节点净变化；
* 边级残差；
* 节点级传输残差；
* 总传输残差；
* 提交时间步；
* 使用的 registry revision。

并验证：

[
q_i^{after}-q_i^{before}
========================

\Delta q_i^{plan}.
]

## B3 验收重点

至少覆盖：

* 成功提交与计划完全一致；
* 计划生成后节点状态改变，提交拒绝；
* registry revision 改变，提交拒绝；
* 边版本改变，提交拒绝；
* 同一计划第二次提交拒绝；
* 计划应用到另一个图拒绝；
* 中途注入异常时完整回滚；
* 所有拒绝场景中状态不变；
* 成功提交后边级和全局传输账本闭合。

B3 通过后，不再继续拆 B 阶段，应直接进入 P1-C。

# 二、这些“降级”究竟是什么

近期至少发生了几种看起来像降级的变化。

## 1. “平流”变成“有序过剩热能转移”

原设想接近真实介质搬运，但当前没有：

* 介质质量；
* 比热；
* 质量流率；
* 体积变化；
* 动量或压力；
* 驱动功账本。

因此收紧为：

[
J_e^{oet}
=========

a_eu_{\mathrm{tail}}^+.
]

V3 现在明确声明它不是方向、不是平流、不是完整热能转移，并记录外部驱动功和第二定律尚未建模。

这不是放弃真实平流，而是承认：

[
\boxed{
\text{当前机制只有资格叫有序过剩热能转移。}
}
]

## 2. “方向”被取消

旧方向生成元缺乏内部参考系和真实传播基础，因此暂停。

这不是应在后期集中修复的普通技术债。它需要新的本体条件：

* 自我参考结构；
* 身体锚点；
* 运动—感受闭环；
* 或其他内部生成的坐标关系。

在这些条件出现之前，不能通过补代码把它“恢复”。

## 3. “相同状态、不同历史”收紧成“不同传输系数、不同通量”

当前：

[
J=aE
]

是无记忆函数，因此不能宣称同一瞬时状态因历史不同而产生不同通量。

这属于数学事实修正，不是功能缩水。

未来只有加入：

[
J=F(E,m),
]

其中 (m) 是介质惯性、储量或迟滞状态，才有资格恢复历史依赖。

## 4. “统一地址系统”收紧为身份和拓扑地址，不做路由

这是范围限定。

当前需要的是：

* 谁是谁；
* 与谁连接；
* 版本是否过期；
* 关系父支撑是什么。

当前不需要：

* 消息路由；
* 路径搜索；
* 网络坐标；
* 自动发现。

这种限定不会妨碍未来扩展，只是避免提前建设不需要的通信系统。

# 三、并非所有降级都应该后期恢复

应分成三类。

## A. 纠错性撤回：不应恢复

这些原始概念本身不成立：

* 把无质量热转移叫作真实平流；
* 把边端点顺序叫作空间方向；
* 把无记忆函数叫作历史依赖；
* 把相对环境 charge 叫作绝对热能。

这些不能列入“未来升级清单”。

它们应该进入：

[
\boxed{\text{已否决假设档案}}
]

作用是防止以后重复犯错。

## B. 能力暂缓：应该保留升级入口

例如：

* normalized 模式升级到 physical-anchor；
* 有序过剩热量转移升级到质量—焓平流；
* 外部驱动标志升级到驱动功和熵账本；
* 单点皮肤升级为多层、多点皮肤；
* 无记忆传输升级为具有介质内部状态的过程；
* 最小支撑升级到更大网络。

这些应进入：

[
\boxed{\text{资格升级清单}}
]

## C. 工程范围限制：按需求处理

例如：

* 地址路由；
* 全 64 感温点；
* 通用事务系统；
* 全网络扩展；
* 性能优化。

它们不一定全部需要完成。是否建设取决于后续系统是否真正需要。

# 四、后期需要集中处理，但不能全部堆到最后

你的直觉是对的：如果所有“降级项”都只写一句“以后处理”，最后会积累成一次无法控制的大重构。

但也不能现在逐项恢复，否则当前主线永远无法闭合。

建议设置四个集中审查点，而不是最后一次性处理。

## 审查点 1：P1-C 通过后——世界物理资格审查

集中审查：

* normalized 模式是否继续；
* 有序过剩热能转移是否足够；
* 是否需要质量、比热、流率；
* 外部驱动功是否要进入账本；
* 多点皮肤是否已经成为阻塞；
* 当前世界是否足够支撑真实发生元。

此时决定：

[
\text{继续 P2}
]

还是先启动一个：

[
\text{P1-PHYS：物理锚定升级}.
]

## 审查点 2：P2-A 通过后——感受边界资格审查

集中审查：

* 单点皮肤是否导致发生元失真；
* 皮肤热容模型是否过薄；
* 世界到皮肤的映射是否足够；
* 发生元工作区间是否可以真实标定。

## 审查点 3：P2-C 通过后——关系资格审查

集中审查：

* (r_\prec^\tau) 是否在真实过程下仍成立；
* (r_\rho^\tau) 是否真正使用了关系输入；
* 关系—关系生成是否有足够结构差异；
* 是否需要内部状态化传输以引入历史依赖；
* 是否具备 L3 条件。

## 审查点 4：首次长程验证前——债务收口

集中处理所有会影响长程可信性的项目：

* `stable_hash()`；
* 物理量纲统一；
* 参数标定；
* 事务边界；
* 多点扩展；
* 性能与可复现性；
* 长期能量漂移；
* 结构版本生命周期。

所以答案是：

[
\boxed{
\text{需要集中处理，但应按里程碑分批集中，}
\text{而不是全部推到项目末尾。}
}
]

# 五、怎样防止降级让方案变形

最有效的方式不是少降级，而是让每次资格收紧都有一份结构化记录。

建议在 V3 中增加一个很短的：

# 资格与升级登记表

每项只记录八个字段：

| 字段     | 含义           |
| ------ | ------------ |
| 原始目标   | 最初希望获得的能力    |
| 当前资格   | 现在真正实现了什么    |
| 收紧原因   | 缺少了什么物理状态或证明 |
| 保留的不变量 | 当前机制已经保证什么   |
| 被删除的宣称 | 现在明确不能说什么    |
| 升级前置   | 恢复更高资格需要什么   |
| 触发审查点  | 在哪个里程碑重新评估   |
| 禁止捷径   | 哪些方法不能用于假装升级 |

例如当前 P1：

| 项目    | 内容                    |
| ----- | --------------------- |
| 原始目标  | 真实介质平流                |
| 当前资格  | 有序过剩热能转移              |
| 收紧原因  | 无质量、比热、流率、驱动功         |
| 保留不变量 | 有序端点、快照计划、热量两端守恒      |
| 删除宣称  | 不称流体、不称方向、不称完整热力学闭合   |
| 升级前置  | (m,c_p,\dot m)、焓和驱动账本 |
| 审查点   | P1-C 后世界物理资格审查        |
| 禁止捷径  | 不能只把类名改回 `Advective*` |

这样一来，“降级”不会把原目标擦掉，也不会让当前实现冒充最终实现。

# 六、判断方案是否已经变形，要看不变量，不看名称

方案是否变形，不能只看名字从“大”变“小”。

应检查四条主脊柱是否仍然存在。

## 1. 真实物理过程优先

仍然要求：

[
\text{状态}
+
\text{通量}
+
\text{耗散}
+
\text{守恒}.
]

没有变。

## 2. 关系由真实过程产生

P2 仍计划：

[
\text{world}
\rightarrow
\text{skin}
\rightarrow
\xi^{\mathrm{occ}}
\rightarrow
r_\prec^\tau,r_\rho^\tau.
]

没有变。

## 3. 不预设方向和事件语义

当前收紧反而更忠于这一原则。

## 4. 关系可继续参与更深生成

P2-C 仍计划使用三条真实有序转移通量形成：

[
r_{\rho,J}^{\tau}.
]

V3 已把输入公式同步为：

[
J_e^{oet}=a_eu_{\mathrm{tail}}^+,
]

并明确不把它叫方向或事件。

因此目前并没有发生主线变形。

发生的是：

[
\boxed{
\text{把未经证明的高资格，压回已证明的低资格。}
}
]

这实际上是在保护方案不被实现过程扭曲。

# 七、真正会导致方案变形的信号

需要警惕的不是“名称越来越保守”，而是以下情况：

1. 临时机制成为唯一生产路径，却没有升级接口；
2. 原始目标从 V3 中消失，只剩当前近似；
3. 为了通过测试，把物理过程改成无状态公式；
4. 未来阶段开始依赖当前近似的偶然数值，而不是它的结构契约；
5. 暂缓项没有明确重新评估的触发点；
6. 当前 normalized 参数被当成现实物理常数；
7. P2/L3 为适应 P1 的限制而改变本体目标；
8. “以后处理”项目不断累积，但从未进入阶段性资格审查。

当前第 2 点有一定风险：V3 详细记录了当前资格，但“最终真实平流、内部参考系、历史介质状态”仍主要散落在正文中。

所以增加资格与升级登记表是有必要的。
