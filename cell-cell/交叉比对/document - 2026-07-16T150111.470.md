## 一、双轨可以并行设计，不能并行写入同一实现分支

文档称“双轨并行”，容易被理解为同时在 `VariantCircuit` 中加入温感和运动两套 Phase 0～4。

这会重新制造我们试图避免的问题：

* 两套新增 Bundle 同时进入 census；
* 运行成本同时上升；
* 回归失败时无法判断来自哪一轨；
* 两套 RC 参数和命名同时变动；
* `variant_adapter.py` 发生大范围交叉修改。

正确方式应是：

[
\boxed{
\text{方案并行，代码串行；轨道独立，Phase 串行}
}
]

建议顺序：

```text
共同总纲
   ├── 温感 Phase 0 → 1 → 2 → 3 → 4
   └── 运动 Phase 0 → 1 → 2 → 3 → 4
```

两条轨道可以同时完成文档设计，但首轮代码实施应先选择一条轨道。更适合先做温感轨，因为：

* 已有 64 个明确的 (\xi) Collector；
* 信号读取和 RC 动态已经测过；
* 不涉及运动侧“状态生成元还是残差生成元”的语义选择；
* 不会立即影响现有 Motor 和 `polarization`。

完成温感 Phase 1 后，也可以切换去做运动 Phase 1，但不能在同一未验证提交中同时增加两轨。

分支建议为：

```text
feat/thermal-basegen-p0
feat/thermal-rprec
feat/thermal-rdir
feat/thermal-rrho
feat/thermal-basegen-integration

feat/motion-basegen-p0
feat/motion-rprec
feat/motion-rdir
feat/motion-rrho
feat/motion-basegen-integration
```

不是一个 `feat/base-generators-all` 分支。

## 二、Phase 3 与“终止于 Collector”的边界发生冲突

文档一方面规定：

> Phase 0～4 全部终止于 Collector，不接 Motor。

另一方面又提出：

> 运动轨 Phase 3 用 (r_\rho) 替换现有 `MotionState.polarization` Python 除法。

这两件事不能在同一个 Phase 3 内同时成立。

因为“替换 polarization”意味着：

* 新 (r_\rho) 已经接入现有运动状态计算；
* 改变了既有下游行为；
* 不再只是独立 Collector 原型；
* 回归不再只验证隔离性，而要验证功能等价性。

因此运动轨必须拆成：

### Phase 3A：占比关系生成元原型

只完成：

[
(\xi_x,\xi_y,\xi_z)
\longrightarrow
(r_{\rho,x},r_{\rho,y},r_{\rho,z})
]

输出停在 Collector，和现有 `polarization` 并行存在，不替换任何东西。

### Phase 3B：占比输出校准与影子比较

离线比较：

[
\rho_{\mathrm{struct}}
\quad\text{与}\quad
\rho_{\mathrm{python}}
]

包括：

* 排序一致性；
* 共同尺度变化；
* 静默状态；
* 单轴主导；
* 两轴竞争；
* 三轴接近等强。

这一阶段仍不切换生产路径。

### 后续独立 Phase 5：硬编码替换

只有结构输出被证明足够稳定后，才能考虑用它替代：

[
\mathrm{polarization}
=====================

\frac{\max_i|\nu_i|}
{\sum_i|\nu_i|}.
]

因此当前 Phase 0～4 方案中，应删掉“替换 polarization”，改为：

> 为未来替换 `polarization` 提供结构化候选输出和影子比较数据。

否则它不再是基础生成元独立构建方案，而变成运动状态系统重构。

## 三、运动轨的“路线 1”可以实施，但不能称为预测残差 (\xi)

文档已经发现了代码中的术语冲突：

* 方案中的 (\xi)：局部尖峰发生生成元；
* `BundleConfig.xin_tension` 中的 (\xi)：PI 预测残差或张力参数。

这个区分必须写入代码命名，而不能只写在报告里。

建议正式类型命名为：

[
\xi^{\mathrm{occ}}_a
]

表示 occurrence generator，即局部发生生成元。

未来路线 2 的运动残差则写为：

[
\xi^{\mathrm{err}}_a.
]

Bundle 的 `xin_tension` 仍保持原字段，但报告中明确记为：

[
\xi^{\mathrm{PI}}_{\text{bundle}}.
]

于是三者不会再混为一谈：

| 符号                   | 工程对象                       | 含义             |
| -------------------- | -------------------------- | -------------- |
| (\xi^{\mathrm{occ}}) | 感温/运动 Collector            | 局部物理发生         |
| (\xi^{\mathrm{err}}) | 误差 Neuron/Collector        | 预测—实际残差发生      |
| (\xi^{\mathrm{PI}})  | `BundleConfig.xin_tension` | Bundle PI 张力参数 |

首轮运动轨采用路线 1 是合理的，但其准确表述应为：

[
\boxed{
\text{运动局部发生生成元轨}
}
]

而不是“真 (\xi) 预测残差轨”。

路线 2 可以以后单独构建，不能称为路线 1 的简单升级，因为二者表达的物理对象不同：

* 路线 1：运动发生了什么；
* 路线 2：预测与运动之间破缺了什么。

它们未来可能并存，而非必然替换。

## 四、温感轨不能以 64 个源全面展开，必须先选最小支撑

文档中说每轨都走 Phase 0～4，但没有明确每一阶段使用多少个 (\xi)。

若直接对 64 个感温 Collector 建立成对关系：

[
\binom{64}{2}=2016
]

仅无向对就有 2016 对；时间关系又有正反、多 RC 通道，结构会立即爆炸。

如果每对使用正反各 4 个历史尺度：

[
2016\times8=16128
]

个关系检测输出，尚未计算中继神经元和 Bundle。

这显然不能作为首轮。

因此需要写死“最小支撑实施规则”。

### Phase 1：时间关系

只选两个真实 (\xi)：

[
\xi_a,\xi_b.
]

先完成一个二元时间关系生成元：

[
r_{\prec}^{ab}.
]

### Phase 2：方向关系

只选三个具有已知局部邻接的 (\xi)：

[
\xi_1\leftrightarrow\xi_2\leftrightarrow\xi_3.
]

不能从 64 点中随意挑三个。应根据 `skin_network.py` 已有球面点构造，在初始化阶段选出局部邻接，但运行时方向不得再靠坐标计算。

### Phase 3：占比关系

先做两个输入：

[
r_\rho^{ab}.
]

二元通过以后才做三元：

[
r_\rho^{abc}.
]

### Phase 4：集成

仍然使用 Phase 1～3 的同一最小支撑集合，不扩展到全皮肤网络。

所以 Phase 0～4 的目标不是“把所有 (\xi) 都接入”，而是：

[
\boxed{
\text{证明一套最小基础关系生成元可以由真实 }\xi\text{ 稳定地产生}
}
]

全网络扩展必须是后续独立阶段。

## 五、(r_{\rightarrow}) 的运动轨物理意义尚未充分成立

温感轨可以从皮肤邻接结构得到：

[
\xi_1\leftrightarrow\xi_2\leftrightarrow\xi_3.
]

因为感温点确实存在局部空间邻接。

但是运动轨若选：

[
\mathrm{move}_x,\mathrm{move}_y,\mathrm{move}_z
]

并人为连成：

[
x\leftrightarrow y\leftrightarrow z,
]

这个链本身没有物理依据。它只会生成“我们手工排列的轴顺序”，而不是从运动结构中生成方向。

运动侧 (r_{\rightarrow}) 需要先明确传播支撑是什么。候选有两类。

### 路线 A：同一轴的反向发生对

利用现有对向结构：

[
\mathrm{yaw}*{cw}
\leftrightarrow
\mathrm{yaw}*{ccw}.
]

或者前庭量子链路中同一轴的正负向：

[
\xi_{\mathrm{yaw}+}
\leftrightarrow
\xi_{\mathrm{yaw}-}.
]

这具有真实的 push-pull 结构基础。现有前庭量子链路正是由 MET/antimet 构成反向物理通道。

但它更接近“极性竞争关系”，不一定是空间传播方向。

### 路线 B：运动发生链中的因果传播

选择真实存在的结构路径，例如：

```text
前庭 ξ
   → 中继/运动神经元
   → Body 或运动反馈 ξ
```

然后比较：

[
\pi_{a\to b}
\quad\text{与}\quad
\pi_{b\to a}.
]

这才更接近方向关系的定义：

> 发生沿哪条结构路径能够传播。

不过路线 B 会触碰现有 Motor/Body，超过当前“只读 (\xi)、终止于 Collector”的范围。

因此首轮运动轨 Phase 2 应谨慎降格为：

[
\boxed{
\text{对向结构关系原型}
}
]

或者暂缓运动轨 (r_{\rightarrow})，先完成温感轨方向关系。

不能为了保持“双轨完全对称”而强行把不同运动轴排成一条链。

# 六、严格使用项目内组件方面，文档基本合格

文档的以下限制应保留：

* 不新增 `DelayLine`；
* 不新增 `RatioDivider`；
* 不新增 `DirectionOperator`；
* 历史支路使用现有非 spiking `Neuron` 的 RC 膜状态；
* 信号只经 `SynapticBundle`；
* 抑制使用 `synapse_gain=-1.0`；
* Memristor 权重保持非负；
* 新 Bundle 纳入 `get_all_bundles()`；
* 新关系神经元暂时排除 `get_all_neurons()`；
* 所有路径第一阶段 frozen；
* 每类生成元独立配置工厂。

现有感温 Ω 报告已经证明，Collector 上游信号是阵发性 `pre_trace` 时，必须重新标定膜电容和权重，不能复用持续输入链路的参数。

不过文档中这一句应更谨慎：

> 已确认 `BundleConfig.delay_steps` 存在，可用作纯延迟。

即使字段存在，也需要在 Phase 0 核实：

1. 它是否对当前类型 Bundle 生效；
2. 延迟队列存储的是 `activation` 还是最终电流；
3. 多源 Bundle 的延迟单位是什么；
4. 是否会与 `pre_trace` 产生二次时间扩展；
5. 延迟路径是否进入保存、复制和 census。

因此 Phase 1 的默认主方案仍应是：

[
\boxed{
\text{非 spiking Neuron 的 RC 历史痕迹}
}
]

`delay_steps` 只用于 A/B 对照探针，不作为首版理论结构。

# 七、建议修订后的双轨计划

## 共同总纲

统一：

* 术语；
* 项目组件约束；
* census；
* frozen；
* 报告格式；
* 测试门槛。

## 温感轨

[
T0\rightarrow T1\rightarrow T2\rightarrow T3\rightarrow T4
]

* T0：选择两个或三个真实感温 (\xi^{\mathrm{occ}})；
* T1：二元 (r_{\prec})；
* T2：三节点局部邻接 (r_{\rightarrow})；
* T3：二元后扩展三元 (r_\rho)；
* T4：同一最小支撑上的三路并行。

## 运动轨

[
M0\rightarrow M1\rightarrow M3\rightarrow M4
]

首轮建议暂时不强制实施 M2：

* M0：明确运动 (\xi^{\mathrm{occ}})；
* M1：二元时间关系；
* M3：轴间参与占比原型；
* M4：已有关系并行，无下游替换；
* M2：待找到真实传播支撑后单独设计。

如果必须完整走 0～4，则 M2 应使用前庭正反向量子链路构造“对向结构关系原型”，并明确它尚不等于普遍空间传播方向生成元。

# 最终评价

这份文件可以作为**评估与路线分析稿**保存，但还不适合作为直接执行的 Phase 总计划。

建议采纳的部分约占八成：

* 双轨隔离；
* 只用现有组件；
* Phase 门控；
* 运动 (\xi) 路线 1 优先；
* 禁止直接读取 `xin_tension`；
* 独立 RC 标定；
* census 和 frozen 规则。

需要修改的关键部分是：

1. 双轨并行改为“设计并行、实施分轨串行”；
2. Phase 3 不直接替换 `polarization`；
3. 64 个温感源改为最小支撑；
4. 运动轨方向生成元不能用人为轴链冒充；
5. 区分 (\xi^{\mathrm{occ}})、(\xi^{\mathrm{err}}) 与 `xin_tension`；
6. 全网络扩展和硬编码替换放到 Phase 0～4 之后。

修订后，它就能成为一份真实可执行的双轨落地总计划。
