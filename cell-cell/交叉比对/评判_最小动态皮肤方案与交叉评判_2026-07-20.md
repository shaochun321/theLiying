## 一、定位

两份文档均在 `cell-cell/交叉比对/`,时间戳 2026-07-20,处于 P2-A0(皮肤地址挂载 + 轨迹身份核对,**已完成**)与 P2-A 主体(单点真实发生元构造与标定,**尚未启动**)之间——是 P2-A 主体启动前的最后一轮交叉比对。

- **方案**是为 P2-A 主体提出的具体接入方案:三点皮肤、十神经元生成元、自然单位候选、四次实现循环(单通道闭合→三通道并行→时序频率→关系输入资格)、验收标准 A/B/C/D。
- **评判**裁定方案提出的三个问题(u_i 量纲缺失 / 三点皮肤与 W1 几何冲突 / ε_ij 标定不严谨)均成立,并追加隐含第四问(频率比较需工作区间),产出 P2-A1/A2/A3 三个前置任务。

## 二、代码实况核对(两份都未正面处理)

这是本轮评判最重要的一环——两份文档的推演质量很高,但都建立在与代码现状脱节的前提之上。

### 1. 项目里没有任何真实硬件

`nexus_v1/components/semiconductor.py` 的 `Capacitor`/`MOSFET`/`Memristor`/`PowerRail` 全部是纯 Python `@dataclass`,用等效电路方程模拟。全仓库无 GPIO、无 `adc_read`、无 DAC 硬件调用、无串口/I2C/SPI 设备驱动。

方案反复出现"真实热接触 / 薄金属片或其他连续导热片 / 绝热或低导热背衬",评判进一步推到 `[u_i]=A`(安培)、pA/nA、ADC 或采样调度、系统时钟误差、接线和接口差异——描述的都是一个**当前项目里不存在的硬件场景**。方案本身还算克制(明确写"拟真软件皮肤继续保留,定位为测试夹具"),但仍是两头下注;评判则沿着这条线走得更远,偏离更大。

**裁定:P2-A 第一版应明确定为纯软件热扩散模型,"真实材料/真实皮肤"作为远期愿景搁置,不进入本轮标定设计。**

### 2. "十神经元 / G₁₀" 在代码里不存在为封装单元

搜索确认:代码中匹配到的 `G10` 是 `test_ecm_vascular.py` 里一个**无关的血管神经耦合测试用例编号**("G10 Vascular NVC"),与"十神经元基础生成元"毫无关系。

真实存在且已实现的是:统一的 `Neuron` 类(`components/neuron.py`,configured via `NeuronConfig`)+ `SynapticBundle`(`circuit/bundle.py`)+ 已实现的发生检测测试(`tests/test_basegen_thermal_t0~t3*.py`,用真实感温 Collector 的 `pre_trace` 首次上升沿作为 ξ^occ)。

方案与评判都把 `G_{10,i}` 当作"现有十神经元动力学核心"直接引用——**高估了现状**。这不是文字问题,而是循环一(单通道闭合)缺少可连接的具体实体。

**裁定:进入循环一前,必须先用现有 `Neuron`/`SynapticBundle` 原语把"十神经元生成元"具体构造出来(拓扑、参数来源、迟滞阈值 θ↑/θ↓ 的生物依据),否则它只是语义占位符,违反 CLAUDE.md 的"写代码前强制三问"。**

### 3. 复用机会,两份都漏了

方案 §三对连续材料的全部要求(局部热容、横向热扩散、接触热阻、传播延迟、峰值衰减、环境散热、材料不均匀性)——`nexus_v1/components/dynamic_thermal_field.py` 的 `ThermalFieldGraph`/`ThermalCell`/`ThermalLink` 与 `world.py` 的 `SkinPatch`(Fourier 冷却定律 + Arrhenius 损伤积分 + Langevin 热噪声)**已经实现了这些物理**。

一个 1D 三节点 `ThermalFieldGraph` 子图(`s1-s2-s3` + `e12/e23` 邻接)即可直接满足方案的最低要求("刺激一个位置时,另外两个位置能以不同延迟和幅度受到影响"),不需要另起炉灶讨论金属片/背衬等硬件构造细节。

（补充背景:W1 = `fibonacci_sphere_points(32, 2.0)` 构建的球壳测试夹具,代码中明确标注 `TEST FIXTURE ONLY`,不得作生产世界坐标;现有皮肤是 `world.py` 的 12 块布局(3 环 × 4 方向),不是三点。）

## 三、方案(203329)评判

### 优点

- 高度贴合项目核心约束(结构优先、禁语义硬编码):§5/§7 的"允许/禁止"清单与 CLAUDE.md 的结构构建原则严丝合缝。
- 正确禁止 `(T₁,T₂,T₃)→G_10,single` 多对一映射(避免预设三点为不可分单元)。
- 正确区分 `S_i ≠ 𝒢_i`(传感器只是基础生成元的物理支撑之一,不是完整生成元)。
- 迟滞阈值 θ↑/θ↓ 处理阈值抖动、避免伪脉冲重复计数,合理。
- 双能量账本分离(`Q_thermal` 被感受的物理过程 vs `E_supply` 项目供电过程)与项目既有的世界-皮肤联合守恒纪律一致。
- 自然单位标注为"候选",不上升为理论定义,认识论上克制。
- 四循环 + A/B/C/D 验收标准,具体可测,符合"model before tune"精神。

### 薄弱之处

- `u_i(t)` 无量纲、无工作区间(评判问题1,成立)。
- 硬件/软件两头下注(见上文核对第1点)。
- `ε_ij` 简单误差相加公式不够严谨(评判问题3,成立)。
- 评判问题2(三点皮肤与 W1 几何冲突)部分打在方案未主张的靶子上——方案原文从未提议"从 W1 球面 32 点里抽 3 个编号假装成直线",这条更像预防性提醒而非纠错。

## 四、评判(203750)评判

核心价值在标定方法学,确实实质性提升了方案。

### 强项

- **问题1(工作区间)成立且重要。** 用输入-响应工作图 `u ↦ (L_first, f_occ, N_occ, t_recovery, E_closure)` 扫描替代"X秒内触发一次"单点标定,把循环一从"单点触发调参"升级为"输入扫描与工作区间标定"——正对应 RULES.md 的"Model before tune / 反对为通过而调参"。这是全文最有工程价值的修正之一。
- **问题3(ε_ij 标定)是全文最强贡献。** 正确区分确定性误差界(最坏情况和,保守但有效)与统计抖动(RSS + 协方差项,忽略协方差需独立性证据),并进一步主张**不先拆解误差来源,而直接测量成对时序分辨率**:对 `(s_i, s_j)` 施加可认为同时到达的共同刺激,重复 N 次,取经验分布的中位数偏置 `b_ij` 校正、99 分位定义不可分辨带宽 `ε_ij`。方法学干净,绕开了"各误差项独立可加"这一未经证明的假设。
- **问题4(频率工作区间)真实且微妙。** 三通道 `f_max` 差异(响应速度、增益、恢复时间、供能限制不同)不应被直接送入频率比 `r_ρ^τ`,否则混合了真实刺激差异与通道容量差异;提出的归一化 `f̃_i = (f_i - f_i,false)/(f_i,max - f_i,false)` 是合理的第一版处理。

### 薄弱之处

- **硬件误差源错配,是评判中最该修正的一点。** `ε_ij` 列出的 ADC/采样调度、系统时钟误差、接线和接口差异是硬件产物;而在纯软件项目中真正的抖动/时序偏差来源是 **RC 时间常数失配、dt 离散化步长、代码执行顺序**——这些恰恰是项目已经踩过的坑(见项目历史:`dt=1.0` 陷阱导致 `exp(-50)≈0`、RC 时间尺度失配导致新聚合层完全不发放、"不能让数组遍历顺序替代真实发生顺序"等已验证教训)。直接测量成对时序分辨率的方法本身依然有效,但误差源框架应换皮映射到软件语境。
- 问题2的裁定同样部分打在非主张上(见上文方案评判)。
- `f̃_i` 归一化存在未言明的张力:若三通道间的响应差异本身就是**物理真实**的(比如某通道离热源更近导致更快触发),按各自工作区间归一化可能反而抹掉这种真实的参与不对称。评判自称"这不是抹平生成元差异",但这条边界应当显式标注、并在循环三/四中设计对照实验验证,而不是留白。
- 没有把三点结构的标定需求接回审查点1的核心动机:审查点1 已用 T-WQR-2/3 实测坐实"单点皮肤把不同世界过程(`Γ1^phys ≠ Γ2^phys`)压平成不可区分轨迹,差异仅浮点精度量级(~1e-16)"。三点结构存在的全部意义正是**站间延迟/幅度差**能否被可靠分辨;因此 `ε_ij` 与频率工作区间标定之所以关键,恰恰是因为信号本身就是通道间的差异。评判触及了这个问题但没有点破这层因果关系,建议在 P2-A2/A3 任务说明中补上。

## 五、总裁定

| 项 | 裁定 |
|---|---|
| P2-A1(输入扫描标定工作区间) | **采纳** — 真实的方法学升级,替代单点调参 |
| P2-A3(直测成对时序分辨率) | **采纳**,但需把 `ε_ij` 误差源从硬件语汇(ADC/时钟/接线)改写为软件语汇(dt 离散化 / RC 时间常数失配 / 执行顺序),并显式关联审查点1的"单点压平"实测结论 |
| P2-A2(三点独立于 W1) | **同意方向**,但重构实现路径:复用 `nexus_v1/components/dynamic_thermal_field.py` 的 `ThermalFieldGraph` 搭建 1D 三节点软件热模型,**不新建硬件构造细节** |
| 补漏①(两份都缺) | P2-A 第一版应明确定为**纯软件**实现,真实材料/硬件接口作为远期愿景搁置 |
| 补漏②(两份都缺) | 在进入循环一之前,先用现有 `Neuron`/`SynapticBundle` 原语把"十神经元生成元"具体构造为真实代码实体(含迟滞阈值的生物依据),否则循环一无实体可接 |

## 六、下一步(修正后执行顺序)

原定 V5 总纲下一步是"P2-A 主体:单点真实发生元构造与标定"。本轮交叉比对将其细化为:

1. **补漏①** — 在设计文档中明确 P2-A 纯软件定位(搁置硬件路线)
2. **补漏②** — 用 `Neuron`/`SynapticBundle` 构造十神经元生成元的具体实现(而非语义占位)
3. **P2-A1** — 生成元输入工作区间标定(`u_i` 量纲 + 输入扫描)
4. **P2-A2** — 独立三点物理接口(复用 `dynamic_thermal_field.py` 的 1D 软件热模型)
5. **P2-A3** — 成对时序分辨率标定(直测 `b_ij`/`ε_ij`,误差源改为软件语汇)
6. **P2-A 主体四循环** — 单通道闭合 → 三通道并行 → 时序与频率 → 关系输入资格
7. 之后进入 **P2-B** — 回接 `r≺^τ`(时间先后)/ `r_ρ^τ`(比例)关系原语
