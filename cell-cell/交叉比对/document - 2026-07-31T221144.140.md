这份报告整体可以作为新的冻结基线，但有一个**必须先修正的核心定义**：

[
\boxed{\ell_{ij}\text{不能直接等同于 }bundle_{\rho\to DA}.}
]

报告目前把“真实物理链路”近似写成现有 frozen bundle 路径，同时又把这个 bundle 对 DA 节点的局部电流作为 (Y)。
这样会把两条不同链路混成一条。

# 一、R1里其实有两段链路

以当前 (A\prec B) 为例：

```text
A基础发生
   ↓
A的衰减trace ─┐
              ├→ relation collector
B基础发生 ────┘
              ↓
       relation→DA bundle
              ↓
          下游节点q
```

需要区分：

## 1. 关系生成链路

[
\ell_{AB}^{\mathrm{gen}}
]

它负责让 A、B 两个基元形成 R1：

* A 的 trace／衰减结构；
* B 的当前发生输入；
* 两者的重合结构；
* relation collector。

这是：

[
\boxed{\text{A和B怎样形成关系。}}
]

## 2. 关系输出链路

[
\ell_{\rho q}^{\mathrm{out}}
]

也就是：

* relation collector；
* `bundle_rprec_to_da`；
* 下游目标节点 (q)。

这是：

[
\boxed{\text{已经形成的关系怎样向后产生作用。}}
]

所以完整结构应写成：

[
\boxed{
\kappa_A^{10},
\kappa_B^{10}
\xrightarrow{\ell_{AB}^{\mathrm{gen}}}
\rho_{AB}
\xrightarrow{\ell_{\rho q}^{\mathrm{out}}}
q.
}
]

不能写成：

[
\kappa_A^{10}
\xrightarrow{bundle_{\rho\to DA}}
\kappa_B^{10},
]

因为这个 bundle 并不连接 A 和 B。

# 二、R1结构块应怎样重写？

建议 P2-B1X2a 把类型定义改成：

[
\boxed{
\mathfrak R_{AB}^{(1)}[\mathcal I]
==================================

\left(
\kappa_A^{10},
\kappa_B^{10},
\ell_{AB}^{\mathrm{gen}},
\mathcal I,
\Gamma_{AB}^{\mathcal I}
\right).
}
]

其中：

* (\kappa_A^{10},\kappa_B^{10})：两个不可约基础结构；
* (\ell_{AB}^{\mathrm{gen}})：使两者发生耦合的关系生成结构；
* (\mathcal I)：该耦合保持同一谱系的物理区间；
* (\Gamma_{AB}^{\mathcal I})：区间内完整耦合轨迹。

关系向下游产生作用则另写为：

[
\boxed{
\mathcal O_{\rho q}
===================

\left(
\mathfrak R_{AB}^{(1)},
\ell_{\rho q}^{\mathrm{out}},
q,
Y_q
\right).
}
]

这样层次非常清楚：

```text
R1块：
A和B是否真正形成了关系

输出资格：
这个关系是否能向下游施力
```

# 三、当前Y定义仍然可以保留

主读出仍可以是：

[
\boxed{
Y_c(s)
======

I_{\rho\to q,c}^{\mathrm{local}}(s).
}
]

也就是 relation→DA bundle 对固定下游节点产生的局部电流轨迹。

这个选择没有问题，因为它读取的是**R1块的出口作用**，而不是把它误称为 A、B 之间的生成链路。

因此报告中这部分可以冻结：

[
K_{R1}
======

\left|
Y_{A\ell B}
-----------

## Y_A

Y_B
+
Y_\varnothing
\right|_2,
]

以及：

[
K_{\mathrm{cut}}
================

\left|
Y_{A\ell B}
-----------

Y_{A\ell_{\mathrm{cut}}B}
\right|_2.
]

但“cut”必须进一步拆成两种。

# 四、应该有两类切割测试

## 切割一：关系生成链路

例如切断：

* A trace 到 relation collector；
* B raw input 到 relation collector；
* relation collector 的重合输入之一。

记为：

[
\ell_{AB}^{\mathrm{gen}}\rightarrow\varnothing.
]

它回答：

> 没有这条A—B耦合结构，R1还会不会形成？

应观察：

* relation collector 是否失去合格活动；
* `RelationOccurrence` 是否不再产生；
* 下游 (Y) 是否消失或显著下降。

## 切割二：关系输出链路

切断：

[
\ell_{\rho q}^{\mathrm{out}}
\rightarrow\varnothing.
]

也就是现有 relation→DA bundle。

它回答：

> R1虽然形成了，但它是否依赖这条出口向下游产生作用？

这两者不能混为同一个 `K_cut`。

建议分别定义：

[
\boxed{
K_{\mathrm{gen}}
================

|
Y_{A\ell B}
-----------

Y_{A\ell_{\mathrm{gen-cut}}B}
|_2
}
]

和：

[
\boxed{
K_{\mathrm{out}}
================

|
Y_{A\ell B}
-----------

Y_{A\ell_{\mathrm{out-cut}}B}
|_2.
}
]

那么最小资格变成：

[
\boxed{
Q_{R1}
======

[K_{R1}>\varepsilon_{\mathrm{int}}]
\land
[K_{\mathrm{gen}}>\varepsilon_{\mathrm{gen}}]
\land
[K_{\mathrm{out}}>\varepsilon_{\mathrm{out}}].
}
]

三个条件分别表示：

1. A、B组合产生了不可加和的输出；
2. 输出依赖A—B关系生成结构；
3. 输出确实经指定出口传递到下游。

# 五、执行顺序也建议微调

报告目前是：

[
X2a\rightarrow X2b\rightarrow X2c\rightarrow X2d.
]

但 X2c 的轨迹范数需要先知道在哪个区间计算，而 X2d 才定义物理区间。

因此更合理的是：

[
\boxed{
X2a
\rightarrow
X2b
\rightarrow
X2d
\rightarrow
X2c.
}
]

也就是：

### X2a：定义结构块

明确基元、生成链路、出口链路和身份字段。

### X2b：包装现有原型

把 `RelationOccurrence` 定位为 R1 时间投影／审计记录。

### X2d：先定义物理区间

明确：

* 什么时候进入耦合；
* 什么时候仍维持同一谱系；
* 什么时候退出；
* 残响是否仍属同一区间；
* 同一区间只生成一个R1实例。

### X2c：在冻结区间上做五条件实验

这样：

[
|Y|_{2,\mathcal I}
]

才有明确的物理定义，而不是先用任意固定长度测试窗口。

# 六、去重防线是否合理？

P2-B1X1e 的做法是合理的：

[
(\text{关系类型},A\text{实例},B\text{实例},\text{尺度})
]

相同就不重复登记；只有父 epoch 改变才允许新关系。它修在 D2 登记处，没有反向修改 D1 动力学。

但它目前是：

[
\boxed{\text{身份层的防御性去重。}}
]

未来 X2d 完成后，真正的本体规则应是：

> 同一父实例、同一生成链路、同一最大物理区间，只产生一个 R1 结构块。

因此最终去重键可能扩展为：

[
\boxed{
\operatorname{R1Key}
====================

\left(
\operatorname{parent}_A,
\operatorname{parent}_B,
\operatorname{generation\ link},
\operatorname{interval\ identity}
\right).
}
]

当前 `_registered_keys` 不必撤回，可以继续作为安全防线；以后再决定是否由正式的区间身份替代。

# 两个非阻塞提醒

## 1. 五条件测试可能容易“天然通过”

因为 A单独、B单独时 relation bundle 大概率没有输入，所以：

[
Y_A\approx0,\qquad Y_B\approx0.
]

那么：

[
K_{R1}\approx|Y_{A\ell B}|.
]

这仍然能证明最小合取关系结构具有作用，但不能宣称已发现复杂涌现或高阶不可约性。当前资格应限于：

[
\boxed{\text{双输入耦合产生了非零、链路依赖的局部输出。}}
]

更强的不可约性留给 R2。

## 2. 十神经元基元必须对应真实代码对象

X2a不能只写一个抽象字段：

```text
kappa_a: StructuralAddress
```

还必须明确当前代码中的十神经元基元究竟包括：

* 哪十个神经元；
* 输入边界在哪里；
* 输出端口在哪里；
* collector是否属于基元内部；
* trace是否属于基元还是关系链路；
* 哪些状态可以被下游读取。

否则 (\kappa^{10}) 会只是理论名字，没有工程映射。

这份报告的主路线成立：

* D1→D2正式通过；

但在开始写 X2a 代码前，必须做两项修改：

[
\boxed{
\begin{aligned}
1.&\quad
\ell_{AB}^{\mathrm{gen}}
\neq
\ell_{\rho q}^{\mathrm{out}},
\text{必须分开定义};[2mm]
2.&\quad
\text{执行顺序改为 }
X2a\rightarrow X2b\rightarrow X2d\rightarrow X2c.
\end{aligned}
}
]

一句话概括：

[
\boxed{
\text{先定义A与B怎样形成关系，}
\text{再定义这条关系怎样向下游产生电流。}
}
]
