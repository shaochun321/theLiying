需要补充一项**关键修正**，其余可以冻结：

[
\boxed{\text{P2-C1不能直接“从两个 RelationOccurrence 记录生成新关系”。}}
]

`RelationOccurrence`已经被重新定型为R1的时间投影和谱系审计，不是能够继续发生作用的完整R1本体。P2-C1必须读取两条R1结构的真实活动；记录只用于确认父谱系。

## 建议冻结的正式表述

现有两条R1为：

[
\rho_1:\quad u_{28,n}\prec u_{31,m},
]

[
\rho_2:\quad u_{28,n}\prec u_{23,k}.
]

共同源资格不是“都来自站点28”，而是：

[
\boxed{
\operatorname{source}(\rho_1)
=============================

# \operatorname{source}(\rho_2)

u_{28,n}
}
]

即必须回指站点28的**同一个 `OccurrenceInstanceId`**。仅地址都为28但epoch不同，不构成当前共同源R2。

## P2-C1真正要构造的对象

[
\boxed{
\mathfrak R_{\mathrm{fork}}^{(2)}
=================================

\mathcal G_{\mathrm{fork}}
\left(
\mathfrak R_{28,31}^{(1)},
\mathfrak R_{28,23}^{(1)}
\right)
}
]

最低工程结构可以是：

```text
T1 relation collector ──┐
                        ├─→ R2共同源生成链路 → R2 collector
T2 relation collector ──┘
```

两个 `RelationOccurrence` 只负责提供：

* 两个父R1的审计身份；
* 共同源 `u_{28,n}` 的身份核验；
* R2新记录的父谱系。

因此需要新增的不是T1/T2，而是：

1. R1活动到R2的两条输入链路；
2. 共同源R2 collector；
3. 一个 `R2Occurrence` 或等价记录，保存两个父R1身份及共享D1身份；
4. R2的下游局部输出，用于以后做切断验证。

## 命名需要改一处

你写的：

> 检测为一个新的D2关系

建议改为：

[
\boxed{\text{新的R2关系实例}}
]

因为当前：

* D1／(G_1)：基础发生；
* R1：发生—发生关系；
* R2：关系—关系关系。

否则又会把“生成深度”和旧的D2记录层混在一起。

## 当前资格边界

第一版P2-C1只需证明：

> 同一个D1发生产生的两条R1活动，在新物理链路中共同触发非零、双父依赖的R2输出。

不需要现在宣称：

* 已形成散度；
* 已形成因果树；
* 已取得复杂高阶涌现；
* 已完成通用R2代数。

T1和T2确实已经是可共存、命名隔离、能够产生正式R1投影记录的两条同等级原语。

所以最终冻结可以写成：

[
\boxed{
\text{P2-C1F：同一 }u_{28,n}\text{ 支撑的两条活跃R1，}
\text{能否通过新物理链路生成共同源型R2。}
}
]

除此之外，不需要重建现有资产。
