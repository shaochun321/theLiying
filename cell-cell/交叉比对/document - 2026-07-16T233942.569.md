这次更新是有效推进，不是又一轮文档修补。

* W2A 已修复已知的“先扣热源、后拒绝世界更新”问题；
* T3-C0 不仅验证了共享分流池本身正确，还明确定位到真正的断点：**比例关系在 Neuron 公开输出层被二次门控和硬钳位破坏**；
* 测试仍保持 T-TSC 7/7、T-RPT 7/7、全量回归 21/21。

现在可以继续，但下一步不应直接称为“T3-C1 二级验收”。应先增加一个：

[
\boxed{\text{T3-C1R：关系输出换能机制}}

因为当前缺少的不是参数，而是从共享池电流到可供 Bundle 读取的关系信号之间的物理衔接。

# 一、W2A 修复基本正确，但“原子提交”措辞过强

新的调用顺序是：

```text
稳定性检查
→ 定位查询
→ source.release()
→ graph.step()
```

它已经保证：

* 稳定性检查失败时，source 和 graph 都不改变；
* 定位失败时，source 和 graph 都不改变；
* 只有所有已知前置检查通过后才扣除热源能量。

因此这次修复确实关闭了已发现的 bug。

但它严格来说是：

[
\boxed{\text{前置验证后的提交}}
]

而不是完整事务意义上的原子提交。

原因是 `source.release()` 以后，如果 `graph.step()` 因未预见的异常失败，热源已经扣能，世界仍可能没有收到能量：

```text
source.release()  成功
graph.step()      意外异常
```

目前测试证明的是已知的“不稳定配置拒绝”已经安全，并未证明 `graph.step()` 在提交点以后绝不会失败。

### 两种可接受处理

第一种是收紧措辞：

> `couple_and_step()` 对稳定性与定位失败提供前置原子性；在通过前置验证后，依赖 `ThermalFieldGraph.step()` 的无异常执行契约。

第二种是在 W2C 多组件接入前建立真正的计划—提交接口：

```text
prepare_field_delta()
prepare_source_debit()
validate()
commit_all()
```

W2A 当前不必为此新增事务类，但不要宣称它已经解决所有异常路径。

# 二、T3-C0 已证明：仅重新标定参数不能解决比例失真

审计结果非常关键：

[
\frac{y_a}{y_b}
===============

\frac{i_a}{i_b}
]

在共享 DN 输出层精确成立，并且对共同尺度变化稳定。

但注入 channel Neuron 后：

[
o_i
\approx
g_mV_i^2,
\qquad
V_i\propto y_i,
]

所以在未饱和区：

[
\frac{o_a}{o_b}
\approx
\left(\frac{y_a}{y_b}\right)^2.
]

输入继续增大后，两个通道又会被钳位到同一个上限：

[
o_a=o_b=10
\quad\Rightarrow\quad
\frac{o_a}{o_b}=1.
]

这意味着当前公开 `activation` 经历了两个阶段：

[
\text{比例平方变形}
\rightarrow
\text{饱和后比例完全丢失}.
]

报告的四层审计和共同尺度扫描已经充分证明这一点。

## 为什么调 (C)、(R_{\mathrm{leak}})、(g_m) 不足以修复

降低 (g_m) 或 (R_{\mathrm{leak}}) 可以避免过早触及钳位；改变 (C) 可以改变响应速度。

但只要输出公式仍是：

[
o=g_mV^2,
]

比例平方就仍然存在：

[
\frac{o_a}{o_b}
===============

\left(\frac{V_a}{V_b}\right)^2.
]

所以参数重标只能解决：

[
\text{饱和范围}
]

不能解决：

[
\text{传递函数类型}.
]

报告中把“重新标定现有 channel 参数”列为首选候选，需要增加这一限制。它可以保住排序和部分动态范围，但无法恢复真实输入比例。

# 三、必须先决定 (r_{\mathrm{part}}) 和 (r_\rho) 的资格差异

如果目标只是：

* 较大输入对应较大输出；
* 输入交换则输出交换；
* 共同缩放不改变排序；
* 输出能够表示竞争强弱；

那么平方映射：

[
[y_a:y_b]
\mapsto
[y_a^2:y_b^2]
]

仍然能作为一种 `r_part`。它强化了强通道，但保留排序。

但如果目标是占比关系：

[
r_\rho=[y_a:y_b],
]

那么平方后的：

[
[y_a^2:y_b^2]
]

已经是另一个射影点，不是原占比关系。

例如：

[
2:1
\mapsto
4:1.
]

所以当前资格应明确分层：

| 输出层                             | 资格         |
| ------------------------------- | ---------- |
| DN 输出电流 (y_i)                   | 二元射影占比候选成立 |
| channel Neuron `activation`，未饱和 | 只能作为强化竞争关系 |
| channel Neuron `activation`，饱和  | 关系失效       |

因此：

[
\boxed{
r_{\mathrm{part}}\text{ 已经存在于 DN 输出层}
}
]

但：

[
\boxed{
r_\rho\text{ 尚未形成可供下游读取的稳定输出}
}
]

# 四、建议新增“分级电位中继”，而不是继续挤压现有 Neuron

现在已经满足机制缺口准入条件：

1. 共享分流池确实产生了正确关系；
2. 当前 Neuron 的固有传递函数改变了关系；
3. 参数调整不能改变二次函数的阶数；
4. 下游 Bundle 又必须读取公开信号；
5. 继续用 Python 直接转发 (y_i) 会绕过物理状态。

建议新增：

```text
GradedPotentialRelay
```

或：

```text
GradedConductanceRelay
```

不要命名为 `RatioReadout`，因为后者把语义结论写进了组件名。

## Q1：生物对应物

对应非脉冲、分级电位传输的局部神经元或感受器输出。它不通过全或无尖峰编码，而是在一个有限工作区间内以连续电位或连续递质释放表达输入强度。

## Q2：物理结构

[
\text{DN 输出电流}
\rightarrow
\text{膜电容状态}
\rightarrow
\text{线性电导读出}
\rightarrow
\text{Bundle}.
]

动力学可以是：

[
\tau_r\dot V_i
==============

-V_i+k_iy_i,
]

公开输出为：

[
a_i
===

\operatorname{clip}
\left(
g_rV_i,,
0,,
a_{\max}
\right).
]

关键不是绝对无饱和，而是在经过标定的工作区间内：

[
a_i\approx g_rV_i
]

为线性。

## Q3：参数依据

不直接复用 T1 参数。根据 T3-C0 已测得的 (y_i) 范围确定：

* (R_{\mathrm{leak}})：稳态增益；
* (C)：响应时间尺度；
* (g_r)：公共输出增益；
* (a_{\max})：PowerRail 上限；
* 安全工作范围至少覆盖共同尺度扫描中的目标区间。

要求：

[
\max_i a_i
\leq
\beta a_{\max},
]

首轮可取：

[
\beta\leq0.5,
]

为真实输入波动保留余量。

不要修改现有通用 `Neuron.activation` 的语义，否则会影响已经使用它的其他系统。新机制应作为显式组件或明确的新 Neuron 模式存在。

# 六、Python hash 扰动应升级为全局复现性问题

T3-C0 对多个 `PYTHONHASHSEED` 的测试是有价值的，但把容差从 0.25 收紧到 0.10，只解决了测试门槛问题。

更深层的问题是：

[
\boxed{
\text{Python 进程 hash seed 正在改变实际 Memristor 电导}
}
]

这意味着完全相同的模型配置，在不同进程、机器或运行环境中可能形成不同物理网络。

这不应长期被当成“需要更宽容差的自然扰动”。建议将其改成显式的项目随机性：

```text
circuit_seed
memristor_perturbation_seed
```

并用稳定散列代替 Python 内建 `hash()`：

[
\delta w_{ij}
=============

F(
\text{stable_hash}
(
\text{circuit seed},
\text{bundle id},
i,j
)).
]

这样：

* 同一个 seed 必须精确复现；
* 不同 seed 用于鲁棒性测试；
* 不再依赖 `PYTHONHASHSEED`；
* 物理扰动成为模型参数，而不是解释器副作用。

在 T3-C1 正式资格验收前，至少应固定项目 seed。否则比例误差分布本身不是稳定的实验对象。
