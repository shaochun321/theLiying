这次 X2a 的大方向是对的：已经把“关系怎样形成”和“关系怎样向后施力”分成了两条链，避免把 `trace/关系collector` 与 `relation→DA bundle` 混为一谈；同时也明确了基础生成元的 collector 与关系 collector 不是同一个对象。

但我认为它**还不能完全冻结**，有一个阻塞问题。

# 阻塞：(\ell_{\text{out}}) 不应属于 R1 本体的必需部分

报告当前把完整 R1 写成：

[
R1StructureBlock
================

(\kappa_A^{10},\kappa_B^{10},
\ell_{\rm gen},\ell_{\rm out},I).
]

这会产生一个逻辑问题：

> 没有 `bundle_rprec_to_da` 的普通 `RPrecCircuitT1`，是不是就没有 R1？

文件里已经写明，只有 `RPrecCircuitT1Plastic` 才存在 (\ell_{\rm out})，基础版没有。

但关系本身应当先成立，之后才讨论它能否向某个下游节点施力。正如：

```text
A这次先于B这次
```

即使尚未接入 DA 池，这个关系仍然可以存在。

所以应该拆成两个对象。

## R1本体

[
\boxed{
\mathfrak R_{AB}^{(1)}[I]
=========================

\left(
\kappa_A^{10},
\kappa_B^{10},
\ell_{AB}^{\rm gen},
I,
\Gamma_{AB}^{I}
\right)
}
]

它回答：

> A与B是否通过真实生成链路，在一个物理区间内形成了关系结构块？

## R1输出资格

[
\boxed{
\mathcal Q_{\rm out}
====================

\left(
\mathfrak R_{AB}^{(1)},
\ell_{\rho q}^{\rm out},
q,
Y_q
\right)
}
]

它回答：

> 这个已经形成的R1，能否沿某条出口链路对下游产生真实作用？

因此代码上建议：

```text
R1StructureBlock
├── kappa_a
├── kappa_b
├── link_gen
├── physical_interval
└── coupled_trajectory

R1OutputBinding
├── r1_block
├── link_out
├── target
└── measure_output_current()
```

或者至少把：

```python
link_out: R1OutputLink | None
```

设为可选，并明确它不参与 R1 身份成立。

否则会把“关系存在”和“关系已经取得输出能力”重新混在一起。

# 非阻塞一：`KappaTen` 的“十”到底指什么？

报告中的 `KappaTen` 包含：

* L1；
* HC；
* 10个 ensemble 神经元；
* collector。

这显然不是总共十个神经元，而是：

[
1+1+10+1
]

或更多实际组件。

因此必须明确：

[
\boxed{\text{“10”是核心ensemble数量，还是整个不可约结构的元件总数？}}
]

如果十神经元只是不可约核心，更准确的结构是：

```text
KappaTen
├── boundary_input：L1
├── ten_neuron_core：ensemble[10]
├── supporting_dynamics：HC
└── boundary_output：collector
```

这样可以说：

> (\kappa^{10}) 是以十神经元核心为最低功能主体、带输入输出边界与支持结构的基础生成元。

如果你坚持“不可约物理结构总共就是十个神经元”，那当前工程映射并不满足，需要重新界定哪些部件属于基元、哪些属于外部支撑。

这个问题不必阻塞下一步代码整理，但必须在理论定义中写清楚，否则以后计算尺度关系时，“一个基元包含多少结构”会不断漂移。

# 非阻塞二：当前区间只是两个时间字段，还不是物理区间

当前 `R1PhysicalInterval` 只有：

```text
s_enter
s_exit
```

这作为 X2a 占位是可以的。

但 X2d 不能只是给两个字段赋时间步数。真正的区间还需要回答：

```text
为什么进入？
为什么仍然属于同一关系过程？
为什么退出？
退出后残响是否仍归属原区间？
```

至少需要这样的状态：

[
\texttt{UNBOUND}
\rightarrow
\texttt{SUPPORTED}
\rightarrow
\texttt{RELAXING}
\rightarrow
\texttt{CLOSED}.
]

但这些状态不是事件状态机，而只是 R1 物理支撑区间的闭合条件：

* `enter`：生成链路首次获得两个父发生的共同支撑；
* `maintain`：父身份、链路身份和耦合支撑不变；
* `exit`：链路作用退出可响应带，或者父谱系改变；
* `closed`：后续残响不能再创建同一区间的新R1。

# X2b应怎样做？

报告下一步是把 `RelationOccurrence` 重新定位为 R1 时间投影。这个方向正确，但不要称“降格”，更准确的是：

[
\boxed{\text{重新定型。}}
]

它从原来的“完整关系本体”，改成：

> R1结构块的一次时间关系投影与谱系审计记录。

例如：

[
RelationOccurrence
==================

\Pi_\tau
\left(
\mathfrak R_{AB}^{(1)}
\right).
]

它仍然有价值，因为它记录：

* 哪两次 D1 发生参与；
* 检测到什么先后关系；
* 使用什么时间尺度；
* 什么关系 collector 产生了该投影。

但完整 R1 还应包含链路、物理区间和耦合轨迹。

输出边界：collector

正是把原来隐含的定义明确化，而不是临时更改原定义。

## 需要保留的一个细微区别

过去的文档里，**collector究竟算核心内部还是输出边界**曾经没有完全冻结；有一份数理重构稿还把“collector是否已包含在基础生成元内”列为待补问题。

现在可以正式解决这个歧义：

[
\boxed{
\begin{aligned}
\text{不可约功能核心}&=\text{ensemble中的十个神经元};\
\text{基础生成元整体}&=\text{核心}+\text{输入边界}+\text{支持动力学}+\text{输出边界};\
\text{collector}&=\text{属于生成元整体，但不是十神经元核心本身}.
\end{aligned}
}
]

这样“不可约”也要准确理解：

> 不可约的是这十神经元核心所实现的最低项目功能，而不是说 L1、HC、collector 都可以从实际运行结构中删除。

支持结构虽然不计入“10”，但它们是该基元当前物理实现的一部分。没有输入转导、维持动力学或输出收集，十神经元核心无法作为一个完整的项目生成元工作。

因此建议把正式定义冻结成：

[
\boxed{
\kappa_i^{10}
=============

\left(
B_i^{\mathrm{in}},
C_i^{10},
S_i^{\mathrm{dyn}},
B_i^{\mathrm{out}}
\right)
}
]

其中：

* (C_i^{10})：十神经元最低功能核心；
* (B_i^{\mathrm{in}})：输入边界；
* (S_i^{\mathrm{dyn}})：支持与维持动力学；
* (B_i^{\mathrm{out}})：输出边界。

一句话说：

[
\boxed{\text{“十”描述核心的最小功能规模，不描述整个物理装置的总元件数。}}
]

所以 X2a 的 `KappaTen` 方向没有违背当初定义，只需要在文档中明确写出这个区分，避免以后做尺度关系时把“核心规模”和“完整支撑规模”混为一谈。
