## 一、T2 的“方向关系”还需要重新收紧定义

当前写法是：

```text
ξ₁ ↔ ξ₂ ↔ ξ₃
每对相邻节点建立 a→b、b→a 传播路径和方向 Collector
```

问题在于：如果只是人为新建

[
\xi_a\rightarrow D_{a\to b},
\qquad
\xi_b\rightarrow D_{b\to a},
]

那么输出只能证明“哪一个源激活”，不能证明“发生从 (a) 传播到 (b)”。

换言之，不能因为把 Bundle 命名为 (a\to b)，它就自动成为方向关系。方向检测必须同时包含：

1. **结构邻接**：(a,b) 确实相邻；
2. **起点痕迹**：(\xi_a) 的活动沿 (a\to b) 支路传播；
3. **终点响应**：传播痕迹与 (\xi_b) 的当前活动在终点耦合。

更合理的最小结构是：

```text
ξₐ → a→b 传播中继/RC痕迹 ─┐
                           ├→ Dₐ→ᵦ Collector
ξᵦ ───────────────────────┘

ξᵦ → b→a 传播中继/RC痕迹 ─┐
                           ├→ Dᵦ→ₐ Collector
ξₐ ───────────────────────┘
```

即：

[
d_{a\to b}(t)
=============

\mathcal C
\left(
P_{a\to b}[\xi_a](t),
\xi_b(t)
\right).
]

这与 (r_{\prec}) 的区别在于：

* (r_{\prec}) 的历史支路不要求空间邻接；
* (r_{\rightarrow}) 的传播支路只存在于确定的邻接边上。

所以 T2 在编码前必须先单独出一份**方向关系电路定义报告**，明确“传播痕迹 + 终点耦合”，否则很容易退化成源身份检测。

## 二、T3 的共享抑制只能先称为“竞争参与度”，不能预设为比例

当前设想：

```text
ξₐ、ξᵦ → 总量池 → 共享抑制 → ρₐ、ρᵦ
```

使用：

[
\texttt{synapse_gain}=-1
]

产生的是**减法型抑制**。它不天然等价于数学上的除法归一化：

[
\rho_a
======

\frac{I_a}{I_a+I_b}.
]

例如若输出近似为：

[
y_a
===

\phi(I_a-\lambda I_\Sigma),
]

当两个输入共同放大为 (\alpha I_a,\alpha I_b) 时：

[
y_a'
====

\phi!\left(
\alpha I_a-\lambda\alpha I_\Sigma
\right),
]

输出可能整体增大、饱和或归零，并不保证共同尺度不变。

因此 T3 的第一版验收目标应分成两级。

### 一级：必须达到

* 较大输入对应较大输出；
* 交换输入后输出交换；
* 单输入时对应通道占优；
* 等强输入时输出近似相等；
* 静默时无虚假占比。

### 二级：实验性目标

* 共同放大时排序保持；
* 输出差异对共同尺度相对稳定；
* 多通道竞争后近似形成归一化；
* 输出总量的变动处在有限范围内。

在没有实测证明前，建议工程对象命名为：

[
r_{\mathrm{part}}
]

或在报告中称：

[
\boxed{\text{参与竞争关系原型}}
]

只有达到共同尺度近似不变以后，才正式升格为：

[
r_\rho.
]

这不是否定占比生成元，而是避免把一个尚未证明的减法竞争电路提前解释成除法器。

## 三、census 隔离必须增加“关系层独立账本”

文档继续采用：

* 新神经元排除 `get_all_neurons()`；
* 新 Bundle 纳入 `get_all_bundles()`。

这对保护现有 T4.1 回归是合理的，已有工程也使用过相同策略。但基础关系生成元一旦增多，仅统计 Bundle 而长期不统计其神经元，会产生物理账本缺口：

[
E_{\mathrm{relation}}
=====================

E_{\mathrm{bundles}}
+
E_{\mathrm{neurons}},
]

而现阶段全局系统只看见前一部分。

所以 Phase 0 应增加独立接口或测试统计，不必立刻进入原全局 census，但至少报告：

* 关系中继神经元数量；
* 关系 Collector 数量；
* 每步膜积分调用次数；
* 峰值功率或近似能耗；
* 新 Bundle 数量；
* 相对原系统的运行成本增量。

可以命名为：

```text
get_relation_generator_neurons()
get_relation_generator_bundles()
```

如果不适合新增公开方法，也可以先在专项测试中按保存容器直接统计。

重要的是明确：

[
\boxed{
\text{排除全局 census 是暂时隔离，不是无能耗}
}
]

Phase 4 应把关系层独立账本列为强制验收项。

## 四、还需要补充两个较小约束

### 1. Frozen 权重不能默认顶到物理上限

文档规定：

```text
initial_weight == weight_max
```

这个条件只表示权重不会从初始值向上漂移，不意味着应使用：

```text
initial_weight = weight_max = 1.0
```

此前感温链路已经出现过 (w=1) 附近与随机扰动、PowerRail 饱和相撞的问题。应写成：

[
0<w_0=w_{\max}<1,
]

第一轮建议从明显低于饱和边界的范围扫描，例如：

[
w_0\in[0.1,0.5].
]

具体值仍由实测电流和 RC 充电时间决定。

### 2. T0 选点结果必须冻结保存

T0 可以利用球面点坐标选出局部邻接，但选定后要保存明确的：

* 点索引；
* warm/cool 极性；
* 邻接边；
* 选点理由；
* 输入峰值与爆发周期。

后续 T1～T4 只能读取已经冻结的索引和边，不能每次初始化重新动态搜索最近邻，否则不同运行可能得到不同测试支撑，影响可重复性。

# 五、推荐的最终门控结构

在现有 v2 基础上补充三个预实施关卡：

```text
共同总纲
    │
    ▼
Gate A：T0 真实源与固定邻接核实
    │
    ▼
Gate B：T1 时间关系电路定义
    │
    ▼
Gate C：T2 方向传播—终点耦合定义
    │
    ▼
Gate D：T3 竞争参与度可否达到占比近似
    │
    ▼
T4 并行集成
```

其中：

* T1 可以直接按当前方案进入设计；
* T2 必须先解决“方向不是 Bundle 名称”的问题；
* T3 必须先验证共享抑制到底产生竞争度还是比例；
* T4 才决定二者是否达到基础方向生成元和基础占比生成元的资格。
