总体判断：

[
\boxed{\text{旧构建目前处理得基本合理；当前R1b仍沿着主线前进，没有再次明显拐入旧路。}}
]

但这成立有一个前提：**R1b完成最小物理门后必须立即停止，不得顺手重构 `occurrence.py` 或继续扩展生理机制。**

## 一、旧构建是否被合理处理？

### 已经处理正确的部分

**1. 没有删除旧资产，也没有继续把它们冒充通用算子。**

T1/T2保留为特定工作区中的关系原型；T3则明确冻结为失败反例：

* 拓扑和父发生链存在；
* AND资格不成立；
* 失败权重已撤回；
* 不再继续调参。

这比“强行把测试调到PASS”合理得多。

**2. 已经找到并截断了旧构建最重要的污染入口。**

旧RPrec直接读取：

[
collector.pre_trace,
]

导致发生身份、发火强度、站点增益和历史残留混在一起。R0建立：

[
p_\alpha(t)
===========

# \texttt{CollectorBoundaryPort.spike_output}

collector.activation(t),
]

并证明它不依赖Occurrence、Closure或站点名称才存在。

这意味着后续新算子不必继承旧RPrec的模拟幅值依赖。

**3. `Occurrence`的因果位置已经修正。**

当前被冻结的是：

[
Occurrence=\mathcal A[p_\alpha],
]

而不是：

[
p_\alpha=\mathcal B[Occurrence].
]

因此没有再从后验软件记录反向重建实时过程。这是旧构建处理中最重要的一次纠偏。

**4. 错误的尺度资格已经撤销。**

旧 (\Lambda) 被降格为嵌套支撑集合读出，没有继续把“输入更多”当成尺度转换。这也避免了旧结果被后续方向或耦合生成元错误消费。

### 尚未解决，但已经被隔离的旧问题

以下问题还存在于代码中：

* T1/T2/T3仍读取 `pre_trace`；
* `generator_sigma.py` 和旧 (\Lambda) 资产仍有连续幅值读取；
* `occurrence.py` 仍使用软件计步的双时钟；
* 旧测试仍不等于新的统一算子资格测试。

但这不等于必须马上重构它们。

目前合理的处理方式是：

[
\boxed{\text{保留旧资产、冻结资格、禁止新主线依赖它们。}}
]

只有在新接口稳定后，才决定哪些旧模块迁移、降级或彻底退出。现在贸然统一修改旧代码，反而会重新扩大回归面。

# 二、当前R1a/R1b是否偏离方案？

目前的路径是：

[
\text{R0实时脉冲端口}
\rightarrow
\text{R1a首次进入边界定义}
\rightarrow
\text{R1b首次进入边界的物理实现}.
]

这条路径是连贯的。

## 为什么R1a不是无关支路？

第一次标定 (H_\tau) 时发现，持续驱动下site28会重复发火：

[
p_{28}(t)={384,507,635,778,\ldots}.
]

因此原探针测到的不是一次发生的衰减核，而是重复脉冲不断充电的复合响应。

这迫使项目先回答：

> 时间算子测量的是每一枚spike，还是一次持续发生的首次进入？

裁定为首次进入边界后，R1a建立：

[
\mathcal E^\uparrow:
p_\alpha(t)\mapsto b_\alpha^\uparrow(t).
]

这是统一时间算子的输入定义，不是额外功能。

## 为什么R1b也不是无关支路？

项目要求生成算子必须由物理结构实现，而R1a的三态Python状态机虽然实时，却仍然是软件过程变换。

因此审计：

[
\mathcal E^\uparrow
]

能否由Capacitor、MOSFET和泄漏恢复承载，是R1a之后的直接必需步骤。R1b找到已有物理原语可支持“首次通过、重复抑制、静默恢复”，并发现 `rearm_min_steps` 的双时钟债务。

这仍属于：

[
\boxed{\text{把统一时间算子的输入从软件规则落到物理载体。}}
]

不是离题。

## 刚刚对方案的修正是否必要？

必要。

原方案让被抑制的重复脉冲不再给电容充电，这会使门测量：

[
\text{自首次脉冲以来的时间},
]

而正确需求是：

[
\text{自最近一次脉冲以来的静默时间}.
]

所以必须改为每枚脉冲刷新、但有限饱和的可重触发RC门。这个修正是为了使物理实现真正等价于“同一持续发生只输出一次”，不是另外开辟了新研究方向。

## 风险2：继续研究更多生理机制

当前已经有足够的项目内物理先例：

本轮不需要继续比较更多离子通道，也不需要为双时钟搜索文献。只需实现最小单时钟门。

## 风险3：反复精调物理门参数
