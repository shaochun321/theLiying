# 一、唯一阻塞：P2-A1 当前混合了两种不同标定

报告把 P2-A1 定义为：

[
u_i^{\mathrm{model}}
====================

\kappa_i q_i^{\mathrm{skin}}
]

的量纲、增益与工作区间标定；但 P2-A2 才会建立三节点动态皮肤和真实的：

[
q_i^{\mathrm{skin}}(t).
]

也就是说，当前顺序是：

[
P2\text{-A1：标定 }\kappa q_{\mathrm{skin}}
\rightarrow
P2\text{-A2：建立 }q_{\mathrm{skin}}.
]

这在逻辑上倒置了。总纲与报告目前都保持了这一顺序。 

应把 P2-A1 拆成两部分。

## P2-A1a：生成元核心输入包络

只使用 `BaseGenerator.feed()`，扫描生成元端口 (u)：

[
u
\mapsto
\left(
L_{\mathrm{first}},
N_{\mathrm{occ}},
f_{\mathrm{occ}},
t_{\mathrm{down}},
t_{\mathrm{rearm}},
S_{\mathrm{sat}}
\right).
]

得到：

[
u_{\mathrm{silent}},
u_{\mathrm{on}},
u_{\mathrm{work}},
u_{\mathrm{sat}},
u_{\mathrm{unsafe}}.
]

这一阶段不讨论：

[
q_{\mathrm{skin}},
\qquad
\kappa,
\qquad
\text{皮肤传播}.
]

它回答的只是：

> 十神经元生成元本身能够消费什么范围的输入？

## P2-A2：三点动态皮肤与转导接口

建立：

[
s_1-s_2-s_3
]

以及：

[
q_i^{\mathrm{skin}}
\xrightarrow{\mathcal D_i^{\mathrm{sim}}}
u_i.
]

此时才第一次得到实际皮肤输出的幅值、时间尺度和分布。

## P2-A1b：皮肤—生成元接口标定

再确定：

[
u_i=\kappa_i q_i^{\mathrm{skin}}
]

中的：

[
\kappa_i,
\quad
\text{offset},
\quad
\text{clipping},
\quad
\theta_\uparrow,
\quad
\theta_\downarrow,
\quad
t_{\mathrm{rearm}}.
]

并验证实际皮肤输出主要落在：

[
u_{\mathrm{work}}
]

而不是静默区或饱和区。

因此下一步应调整为：

[
\boxed{
P2\text{-A1a}
\rightarrow
P2\text{-A2}
\rightarrow
P2\text{-A1b}
\rightarrow
P2\text{-A3}.
}
]

这是当前唯一需要立即修改的执行顺序。

# 二、非阻塞一：`Occurrence` 是完成记录，不是实时耦合信号

当前 `Occurrence` 只有在：

[
t_{\mathrm{rearm}}
]

确定以后才能完整产生，因为它需要同时携带：

[
(t_\uparrow,t_\downarrow,t_{\mathrm{rearm}}).
]

因此它本质上是：

[
\boxed{\text{一次发生完成后的回顾记录。}}
]

这对：

* 计数；
* 窗口切片；
* 地址审计；
* 离线自然化候选分析；

都没有问题。

但 P2-B 若直接等待完整 `Occurrence`，关系结构只能在基础发生已经结束并恢复后才收到输入。这不适合在线关系耦合。

应在进入 P2-B 前拆成两类输出。

## 在线结构信号

由状态机实时产生：

[
\xi_i^\uparrow(t),
\qquad
\xi_i^\downarrow(t),
\qquad
\xi_i^{\mathrm{rearm}}(t),
]

或直接暴露只读状态：

[
s_i(t)\in
{
\mathrm{ARMED},
\mathrm{ACTIVE},
\mathrm{REFRACTORY}
}.
]

关系原语的活动迹：

[
z_i^\tau=h_\tau*\xi_i^\uparrow
]

可以在发生开始时立即形成。

## 完成记录

继续保留：

[
\chi_i=
(t_\uparrow,t_\downarrow,t_{\mathrm{rearm}},
1,\alpha_i).
]

它用于发生完成后的轨迹聚合和审计。

因此：

[
\boxed{
\text{在线耦合使用状态转换流，}
\quad
\text{完整 Occurrence 用于回顾记录。}
}
]

不必现在修改 P2-A1，但必须在 P2-B0 前明确。

# 三、非阻塞二：双驱动互斥目前只是文档约定

报告已经明确：

[
\texttt{BaseGenerator.feed()/tick()}
]

与：

[
\texttt{circuit.step()}
]

不能同时驱动同一批神经元，否则每一步会被输入两次。

目前这只是 docstring 警告。对实验代码可能够用，但随着 P2-A2 接入动态皮肤，它会变成容易发生的隐蔽错误。

建议增加生成元驱动所有权：

[
m_i\in
{
\mathrm{MANUAL_CALIBRATION},
\mathrm{WORLD_COUPLED}
}.
]

运行期冻结：

[
m_i(t)=m_i(0).
]

若同一实例已经由 `feed()` 驱动，再被 `circuit.step()` 驱动，则直接拒绝，而不是依赖调用者记住文档。

轨迹中也应记录：

[
\mathrm{driver_mode}
]

以及必要的源谱系，防止以后把合成输入标定轨迹和世界耦合轨迹混为同类证据。

这不是 P2-A1a 的阻塞，但应在 P2-A2 接通世界皮肤链路时完成。

# 四、报告没有暴露的严重问题

以下部分目前没有必要改：

### `Occurrence` 不携带自然单位字段

正确。继续保持：

[
\chi\neq\mathfrak n.
]

### 独立 `GeneratorTrajectory`

正确。因为手动输入路径和世界联合调度路径确实不同，不应强行复用一份轨迹类型。

### 地址接入

当前可以保留。但应继续遵守：

[
\boxed{
\text{地址用于审计谱系，不能成为关系层判断输入身份的运行标签。}
}
]

关系层辨识度应来自不同实际输入端口和结构边。

### P2-B/P2-C 的理论修订

现在不需要因此暂停 P2-A。总纲中的 P2-B/P2-C 表述确实偏旧，但可在 P2-A 完成后、进入 P2-B 前更新；它不会影响当前的工作区间和三点皮肤构建。
