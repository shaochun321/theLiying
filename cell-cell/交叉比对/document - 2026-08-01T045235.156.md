这版可以把 **X2a′、X2b、X2d 视为基本完成**。它已经正确分开：

[
I_{R1}\neq W_Y^\star,
]

并修复了 `collector_address` 与 `generation_link_address` 的混用。现在 X2c 的形式基础已经存在。

但在正式执行 X2c 前，我认为 X2d 还有一个必须补的小机制。

# 阻塞：`RELAXING`必须允许回到`SUPPORTED`

当前状态机是单向的：

```text
UNBOUND → SUPPORTED → RELAXING → CLOSED
```

这不完全符合你刚才确定的区间理念。

真实耗散结构中，collector或trace可能因为振荡、混沌、相位错开，短暂退出响应带，然后又重新进入。如果父实例和生成链路都没有改变，这应当仍然属于**同一个R1物理区间**，而不是一次新的关系。

当前逻辑中，一旦进入 `RELAXING`，就再也不能恢复为 `SUPPORTED`。这可能造成：

* 同一关系过程被过早判定进入结束阶段；
* 重新取得物理支撑的活动无法重新归入原关系；
* 区间无法真正包容振荡和间歇耦合；
* 后续 (W_Y^\star) 对自然波动过于敏感。

建议状态机改成：

```text
UNBOUND
    ↓
SUPPORTED ⇄ RELAXING
                 ↓
               CLOSED
```

其中：

[
\boxed{
\texttt{RELAXING}\rightarrow\texttt{SUPPORTED}
}
]

只有在以下条件同时满足时允许：

1. 父A、父B的epoch没有改变；
2. `generation_link_address`没有改变；
3. 两父物理支撑重新进入响应带；
4. relation collector重新进入响应带；
5. 尚未满足正式关闭条件。

如果父epoch已经变化，则旧区间不能恢复：

[
\text{parent epoch changed}
\quad\Rightarrow\quad
\text{旧区间只允许继续衰减并关闭}.
]

可以增加：

```python
lineage_broken: bool
```

一旦为真，禁止 `RELAXING → SUPPORTED`。

# 阈值必须有迟滞和持续条件

现在报告描述的是：

[
support>\theta,\qquad collector>\theta.
]

如果进入和退出使用同一个阈值，一点数值抖动就会反复切换状态。

建议至少区分：

[
\theta_{\mathrm{on}}>\theta_{\mathrm{off}}.
]

## 进入

[
support_a>\theta_{a,\mathrm{on}},
\quad
support_b>\theta_{b,\mathrm{on}},
\quad
collector>\theta_{c,\mathrm{on}}.
]

并持续 (m_{\mathrm{on}}) 个采样步。

## 进入RELAXING

不是单个采样点低于阈值，而是：

[
support<\theta_{\mathrm{off}}
]

或：

[
collector<\theta_{c,\mathrm{off}}
]

持续 (m_{\mathrm{off}}) 步。

## 正式关闭

要求trace和collector同时回到基线带，并维持：

[
m_{\mathrm{close}}
]

个连续采样步：

[
|trace-\mu_{\mathrm{trace},0}|
\leq\delta_{\mathrm{trace}},
]

[
|collector-\mu_{\mathrm{collector},0}|
\leq\delta_{\mathrm{collector}}.
]

这样“区间”才真正表示：

> 在允许的耗散振荡和短暂失配下，仍保持同一谱系的最大物理过程范围。

# 建议再增加一个候选起点

当前 `s_enter` 要求两个父支撑和relation collector都已经越过阈值。

这表示的是：

[
\text{R1正式形成时刻}.
]

但在collector响应之前，生成链路可能已经开始积累trace和共同支撑。建议额外保留：

```text
s_candidate
```

定义为：

> 两个父发生第一次同时开始支撑 (\ell_{\rm gen}) 的时刻。

于是：

[
s_{\mathrm{candidate}}
\leq
s_{\mathrm{enter}}
\leq
s_{\mathrm{support_end}}
\leq
s_{\mathrm{closed}}.
]

它们分别表示：

| 字段              | 含义          |
| --------------- | ----------- |
| `s_candidate`   | 关系生成过程开始积累  |
| `s_enter`       | R1取得成立资格    |
| `s_support_end` | 主共同支撑解除     |
| `s_closed`      | 残响结束、区间正式关闭 |

这不会影响当前X2c，但以后研究“关系是怎样形成的”会很重要。

# 非阻塞一：(W_Y^\star)的终点也要使用稳定基线

报告目前按“Y最后一个超阈值步骤的下一步”确定终点。

对混沌或噪声轨迹，单次微小尖峰可能把窗口拖得很长。更稳妥的定义是：

[
s_{\mathrm{end}}^Y
==================

\inf
\left{
s:
|Y(s:s+m_Y)-\mu_{Y,0}|
\leq\delta_Y
\right}.
]

即：

> Y进入基线带，并连续保持 (m_Y) 步后的第一个时刻。

基线带应由空条件重复运行得到：

[
\mu_{Y,0},\qquad \sigma_{Y,0}.
]

例如：

[
\delta_Y=k\sigma_{Y,0}+\varepsilon_{\mathrm{num}}.
]

不能只用绝对固定阈值。

# 非阻塞二：切断链路不能只修改`weight_max`

报告计划通过：

```python
bundle.weight_max = 0.0
```

切断 (\ell_{\rm gen}) 或 (\ell_{\rm out})。

执行X2c时必须确认：

* 当前实际权重是否立即变成零；
* 是否仍存在残余电流；
* STDP或其他更新是否会重新写回；
* `propagate()`是否真的读取`weight_max`而不是当前weight；
* 切断前后除这条链路外，其他状态完全一致。

更安全的是增加实验专用的物理门：

```python
bundle.transmission_enabled = False
```

或在 `propagate()` 中施加：

[
I_{\mathrm{out}}
================

g_{\mathrm{cut}},
I_{\mathrm{raw}},
\qquad
g_{\mathrm{cut}}\in{0,1}.
]

这样“切断”只改变传输能力，不改变学习上限、历史权重或其他动力学参数。

无论采用哪种方法，都应增加断言：

[
\max_s
\left|
I_{\mathrm{cut}}(s)
\right|
\leq
\varepsilon_{\mathrm{num}}.
]
