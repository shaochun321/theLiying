## 评判结论

这轮 P1-B1.5 可以通过，而且不是表面修补。

它关闭了两个已经代码复现的真实漏洞：

* `capacitor.charge` 是相对节点环境基线的有符号偏差，不是绝对热能；负 charge 原先会使传输功率变负、实际供受体翻转；
* (a_e\Delta t>1) 原先会把 tail 从正值直接更新成负值。

现在通过：

[
u_i^+=\max(q_i,0),
\qquad
p_e=a_eu_i^+,
]

以及：

[
a_e\Delta t\leq1
]

的执行前稳定性门，已经保证单边传输非负、身份不翻转、失稳时零副作用。基线不一致、自环、负数、NaN、无穷参数也都受到拒绝，13 项专项测试和 21/21 回归通过。 

因此当前状态应表述为：

[
\boxed{
\text{单条有序过剩热能转移边已经成立；}
\text{多边联合更新尚未成立。}
}
]

# 一、这轮修复后的物理语义已经基本准确

现在组件不再声称搬运：

* 完整热力学内能；
* 介质质量；
* 真实平流；
* 空间方向。

它搬运的是：

[
\boxed{
\text{共同环境参考基线以上的规范化过剩热状态。}
}
]

而且明确登记了：

```text
transport_drive_mode = "exogenous_normalized"
```

说明驱动此转移的机械功、压力差、介质动量和熵增尚未进入模型，因此只能宣称热状态在两个节点之间守恒，不能宣称完整热力学过程闭合。

这是一个很重要的收敛点。P1-B 不再偷偷承担“方向”或“真实流体”的任务。

# 二、进入 B2 前仍有一个命名契约矛盾

P1-A 的有序边机制目前仍使用：

```text
medium-transport
```

但 B1.5 已经明确否认当前机制是介质传输或平流。

因此地址注册表中的机制类型也应同步收紧。否则会出现：

* 组件称“有序过剩热能转移”；
* 地址和拓扑账本却称“介质传输”。

建议在进入 B2 前，将机制标识改成：

```text
ordered-excess-thermal-transfer
```

或者稍短一些：

```text
ordered-thermal-transfer
```

不要继续使用：

```text
medium-transport
```

因为地址机制名称不是普通注释，它会进入：

* 域兼容性检查；
* 边身份；
* 账本追踪；
* 后续 `GeneratedAddress.parent_addresses`；
* P2-C 的关系父支撑。

现在改成本低；等 P2 回接后再改，会造成地址谱系迁移。

# 三、基线一致性不应长期停留在浮点数精确相等

当前实现检查：

```python
tail_cell.ambient_temperature == head_cell.ambient_temperature
```

作为单边安全门是有效的，也足以完成 B1.5。

但 B2 出现多条边后，更合理的契约不是“每条边临时比较两个浮点数”，而是整个有序传输连通分量共享同一个热参考基线。

建议给计划层增加：

```text
thermal_reference
```

它可以首轮只是一个不可变记录：

```text
ThermalReference(
    reference_id,
    ambient_temperature
)
```

所有参与同一个 `ThermalTransportPlan` 的节点必须具有：

[
\text{reference_id}_i
=====================

\text{reference_id}_j.
]

这样能区分：

1. 两个节点碰巧拥有相同数值；
2. 两个节点明确属于同一个热参考体系。

这不是建设坐标，也不是新物理机制，只是把“相同零点”从浮点比较提升为结构契约。

最低限度也应使用严格容差比较并验证数值有限，而不是依赖裸 `==`。不过从长期地址体系看，显式 `reference_id` 更一致。

# 五、下一步应正式进入 P1-B2

B2 不再只是“测试两条边”，其核心交付物应是：

[
\boxed{
\text{从同一物理快照生成不可变多边转移计划。}
}
]

## 1. `ThermalTransportPlan` 的最小字段

建议包含：

```text
plan_id
dt
thermal_reference_id
registry_revision
topology_revision
state_revision

edge_transfers
node_outgoing_totals
node_incoming_totals
node_net_deltas

stability_report
ledger_preview
```

每条 `edge_transfer` 至少包含：

```text
edge_identity
tail_address
head_address
tail_energy_snapshot
rate_per_time
power
delta_energy
```

其中：

[
p_e=a_eu_{\operatorname{tail}}^+,
]

[
\Delta u_e=p_e\Delta t.
]

## 2. `prepare_thermal_transport_plan()`

这一阶段只能读，不能写。

严格顺序：

1. 验证所有节点和边地址仍是当前版本；
2. 验证所有有序边机制类型正确；
3. 验证没有自环和重复边；
4. 验证所有节点共享热参考；
5. 一次性拍摄所有 tail 的 charge 快照；
6. 从快照计算每条边的 (u_i^+)；
7. 计算每条边功率和单步能量；
8. 按 tail 汇总全部出流率；
9. 验证：
   [
   \Delta t\sum_{e:\operatorname{tail}(e)=i}a_e\leq1;
   ]
10. 生成节点净变化和边级账本预览；
11. 返回不可变计划。

## 3. 同源多边必须共享同一快照

对于：

[
i\to j,
\qquad
i\to k,
]

必须得到：

[
\Delta u_{ij}
=============

a_{ij}u_i^{+,n}\Delta t,
]

[
\Delta u_{ik}
=============

a_{ik}u_i^{+,n}\Delta t.
]

而不是第二条边读取第一条边扣除后的状态。

因此应强制验证：

* 边列表正序；
* 边列表逆序；
* 随机固定重排；

三种情况下生成的计划完全相同，只允许记录顺序不同，不允许边值和节点汇总不同。

# 六、B2 的稳定门不能只逐边检查

单条边分别满足：

[
a_1\Delta t\leq1,
\qquad
a_2\Delta t\leq1
]

并不能保证共享 tail 的组合稳定。

例如：

[
a_1\Delta t=0.7,
\qquad
a_2\Delta t=0.7.
]

每条单独都通过，但总出流是：

[
(a_1+a_2)\Delta t=1.4>1.
]

所以 B2 必须验证：

[
\boxed{
\eta_i^{transport}
==================

\Delta t
\sum_{e:\operatorname{tail}(e)=i}a_e
\leq1.
}
]

这是 P1-B2 自己的稳定性门。

完整的：

[
\eta_i^{joint}
==============

\Delta t
\left[
\frac{
\sum_j\kappa_{ij}
+
\sum_sH_{is}
+
G_i^{env}
}{C_i}
+
\sum_ea_e
\right]
\leq1
]

留到 P1-C，因为 B2 尚不接扩散、皮肤和环境泄漏。V3 已经正确修正了：

[
G_i^{env}=\frac1{r_{\mathrm{leak,ambient}}}.
]

# 七、B2 验收建议

建议 P1-B2 至少覆盖以下项目。

## 计划纯只读

调用 `prepare` 前后：

[
q_i^{after}=q_i^{before}.
]

## 两边共享 tail

验证两条边都基于相同 tail 快照。

## 遍历顺序不变

边注册顺序、输入列表顺序、地址解析顺序改变后，计划的规范化结果一致。

## 组合失稳拒绝

两条边分别稳定、总和失稳：

[
a_1\Delta t<1,
\qquad
a_2\Delta t<1,
\qquad
(a_1+a_2)\Delta t>1.
]

`prepare` 必须拒绝，并且状态不变。

## 零或负过剩状态

某个 tail：

[
q_i\leq0.
]

它的所有有序出边均应：

[
p_e=0.
]

## 多 tail 独立汇总

验证两个不同 tail 的预算不会被错误合并。

## 地址和拓扑错误

* stale 节点地址；
* stale 边版本；
* 未注册端点；
* 重复边；
* 错误机制类型；
* 不同热参考。

全部必须在计划生成阶段拒绝。

## 计划账本闭合

对所有有序边：

[
\sum_e
\left(
-\Delta u_e+\Delta u_e
\right)
=0.
]

对节点汇总：

[
\sum_i\Delta u_i^{transport}=0.
]

# 八、P1-B3 应只处理提交与故障语义

B2 通过后，B3 才实现：

```text
apply_thermal_transport_plan(plan)
```

B3 不应重新计算功率、重新查边或重新判断基线，否则计划就失去了冻结意义。

提交前只检查：

* `plan` 未使用；
* registry revision 未改变；
* topology revision 未改变；
* state revision 未改变；
* 地址和边版本仍与计划一致。

随后应用计划中的既定节点净变化。

## 必须拒绝的情况

* plan 生成后某个节点状态被其他过程修改；
* plan 生成后节点重建；
* plan 生成后边被删除或换版本；
* 同一 plan 第二次提交；
* plan 应用于另一个图；
* `dt` 或热参考不匹配。

所有拒绝：

[
\Delta q_i=0.
]

## 意外提交异常

必须二选一并在报告中明确：

### 方案 A：证明提交区不会抛出可预见异常

所有数值和目标都已验证，提交只执行基础写入。

### 方案 B：保存提交前 charge 快照并回滚

若中途异常，则恢复所有已写节点。

不应使用：

> 理论上不会出错。

作为故障语义。
