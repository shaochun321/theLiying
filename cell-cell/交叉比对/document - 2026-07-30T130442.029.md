# P2-B1X1c 应实现的三个生产对象

## `RelationDraft`

在真实关系 collector 越过检测边界时创建，保存：

[
\begin{aligned}
&\text{relation type};\
&\text{A、B的generator address与epoch id};\
&\text{collector address};\
&\text{fast/slow尺度};\
& t_{\rm detect};\
&\text{候选关系窗口}.
\end{aligned}
]

此时父 occurrence 可能尚未 rearm，因此只保存在线实例键：

[
(\operatorname{GeneratorAddress},\operatorname{EpochID}).
]

## `RelationOccurrence`

当 A、B 两个父实例都能由 registry 解析后完成：

[
\rho_k^{(2)}
============

\left(
\operatorname{RelationType},
u_{A,i}^{(1)},
u_{B,j}^{(1)},
W_{\rho,k},
\operatorname{CollectorAddr},
\operatorname{Scale},
\operatorname{Lineage},
\operatorname{ClosureStatus}
\right).
]

## `RelationFinalizer`

负责监听：

* 新 relation draft；
* 新完成的 D1 occurrence；
* registry 更新；

满足条件时自动把 draft 转成正式关系实例。

# 必须保持的语义边界

关系实例的成立不能依赖 DA：

[
\boxed{
DA=0
\quad\text{仍然必须生成}\quad
\rho_{A\prec B}^{\rm obs}.
}
]

应当分开：

[
\begin{aligned}
\rho^{\rm obs}
&=\text{实际观察到的关系};\
e^{\rm elig}
&=\text{关系活动留下的学习资格};\
\Delta w^{\rm DA}
&=\text{DA门控后的结构沉积}.
\end{aligned}
]

P2-B1R 所证明的局部作用资格属于关系载体类型，不是每个 `RelationOccurrence` 成立的必填条件。

# 一个非阻塞设计提醒

`RelationDraft` 的创建最好读取**关系 collector 的上升转换**，而不是每个活动步都创建一次。

应有类似：

[
C_\rho^\uparrow
\rightarrow
\text{new draft},
]

而不是：

[
C_\rho(t)>0
\rightarrow
\text{每步创建draft}.
]

否则一次持续的关系 collector 活动可能制造大量重复关系实例。
