这份设计总体方向正确，尤其是先检查地基、避免再次用测试手工拼地址。但有一个关键修正：

[
\boxed{\text{地基1还不能判定为完全完成。}}
]

`Occurrence` 增加了 `epoch_id`，但所有 occurrence 仍共享生成元地址；而 `naturalize()` 又没有携带 `epoch_id`。所以当前只是能够区分实例，还没有形成真正可被 D2 使用的 **D1 实例身份／实例地址**。

# 一、四个开放问题的裁定

## 1. 地基2选择方案乙

[
\boxed{\text{采用方案乙：在现有物理通路上外挂只读的 OccurrenceClosure。}}
]

不使用 `wrap_base_generator()` 再次驱动通路。

原因很明确：

* `VariantCircuit.step()` 已经真实驱动 L1、HC、ensemble 和 collector；
* 再调用 `BaseGenerator.tick()` 会使同一路径每步被驱动两次；
* 双重驱动不仅是实现问题，还会改变原来已经取得资格的 D0→D1 动力学；
* `OccurrenceClosure` 本来就是读取既有 `collector.pre_trace` 的记账层，单独外挂符合其设计定位。

但建议不要直接把它写成 `RPrecCircuitT1` 内部随意创建的两个 closure，而是建立一个明确的观察适配器，例如：

```text
CollectorOccurrenceTap
```

它只拥有：

* collector 引用；
* 对应 L1 引用；
* `OccurrenceClosure`；
* D1 地址；
* 在线 transition 输出；
* occurrence 完成输出。

它不拥有也不执行物理驱动权。

---

## 2. `phys_support` 必须使用同一条 L1 门控

[
\boxed{
phys_support
============

(\text{对应 L1.activation}>0)
}
]

直接引用母本已有的：

```text
thermal_quantum_l1_warm[site]
```

是合理方案。

不能改成：

* collector 是否激活；
* HC 是否仍有慢态；
* `pre_trace > 0`；
* 固定 `True`。

因为 `phys_support` 的作用正是区分：

[
\text{真实外部支持}
\quad\text{与}\quad
\text{内部慢态残留}.
]

如果使用 collector 自身作为物理支持，它会再次允许内部长尾给自己续命。

因此链路应明确为：

[
D_{-1}/D_0\text{物理输入}
\rightarrow
L1
\rightarrow
HC/ensemble/collector,
]

而 closure 同时读取：

[
\left(
collector.pre_trace,
L1.activation>0
\right).
]

这是测量，不是第二次驱动。

---

## 3. 第一版复用现有参数，不独立重新标定

当前不建议专门为 `RPrecCircuitT1` 建立另一套：

[
\theta_\uparrow,\quad
\theta_\downarrow,\quad
T_{\rm rearm}.
]

因为它读取的是与基础生成元相同类型、甚至同一个实例的 warm collector 和 L1 通路。

若为关系电路重新标定，就会出现：

> 同一次物理通路，在 BaseGenerator 看来是一个 occurrence，在 RPrecCircuitT1 看来却是另一种 occurrence。

这会制造两套 D1 语义。

因此第一版应：

[
\boxed{\text{严格复用冻结的 OccurrenceClosure 默认参数。}}
]

不过需要增加一个**等价性测试**：

在相同真实输入、相同 collector、相同 L1 门控下：

[
\operatorname{Occurrence}_{\rm BaseGen}
=======================================

\operatorname{Occurrence}_{\rm Tap}
]

至少比较：

* epoch 数量；
* (t_\uparrow)；
* (t_\downarrow)；
* (t_{\rm rearm})；
* 撤去输入后是否产生伪 occurrence。

如果等价性失败，先查调用时序和重复读取，不应立刻重新标定。

# 二、地基1真正缺失的是什么？

目前新增：

```python
address: GeneratedAddress
epoch_id: int
```

因此实例身份实际上是：

[
(\operatorname{address},\operatorname{epoch_id}).
]

这可以作为最小身份键，但不能继续把 `address` 单独叫 occurrence 地址。

建议明确新增一个有类型对象：

```python
@dataclass(frozen=True)
class OccurrenceInstanceId:
    generator_address: GeneratedAddress
    epoch_id: int
```

然后：

```python
@dataclass(frozen=True)
class Occurrence:
    ...
    instance_id: OccurrenceInstanceId
```

或者在保持现有字段的情况下提供：

```python
@property
def instance_id(self) -> OccurrenceInstanceId:
    ...
```

这样不会马上重构全部地址系统，但明确规定：

[
\boxed{\text{D1实例身份是“生成元地址＋epoch”，不是生成元地址本身。}}
]

# 三、NaturalUnit 也必须携带实例身份

报告认为 `naturalize()` 不读取 `epoch_id`，所以暂时无需修改。对于已有测试确实如此；但对于 P2-B1X1 的目标，这一点必须修改。

否则两个不同 occurrence：

[
u_{A,17}^{(1)},
\qquad
u_{A,18}^{(1)}
]

自然化以后仍然无法区分。

因此 `NaturalUnit` 至少需要携带：

```text
source_occurrence_instance_id
```

或具有由该实例身份确定生成的地址。

正确谱系应是：

[
\boxed{
\operatorname{RelationOccurrence}^{(2)}
\rightarrow
\operatorname{NaturalUnitInstance}^{(1)}
\rightarrow
\operatorname{OccurrenceInstance}^{(1)}
\rightarrow
\operatorname{Generator}^{(1)}
\rightarrow
D_0/D_{-1}.
}
]

不一定要求 RelationOccurrence 同时保存这四层的全部字段，但必须可沿地址还原。

因此地基1应改判为：

[
\boxed{\text{epoch传播已完成；实例身份闭合尚未完成。}}
]

# 四、运行时顺序必须冻结

方案乙要成为真实在线闭环，而不是另一个测试夹具，关键在调用顺序。

建议每一步固定为：

[
\boxed{
\begin{aligned}
1.&\quad circuit.step()
&&\text{实际驱动物理通路};\
2.&\quad occurrence_tap.update()
&&\text{读取collector与L1，产生D1 transition};\
3.&\quad relation_circuit.step()
&&\text{根据真实trace检测关系};\
4.&\quad relation_draft.update()
&&\text{用当前epoch身份创建或更新draft};\
5.&\quad registry.register()
&&\text{D1闭合后登记正式实例};\
6.&\quad relation_finalizer.update()
&&\text{两个父实例就绪后闭合D2关系}.
\end{aligned}
}
]

其中需要确认 `relation_circuit.step()` 是否已经包含在 `circuit.step()` 内；若已经包含，就不能再次调用。原则始终是：

[
\boxed{\text{每个物理动力学组件每步只更新一次。}}
]

观察器可以读取一次，但不得再次推进神经状态。

# 五、RelationDraft 何时创建？

不能单凭 A、B 两个 occurrence 存在就创建关系。

应由真实关系 collector 越过资格边界时创建：

[
C_{A\prec B}^{\uparrow}
\Rightarrow
\operatorname{RelationDraft}.
]

创建时保存：

[
\left(
\operatorname{AInstanceId},
\operatorname{BInstanceId},
\operatorname{relation\ type},
\operatorname{scale},
t_{\rm detect},
\operatorname{collector\ address}
\right).
]

其中父实例可以暂时只有：

[
(\operatorname{generator\ address},\operatorname{epoch\ id}),
]

之后再通过 registry 解析为完整 occurrence/NaturalUnit 身份。

如果 collector 激活时无法找到两个合法的活跃／近期 epoch，则不得生成一个完整 draft，应登记明确的拒绝原因：

```text
REJECTED_PARENT_EPOCH_UNRESOLVED
```

不能由测试事后补一个看起来合适的父地址。

# 七、必须新增的测试

除了原来的 T-RLI-1～4，建议增加两个地基测试。

### T-OID-1：实例身份唯一

同一 generator 连续产生两个 occurrence：

[
\operatorname{InstanceId}*{17}
\neq
\operatorname{InstanceId}*{18}.
]

对应 NaturalUnit 也不能混同。

### T-OCC-TAP-1：观察器不改变电路

同一输入分别运行：

* 原始 `RPrecCircuitT1`；
* 加入 `CollectorOccurrenceTap` 的版本。

所有原有神经状态和输出应完全一致：

[
\Gamma_{\rm original}
=====================

\Gamma_{\rm observed}.
]

只有新增的 occurrence／transition 记录不同。

这能直接证明方案乙是观察接口，而不是隐藏动力学修改。
