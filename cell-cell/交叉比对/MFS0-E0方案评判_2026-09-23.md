## 二、勘误与修正案（E-1 ~ E-12）

### E-1（最重要，方法论）：§10 的 I_z 在给定实现下是恒等式，不承载物理内容

方案 §10 把

\[ I_z=(w_{11}-w_{10})-(w_{01}-w_{00}) \]

称为"主结构指标"，并要求 `|I_z|>ε_z`。但若按 §3 把写入规则实现为 `ẇ ∝ e·M`（无论用哪一档乘法），则：

- arm 01（无 Past）⇒ `e≡0` ⇒ `ẇ≡0` ⇒ `w_01 = w_00`
- arm 10（无 Later）⇒ `M≡0` ⇒ `ẇ≡0` ⇒ `w_10 = w_00`
- 故 `I_z = w_11 − w_00`，**只要 11 臂写入非零，`I_z≠0` 自动成立**

也就是说，`I_z≠0` 测的是"我是否把写入规则实现成了乘性"，不是"物理是否支持历史依赖"。**这与 Posterior-0 的 D-2 恰好对偶**：那里的问题是"加法性是架构必然（判据不可能 PASS）"，这里的问题是"乘性是实现选择（判据不可能 FAIL）"。两者都是判据与实现耦合，方向相反。

**修正案**：

1. `I_z` 降级登记为 `IMPLEMENTATION_CONSISTENCY_CHECK`——它只证明装配符合 H1 的函数形式，预期值应在开工前**解析预测**并写入预注册块；实测偏离预测才是信息。
2. **M4 的主判据改为 NC3 的选择性比值** `S = Δw(NEAR) / Δw(TIMING_CONTROL)`。NC3 保持 later-event identity、剂量、物理路径全同，只让 `e_W(t_Δ)≈0`——它测的是**同一套写入机制在 e 存在与不存在时的差别**，这是真实的物理内容，且可以 FAIL。
3. 因果重担由 NC4/NC5（path block）与 §13 transplant 承担（方案已有，只需把权重从 §10 调到它们身上）。

> 这条不是否定 §10，而是纠正判据权重：方案自己在 §15 已经准备了正确的负对照，却把"主结构指标"的名分给了一个恒等式。

### E-2：§3 的"物理乘法"未指定档位，且与自身禁令冲突

§3 一面禁止 `if e > threshold and M: w += constant`，一面允许 `ẇ ∝ e·M` 作为"最简研究近似"。这两句在本项目的结构优先纪律下是冲突的——裸 Python `a*b` 与裸 `if` 在"语义硬编码"意义上同级。当前代码里实际存在**三档**：

| 档 | 形态 | 代码位置 | 项目裁定状态 |
|:--|:---|:---|:---|
| 档 1 | 裸 Python `*`（调用方算好 dw 再交给器件） | `bundle.py:461-481` 三因子 `pre_trace*post_act` 与 `E*_da_ema`；`Memristor.apply_dw` 只做 `self.w += dw`（`semiconductor.py:246-265`） | 现状，但正是 MFS0 要超越的 |
| 档 2 | 两个物理量各驱动一个 FET，乘积由两器件输出相乘、**任一阈下由 DEG-019 硬截零** | `tss/relations/theta_comparator.py:170`：`r = self._unblock_fet.conduct(h_i) * self._entry_fet.conduct(b_j_up)`（注释："NMDA 乘法门控：Mg²⁺ 解除因子 × 突触前脉冲因子"） | **用户 2026-09-06 已裁定合法**（该模块头："比较完全由物理结构（MOSFET）承担，不允许 Python if 读出物理状态作判定"） |
| 档 3 | 串联节点负载线自洽求解 | 仅 `research/A8_state_audit/rail_latch.py:13-21`：`I_fb = G·vdd/(1+G·R_s)` | F1 轮已验证（条件化 Scale-B） |

**修正案**：开工前在 `mfs0_common.py` 预注册块中写死档位。**建议档 2**——有先例、有裁定、成本可控。同时必须**诚实登记其局限**：档 2 的乘积在 Python 层仍然是 `a * b`，它的"器件性"来自*两个因子各自由真实器件产生、且截止由硬阈保证*，而不是来自串联电路的自洽求解。若外部方要求"乘法必须由电路拓扑自洽产生"（档 3），则需新增串联节点负载线解，成本显著上升，应在 R-2 中明示裁定。

### E-3：写电流入口已存在于原语，且有跑通原型——方案未提，建议指名复用

`nexus_v1/components/semiconductor.py:277-280`：

```python
def update(self, current: float, pre_trace: float, post_trace: float):
    """STDP update via charge flux history."""
    dw = 0.5 * current * (pre_trace - post_trace)
    self.apply_dw(dw)
```

这是**全库唯一**"写电流驱动 w"的方程（Strukov 型 `ẇ ∝ i(t)`）。主干 `bundle.py` 的四个学习分支全部绕过它直接走 `apply_dw`，所以它在 production 中零调用；但 research 层已有完整原型 `research/A8_candidate/candidate_z.py:228-244`——门控写电流 `i_mem = g_port·v_gate·G/(1+k·G)` 送入 `Memristor.update(current=i_mem, …)`，带 Joglekar 窗（Joglekar & Wolf 2009）做边界抑制，并已登记"memristor 无衰减项，washout 期 w 不回退"。

**修正案**：§3「必须尽可能沿用已有 local plasticity / memristive update / conductance-write-current / modulatory gate 物理原语」这句是对的，但应指名到具体符号：`Memristor.update` + `candidate_z` 的门控写电流拓扑。省一次重造，也避免 Step B/C 各自发明一套。

### E-4（最可能的失败模式，且**可事前定量**）：M5 会撞上 LIM-RPREC-READOUT-001

`G(w) = 1/(r_min + (r_max−r_min)(1−w)) = 1/(10 − 9.9w)`（`semiconductor.py:227-240`）是双曲形式。已登记的定量结论（`cell-cell/docs/degradation_registry.md:403-437`）：

> 总压缩 297× = **环节A 8.3×**（Memristor 低 w 工作点：ΔG/G = Δw·(r_max−r_min)/R = **0.117% ≪ Δw/w = 0.97%**）× 环节B 35.8×（训练期积分稀释）……**即使消除环节B，效应上限 0.117% 仍低于 1% 阈值一个数量级**

且设计轮一已**否证多束并行读出**能解除它：

> ① 效应量层 **N-不变**：N=1 相对效应 0.0035% vs N=4 0.0034%……上限被 Memristor 低 w 工作点钉死在 ΔG/G≈0.117%，**与束数无关**

后果：MFS0 即使 M4 PASS（`w_11≠w_10` 成立），**M5（Future Causal Action）仍可能因读出端压缩而不可测**，直接落入方案自己定义的终态 E（`MFS0_PERSISTENT_STATE_CAUSALITY_NOT_ESTABLISHED`）。这不是运气问题——诊断数据 `Δw=+0.001052 @ w≈0.109` 表明压缩发生在**低 w 工作点**：该处 `R≈9.01`，`dG/dw = 9.9/R² ≈ 0.122`；而 `w→1` 时 `R→r_min=0.1`，`dG/dw = 9.9/0.01 = 990`，**相差约三个数量级**。

**修正案**（三件，全部在 §17 held-out 冻结之前完成）：

1. **初始工作点 w₀ 选在高 w 端**。§17 已把 `initial w range` 列入冻结清单，正好是落点。注意这偏离 `bundle.py:25` 的默认 `initial_weight=0.1`——需在 R-4 中明示裁定（不能事后调）。
2. Step C（persistent-state baseline）必须**先用解析式给出 M5 的可达效应量估算**：给定预期 `Δw`，算出 `ΔG/G` 与下游电流差，与 `ε_Q` 比较。若解析上就低于 floor，应在开工前改工作点或改读出结构，而不是跑完再登记一条新 LIM。
3. `ε_Q` 不得按主实验 effect size 反推（§18 已禁），但**可以**按"解析可达效应量的若干分之一"预注册——请在 §18 的四个优先来源里补这一条推导路径。

> 这条是本评判最有操作价值的一条：Posterior-0 的 LIM-FAR 是预算耗尽的偶然，而这里的读出压缩是**可以提前算出来的必然**。

### E-5：`w` 是边际稳定连续统，不是 latch；且"持久"的含义依实现路径而变

A8 原语多稳态审计实测（`cell-cell/工作报告/A8最小充分状态与原语多稳态审计工作报告_2026-09-11.md`）：

| 拓扑 | 结果 |
|:---|:---|
| F4 Memristor 闭环 | `u=0` 时**全域边际连续统，λ = 1.000** ⇒ 积分器 / 线吸引子（M2 签名），**不是双稳** |
| F1 单节点正反馈（= RailLatch） | 双稳（V*=0 稳 λ=0.998 / V_u=0.6768 不稳 / V*=1.0 钳位支稳），单稳→双稳边界 k*≈2.40 |

所以 §2 要求的 `e,M→0` 后 `w⁺≠w⁻` **会成立**，但原因是 w **没有回复力**，不是它有两个吸引子。这个区别决定 washout 的解释：w 的"保持"不是主动维持，是无耗散积分。

另有一个实现相关的分叉：

- 若经主干 `bundle.learn()` 路径，带 `lambda_metabolic = 1e-6/步`（`bundle.py:151`、`:485` `decay = λ·m.w·dt`）⇒ w 以约 10⁶ 步时间常数指数趋**零**（不是趋基线）
- 若在 research 层直接 `apply_dw`（如 `candidate_z`）⇒ **无任何衰减**

**修正案**：在预注册块中写死 MFS0 的 w 是否带代谢泄漏（建议：不带，理由=本轮问的是"能否沉积"，泄漏属下一轮 consolidation 议题），并在 §11 washout 结果中**同时报 w 保持率**，避免"持久"一词在两种实现下被混用。

### E-6：`RailLatch` 不在主干，且作为正对照需带三项限定

§2 把 RailLatch 列为 `PERSISTENT_STATE_POSITIVE_CONTROL`。事实：

- `nexus_v1/` 与 `tss/` 全库 **零命中**；唯一实现是 `research/A8_state_audit/rail_latch.py:66-118`
- 其持久量是**电容电压 V**，不是 `w`——与主候选 `z=w` 不同量纲、不同机制
- canonical `n_feedback_fets = 1`（`F1_FEEDBACK_POWER_CONTRACT.md:154-155`，外部实测 N=1 已双稳）；双稳需 `k* ≈ 2.40` 以上
- 其所属终态 `F1_A8v2_PHYSICALLY_VALIDATED` 是**条件化**的（Scale-B 自曝条款）

**修正案**：保留它作正对照（这是合理的——正对照本就该用一个已知持久的东西），但在 §2 注明上述四项，并说明"正对照验证的是测量链能不能看见持久差异，不是 z=w 的替代候选"。

### E-7：§6 的"物理换能"目前只有窗口相位斜坡，没有强度通道

`build_phase_drive`（`tss/adapters/relation_replay_adapter.py:39-64`）对 port 的**唯一**访问是 `((p.t_up, p.t_rearm) for p in ports)`，输出 `value = (k − t_up)/(t_rearm − t_up) ∈ [0,1)`，窗外恒 0。occurrence 族端口（V1/V2）**没有 value 字段**。幅值口在 typed 层被机器封死：

```python
def amplitude_port_stub() -> None:
    raise NotImplementedError(
        "U_T amplitude port requires the L1 amplitude→receptor-current upgrade …")
```
（`tss/adapters/typed_ports.py:123-134`，另有 `base_generator.py:312-318` 的 `isinstance` 硬闸）

所以现有链严格是 **「窗口 → 相位斜坡 → I_e → C_e」**，不是「χ 的强度 → I_e」。

**修正案**（二选一，须在 §6 写明）：

- **(a) 不需要强度**（推荐）：则 `e` 是"窗口指示函数的 RC 积分"，`e_peak` 由 `τ_e` 与换能增益 `g_e` 共同决定，**与 χ 的幅值无关**。这必须在 §6 明说，否则 Step A 标定出的 `e_peak` 会被误读为"过去发生的强度"。
- **(b) 需要强度**：须在 research 层新写展开器读 `raw_relation_track_ref`（端口自带引用，**不在** V1 docstring 的禁止清单内——该清单禁的是 membrane charge / RelationInputNeuron state / frozen bundle trace，这是可用的合法缝隙），并显式登记为 RC-1 typed acceptance 的合同扩展。**不得**走 U_T 幅值口——解封必改 production，与 §21 直接冲突。

### E-8：读出面陷阱——`activation` 不是膜电压

`RelationCell` 的 `activation` 经 `MOSFET(v_threshold=0.3, gm=1.0)` 的 `gated_conduct` 产生（`nexus_v1/components/neuron.py:433-438` + `semiconductor.py:160-166`），阈下**硬归零**（DEG-019）。若 §6 的 `C_e` 要"线性积分 χ"，读出必须显式取 `cell._membrane.voltage`（Posterior-0 已有先例：`p0_common.py:207` `vs.append(p.cell._membrane.voltage)   # DIAGNOSTIC_READ（只读）`）。

否则阈下的 χ 会被硬截零，**看起来像"电容根本没充上电"**，而实际上膜已在充电。Posterior-0 的 Step A 正是栽在这个面上（activation 面 τ=6.4 步 vs 膜面 τ=500 步，差 78×），最后靠改读膜面才拿到 M1。**建议把这条直接写进方案 §6 的输出字段清单**：`e(t)` 的 canonical 读出面 = 膜电压，`activation` 只作诊断。

### E-9：§7 的 SEMANTIC_ERASURE_AUDIT——污染点坐标与可用清白源

**(b) 现有调制原语的真实成色**（三者差别很大，方案笼统称"旧 neuromodulator / DA 机制"会误导）：

| 组件 | 真实构成 | 可用性 |
|:---|:---|:---|

### E-10：§19 的时间纪律正确且必要，但要点名两个禁区

§19（只有 `t_phys`、一律秒制、步数只能由 `N=T/dt` 派生、禁新增 `*_steps` canonical 参数、旧 step-based STDP 参数不得直接继承）**完全正确**，与 G0-R0 确立的 `GENERATOR_DT = 0.001 s` 合同一致。需要补两条具体禁区：

**(a) 禁止照抄 `compensation.py` 的 τ 注释。** 该文件几乎所有时间常数注释按 `dt=1.0` 写成（`:89` "20-100 ms"、`:245` "τ=50 ms"、`:331` "τ_pool=25 ms"、`:411` "τ_D2=100 ms"），在 `dt=0.001` 下**全部放大 1000×**（变成 50 s / 25 s / 100 s）。主线 `VariantCircuit.step()` 的默认形参仍是 `dt=1.0`（`variant_adapter.py:2039`），而 research 层一律传 0.001——这是这套注释的由来。正确换算先例：`neuron.py:587-588`（显式 `×0.001`）、`tss/relations/temporal_r_prec.py:104-105`（`C = τ_steps·DT/R_leak`）、`tss/relations/history_kernel.py:62-70`。

**(b) §19 的禁令在逻辑上排除了复用 `bundle.learn()` 的 eligibility 机制。** `bundle.py:126` `eligibility_tau = 300.0` 与 `:142` `da_ema_tau = 5000.0` 都是步制，且 `:134` 有显式警告 "in SIMULATION STEPS, NOT seconds — do NOT substitute seconds"。此外该 eligibility 的衰减是**线性** `E *= (1 − dt/τ)`（`:459-460`），而非 `Capacitor.leak` 的精确指数 `exp(−dt/RC)`，尽管其注释自称 "Capacitor dynamics"——这本身是一处名实不符，建议本轮顺手登记为新 DEG（不修，只登记）。

⇒ 结论：**`C_e` 必须自建**（用 `semiconductor.Capacitor`，τ_e = R_e·C_e 秒制），不能复用 bundle 的 eligibility。这与 E-7 的结论一致，也正是 §6 要求"不允许继续把普通 Python float list 直接称作 physical eligibility"的落实路径。

### E-11：三处衔接与预算口径

**(b) §0「Posterior-0 已结束」与 §22 终态 D 的措辞需修正。** 存档终态是 `A_CONDITIONAL`（六门 PC0-M1~M6 **全 PASS**），且 `READY_FOR_POSTERIOR_1 = "pending user ruling on RULING_EXPOSURE"`——**RULING-P0-1 仍 OPEN**。而 §22 终态 D 称"这是最接近 Posterior-0 失败类型的终态"，把一个六门全 PASS 的轮次归类为失败类型，与存档不符。

**(c) §20 预算表缺 `new_g0_trajectories` 类别——但本轮大概率不需要它。** Posterior-0 有独立 cap=4，`LIM-POSTERIOR-TIMING-FAR` 正因其耗尽而产生。MFS0 §1 要求 later event 用 `χ_j^(0)` 且 `t_Δ > t_W`，落在 `e_W` 窗内。核对库存：

### E-12：`τ_e` 的自由度漏洞——§9 堵了幅值却没堵时间常数

§9 明令禁止 `shift historical W` / `change G1 parameters` / `change relation parameters` / `increase later-event amplitude until PASS`，唯独**没有禁止"调 `τ_e` 直到 later event 落进窗里"**。而 `τ_e = R_e·C_e` 恰恰是本轮唯一完全自由的新参数——它既决定 §9 的合法 timing 区间，又决定 §11 的 washout 时长，还决定 E-1 中 NC3 的"`e_W(t_Δ)≈0`"到底有多远。这是本方案最大的未封堵自由度。

**修正案**：
