## 三、机制清查：代码是否按设计工作？

### 3.1 pre_trace公式
**当前**（`neuron.py:589`）：
```python
self.pre_trace = self.pre_trace * decay_pre + abs(self.activation)
```
**问题**：缺少`(1-decay)`缩放，稳态放大20.5倍【1†L36-L41】。清查这是设计意图还是bug？

### 3.2 DA浓度赋值
**当前**（`variant_adapter.py:2224-2225`）：
```python
mean_da = sum(n.activation for n in self.da_neurons.values()) / len(...)
self.dopamine._concentration = max(0.0, min(1.0, mean_da))
```
**问题**：`dopamine.step()`从不被调用，tau_decay/tau_release形同虚设【3†L16-L19】。清查这是否应该修复？

### 3.3 D2自受体
清查`D2Autoreceptor`实例化时使用的是配置值`d2_da_r_leak=1.0`还是类默认值100.0【1†L52-L53】——两者差了100倍。

### 3.4 `gain_factor()`的双重角色
清查`gain_factor()`在`_propagate_bundles()`（调制突触电流）和`_do_learning()`（调制学习速率）中的使用是否语义一致【1†L50】。


## 四、执行顺序建议

```
第一步：通路清查（1-2天）
  ├── 逐条验证10条DA通路的输入/输出
  ├── 确认CPG是否可以安全移除
  └── 列出所有STDP束及其eligibility配置

第二步：数值溯源（1-2天）  
  ├── 每个时间常数：有实验来源？还是拍脑袋？
  ├── 每个增益/权重：有推导？还是试出来的？
  └── 每个钳位/阈值：有生物依据？还是为了方便？

第三步：机制验证（2-3天）
  ├── pre_trace公式：修正前/后对比
  ├── DA浓度赋值：是否应该用ODE？
  └── D2R参数：实际生效值确认

第四步：整合报告
  └── 输出《DA-STDP系统清查报告》：哪些是设计、哪些是bug、哪些是化石
```

**建议从第二步（数值溯源）开始**——因为时间常数的失配（300 vs 5000）和pre_trace的标度错误（20.5倍）是最明确的硬问题，查清它们能帮你快速定位哪些是设计、哪些是bug。
