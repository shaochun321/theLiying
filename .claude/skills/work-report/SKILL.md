# 工作报告写作（work-report)

## 默认原则（2026-07-28 起，用户反馈）

**默认极简：每轮工作只给 ≤30 行小结（对话内）+ memory 记录，不主动落报告文件。**
仅当用户明确要求"写报告/存档"时才写全文。写全文时无需询问确认，篇幅超出单文件合理范围自行拆 Part 1/2/3。

## 存档位置与命名

- 位置：`cell-cell/工作报告/`（**`cell-cell/报告/` 是 legacy 归档，禁止新增**）
- 命名：`{主题}_{日期}.md`，例：`EXT-2全量复验收口工作报告_2026-09-10.md`
- 实施方案（写代码前的方案文档）另存 `cell-cell/claudecode方案/`，同命名格式

## 六段式工作报告模板（当前实践，2026-08 后的标准）

头部固定元数据块：

```
日期：YYYY-MM-DD
执行依据：cell-cell/claudecode方案/{方案文件}.md（或用户指令/裁定编号）
代码路径：{涉及的主要文件}
数据路径：{日志/输出所在目录}
关联提交：{commit hash}
```

正文六段：

```
## 一、目标（总览）        — 本轮要解决什么，来源（方案/裁定/反馈）
## 二、实际改动            — 文件级清单：改了什么、为什么
## 三、发现的真实问题       — 过程中暴露的新问题（登记 DEG/LIM/HC 编号）
## 四、测试结果            — 回归状态行 + 关键实测数值（先跑 verify-regression skill 的序列）
## 五、冻结状态            — 本轮结论与已冻结结论的关系（一致/修订/待裁定）
## 六、未完成项            — 遗留任务（同步写入 BACKLOG.md 📋待执行）
```

可选附加节：`## 复现入口`（实际执行过的命令原样贴代码块，带 `PYTHONIOENCODING=utf-8` 前缀）、`## 原始数据位置`。

## 七节实验分析报告模板（长程实验专用备选）

适用：>100k 步长程实验的中期/最终分析。

```
# {标题} — {中期/最终}分析报告
报告日期 / 状态 / 实验脚本 / 日志文件 / 关联提交

## 一、实验背景        — 实验目标、补丁列表、参数配置
## 二、关键指标时间序列 — fill/DA/AGC/dist/motor 按检查点列表
## 三、束权重演化       — Col→Motor 及 Therm→Motor 权重变化表
## 四、验收标准评估     — 逐条 CR/J 判据当前状态（PASS/FAIL+数值）
## 五、问题诊断         — 每个 FAIL 或异常：观察→根本原因→建议
## 六、实验进度         — 当前步数 / 预计完成时间（中期报告）
## 七、结论与下一步     — 一段结论 + 下轮参数调整草案（代码块）
```

生成步骤：
1. 读实验日志，提取快照段落和检查点数值（新脚本日志多为 stdout 重定向文件或 `cell-cell/test_runs/`；旧文档所说 `工作报告/*.log` 已不存在）
2. 对照实验设计逐条评估验收标准，给 PASS/FAIL + 实测值
3. 诊断 FAIL 项：观察 → 根本原因 → 下轮修复建议（含参数草案）
4. 写入 `cell-cell/工作报告/{命名}.md`

## 数据来源

- 实验脚本：`nexus_v1/tests/exp_*.py`、`tss/tests/exp_*.py`
- 批量测试输出：`cell-cell/test_runs/`
- 项目状态：`cell-cell/当前状态.md`、`cell-cell/工作追踪/BACKLOG.md`、`cell-cell/工作追踪/暂停快照_2026-09-06.md`
- 历史背景：`cell-cell/00_Dashboard/`（聚合检索入口）

## 报告纪律

- 忠实报告：测试失败就写失败+输出；跳过的步骤写明跳过；不粉饰
- 数值必须来自实测（日志/命令输出），不允许凭记忆填
- 报告完成后同步 BACKLOG.md（完成项填 commit hash，遗留项进📋待执行）
